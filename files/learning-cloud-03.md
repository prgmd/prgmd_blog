## 1. 클라우드 네이티브의 핵심 기둥 (Pillars)
클라우드 네이티브 환경을 구축하기 위해 필수적으로 요구되는 문화와 방법론이다.

### 1) 데브옵스 (DevOps)
개발(Dev)과 운영(Ops)의 합성어로, 소프트웨어 제품과 서비스를 빠른 시간에 개발하고 배포하기 위한 협업 문화와 철학을 의미한다.
* **단계별 도구 (Tool Chain)**:
    - **Plan/Code**: Git, SVN, JIRA 등을 통한 버전 관리 및 협업.
    - **Build/Test**: Maven, Gradle, JUnit 등을 활용한 지속적 통합(CI).
    - **Deploy/Operate**: Docker, Kubernetes, Terraform 등 컨테이너 기반 배포 및 코드형 인프라(IaC).
    - **Monitor**: ELK Stack, Nagios 등을 이용한 실시간 상태 모니터링.

### 2) 애자일 (Agile)
전통적인 폭포수(Waterfall) 모델의 단점을 보완하기 위해 등장한 반복적 개발 주기 중심의 방법론이다.
* **핵심 가치**: 프로세스와 도구보다 개인과의 상호작용을 중시하며, 포괄적인 문서보다는 작동하는 소프트웨어에 집중하고 고객과의 협업 및 변화에 대한 대응을 우선시한다.

### 3) ITIL v4
전 세계 IT 서비스 기업의 표준 운영 방법론으로, 최신 v4 버전부터는 애자일, 린(Lean), 데브옵스 등 현대적 방법론과의 연계성을 강화한 서비스 가치 체계로 변화했다.

## 2. 마이크로서비스 아키텍처 (MSA)
애플리케이션을 작은 서비스 단위의 집합으로 개발하는 접근 방식이다.

* **모놀리식(Monolithic) vs MSA**:
    - **모놀리식**: 일체식 구조로 작은 변경에도 전체를 다시 빌드해야 하며 확장이 어렵다.
    - **MSA**: 각 서비스가 별개의 인스턴스로 구동되어 독립적인 배포와 확장이 가능하며 서비스별로 다른 언어와 데이터베이스(폴리글랏)를 사용할 수 있다.
* **조직의 변화**: '투 피자 팀(Two-Pizza Team)'과 같이 업무 기능 중심의 소규모 다기능 팀이 기획부터 운영까지 전체 생명 주기를 책임진다.
* **데이터 관리**: 서비스별로 저장소를 분리(캡슐화)하며, 메시지 큐를 활용한 **결과적 일관성** 모델과 장애 발생 시 원상 복구하는 **보상 트랜잭션** 기법을 사용한다.
* **위기 대응**: 시스템은 언제든 실패할 수 있다는 전제하에 장애 전파를 차단하는 **서킷 브레이커(Circuit Breaker)** 패턴 등을 적용하여 내결함성을 확보한다.

## 3. 클라우드 인프라 서비스 기술

### 1) 가상 머신(VM)과 컨테이너
* **VM**: 하이퍼바이저를 통해 운영체제 전체를 가상화하므로 오버헤드가 발생한다.
* **컨테이너**: 호스트 운영체제를 공유하며 애플리케이션 실행에 필요한 라이브러리만 패키징하여 가볍고 이식성이 뛰어나다. 대표적인 도구로 **Docker**가 있다.

### 2) 컨테이너 오케스트레이션 (Kubernetes)
수많은 컨테이너의 자동 배치, 복제, 장애 복구, 수평 확장을 관리하는 기술이다.
* **주요 기능**: 자동화된 자원 배정, 셀프 치유(장애 시 자동 교체), 사용량에 따른 자동 수평 확장 기능을 제공한다.

### 3) 클라우드 서비스 유형별 분류
* **IaaS (Infrastructure)**: AWS EC2, GCP Compute Engine 등 가상 서버 자원 제공.
* **CaaS (Container)**: AWS EKS, Azure AKS 등 쿠버네티스 기반 서비스 제공.
* **PaaS (Platform)**: AWS Elastic Beanstalk, Google App Engine 등 앱 실행 환경 제공.

## 4. 개발 환경의 자동화 (CI/CD)
* **CI (지속적 통합)**: 개발자가 코드를 공유 저장소에 업로드하면 자동으로 빌드와 테스트가 수행되어 품질을 높인다.
* **CD (지속적 배포)**: 빌드된 코드를 개발, 스테이징, 운영 환경에 자동으로 배포하여 사용자에게 신속하게 전달한다.
* **IaC (Infrastructure as Code)**: 인프라 설정을 코드로 관리하여 하드웨어 리소스를 동일하게 통제하고 쉽게 복제할 수 있게 한다.
