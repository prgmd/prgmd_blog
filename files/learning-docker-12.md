## 1. 도커 스웜 클러스터 구축
도커 스웜은 여러 대의 호스트를 하나의 가상 서버로 관리하는 클러스터링 솔루션이다. 매니저 노드와 워커 노드로 역할을 나누어 구성한다.

### 1) 매니저 노드 초기화
* **초기화 명령**: `docker swarm init --advertise-addr [IP주소]` 명령을 통해 스웜 모드를 활성화한다.
* **통신 포트**: 스웜 클러스터 유지를 위해 2377(관리), 7946(노드 통신), 4789(오버레이 네트워크) 포트가 개방되어 있어야 한다.
* **상태 확인**: `docker info | grep Swarm` 명령으로 활성화 여부를 확인하며, `docker node ls`를 통해 참여 중인 노드 목록을 조회할 수 있다.

### 2) 워커 노드 추가
* **토큰 발행**: 매니저 노드에서 `docker swarm join-token worker`를 실행하여 참여에 필요한 토큰을 확인한다.
* **노드 조인**: 워커 노드로 사용할 서버에서 확인한 조인 명령어를 입력하면 클러스터에 합류한다.

## 2. 서비스 배포 및 네트워크 구성
스웜 환경에서는 단일 컨테이너가 아닌 '서비스' 단위로 애플리케이션을 관리한다.

* **오버레이 네트워크(Overlay Network)**: 서로 다른 호스트에 존재하는 컨테이너들이 내부적으로 통신할 수 있도록 가상 네트워크를 생성한다. (`docker network create --driver overlay [이름]`)
* **서비스 생성**: `docker service create` 명령을 사용하여 복제본(replicas) 개수, 네트워크, 포트 등을 지정해 실행한다.

## 3. 도커 스택 (Docker Stack)
여러 개의 연관된 서비스를 하나의 그룹으로 묶어 배포할 때 사용하며, 도커 컴포즈와 유사한 YAML 형식을 활용한다.

### 1) 스택 설정 (YAML) 주요 속성
* **deploy**: 스웜 모드 전용 설정으로, 서비스의 배치 제약이나 복제본 수를 정의한다.
    * `replicas`: 실행할 컨테이너의 개수를 설정한다.
    * `placement`: `constraints: [node.role != manager]`와 같이 특정 역할을 가진 노드에만 배포되도록 제한할 수 있다.
    * `restart_policy`: 장애 발생 시 재시작 조건, 시도 횟수, 지연 시간 등을 상세히 설정한다.

### 2) 배포 및 관리
* **배포**: `docker stack deploy -c [파일명] [스택이름]` 명령을 사용하여 정의된 모든 서비스를 일괄 실행한다.
* **확인**: `docker stack ls`로 전체 스택을 확인하고, `docker stack services [스택이름]`으로 개별 서비스의 구동 상태를 점검한다.
