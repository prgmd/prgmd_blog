## 1. 테스트 주도 개발 (TDD)
TDD는 프로덕션 코드를 작성하기 전에 테스트 코드를 먼저 작성하는 소프트웨어 개발 방법론이다. 단순한 테스트 기술을 넘어 분석과 설계 기술의 성격을 띤다.

### 1) TDD 사이클 (RED - GREEN - REFACTOR)
* **RED (실패하는 테스트 작성)**: 구현하려는 기능의 요구사항을 반영하여, 아직 동작하는 코드가 없는 상태에서 실패하는 테스트 코드를 먼저 작성한다.
* **GREEN (테스트 통과)**: 실패한 테스트를 통과시키기 위해 필요한 최소한의 프로덕션 코드를 작성한다.
* **REFACTOR (리팩토링)**: 테스트 통과를 유지하면서 코드의 가독성을 높이고 중복을 제거하는 등 구조를 개선한다.

### 2) TDD의 의의
* 코드 작성 전에 요구사항을 명확히 정의할 수 있다.
* 설계 단계에서 발생할 수 있는 오류를 사전에 방지하는 설계 방법론으로 활용된다.

## 2. Jenkins를 이용한 테스트 자동화
CI/CD 도구인 젠킨스를 사용하여 소스 코드 관리부터 테스트 수행까지의 과정을 자동화할 수 있다.

### 1) 젠킨스 설치 및 초기 설정
* **도커 설치**: `jenkins/jenkins` 이미지를 사용하여 컨테이너를 실행한다.
* **초기 비밀번호 확인**: 컨테이너 로그 또는 `/var/jenkins_home/secrets/initialAdminPassword` 경로에서 확인 후 로그인 및 기본 플러그인을 설치한다.

### 2) 테스트 자동화 파이프라인 (Declarative Pipeline)
Java/Gradle 프로젝트를 기준으로 깃 허브에서 코드를 가져와 컴파일 및 테스트를 수행하는 파이프라인 구조는 다음과 같다.

* **git**: 대상 리포지토리의 브랜치와 URL을 지정하여 소스를 체크아웃한다.
* **Permission**: `./gradlew` 파일에 실행 권한을 부여한다 (`chmod +x`).
* **compile**: `sh "./gradlew compileJava"` 명령을 통해 자바 코드를 빌드한다.
* **test**: `sh "./gradlew test"` 명령을 수행하여 작성된 테스트 코드를 실행한다.

### 3) 코드 커버리지 관리
* **JaCoCo (Java Code Coverage)**: 테스트 코드가 프로덕션 코드를 얼마나 꼼꼼하게 검증하고 있는지 측정하기 위해 JaCoCo 플러그인을 파이프라인에 통합하여 수행할 수 있다.
