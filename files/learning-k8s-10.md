## 1. 영구 볼륨 클레임 (PersistentVolumeClaim, PVC)
영구 볼륨(PV)을 사용하기 위해 필요한 자원을 요청하는 리소스다.

### 1) 동작 원리
* 사용자가 PVC에 용량, 레이블, 접근 모드 등의 조건을 명시하여 요청하면, 쿠버네티스 스케줄러가 클러스터 내에 생성된 PV 중 조건에 부합하는 적절한 볼륨을 찾아 연결(Binding)한다.
* 요청하는 용량은 실제 PV의 용량보다 작거나 같아야 할당이 가능하다. 단, NFS 플러그인처럼 용량 제한 구조를 지원하지 않는 경우도 존재한다.

### 2) 주요 설정 항목
* **Selector**: 특정 레이블(matchLabels)이나 조건(matchExpressions)을 가진 PV를 선택한다.
* **Resources**: 필요한 스토리지 용량을 정의한다. (예: storage: 3Gi)
* **Access Modes**: PV에서 정의한 접근 모드와 일치해야 한다. (예: ReadWriteOnce)

## 2. 리소스 관리: Requests와 Limits
파드가 노드에서 실행될 때 사용할 CPU와 메모리 자원을 정의한다.

### 1) 자원 할당의 특징
* **Requests**: 파드가 실행되기 위해 보장받아야 하는 최소 자원이다. 스케줄러는 노드에 이 요청량만큼의 여유 공간이 있는지 확인하고 파드를 배치한다.
* **Limits**: 파드가 사용할 수 있는 최대 자원 제한선이다.
* **주의사항**: Requests와 Limits의 차이가 너무 크면 실제 리소스 사용량은 높지만 스케줄링상으로는 여유가 있는 것으로 오판하여 클러스터 스케일 아웃이 발생하지 않는 문제가 생길 수 있다.

## 3. LimitRange를 사용한 리소스 제한
네임스페이스 내에서 생성되는 파드나 컨테이너의 리소스 사용량을 일괄적으로 제한하는 정책이다.

### 1) 설정 가능한 항목
* **default**: 별도의 설정이 없을 때 적용되는 기본 Limits 값
* **defaultRequest**: 별도의 설정이 없을 때 적용되는 기본 Requests 값
* **max / min**: 설정 가능한 리소스의 최댓값과 최솟값
* **maxLimitRequestRatio**: Limits와 Requests 사이의 허용 비율

### 2) 적용 범위 및 효과
* 네임스페이스마다 별도로 설정해야 하며, 설정 이후 생성되는 신규 파드에만 적용된다. (기존 파드에는 영향 없음)
* 리소스 제한이 전혀 없는 경우 특정 파드가 노드의 모든 자원을 소비하여 다른 서비스에 장애를 줄 수 있으므로, 메모리 부족(OOM)이나 CPU 경합을 방지하기 위해 사용된다.
* 컨테이너뿐만 아니라 파드 전체, 영구 볼륨 클레임에 대해서도 용량 제한(max/min)을 설정할 수 있다.
