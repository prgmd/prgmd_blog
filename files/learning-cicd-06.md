## 1. GitOps의 정의와 핵심 원칙
GitOps는 운영 업무에 Pull Request를 활용하고, 인프라 설정을 Git과 같은 버전 관리 시스템으로 통제하는 프로세스이다.

### 1) 주요 운영 원칙
* **선언적 구성**: 시스템이 도달해야 할 최종 상태(Desired State)를 선언하면, 구체적인 명령 없이 에이전트가 이를 구현한다.
* **불변적 저장소**: 모든 설정은 버전 제어가 가능한 저장소에서 관리하며 변경 이력을 투명하게 유지한다.
* **자동화된 배포**: 저장소의 변경 사항이 감지되면 수동 개입 없이 소프트웨어 에이전트가 실제 환경에 즉시 동기화한다.
* **지속적 루프와 에이전트**: 선언된 상태와 실제 상태를 계속 비교하여 일치하도록 유지하는 폐쇄 루프 구조를 지향한다.

### 2) 쿠버네티스와의 정합성
* 쿠버네티스는 REST API 엔드포인트와 etcd 상태 저장소를 가진 구조로, 선언형 API 모델에 최적화되어 있어 GitOps 구현에 적합하다.

## 2. Argo CD의 특징 및 구성 요소
Argo CD는 쿠버네티스 환경에서 선언적 지속적 배포(CD)를 실현하는 도구이다.

### 1) 주요 구성 요소 및 고가용성(HA)
* **Application Controller**: 애플리케이션의 상태를 감시하며, 대규모 환경에서는 레플리카 수를 조정하여 처리 성능을 높일 수 있다.
* **Kustomization 활용**: `kustomization.yaml`과 패치 파일을 통해 서버, 레포 서버, 컨트롤러 등의 설정을 코드로 관리한다.

### 2) Redis 캐시의 역할
* **성능 최적화**: Git 레포지토리에서 생성된 매니페스트를 캐싱하여 동기화 성능을 높인다. 캐시가 없으면 매 요청마다 매니페스트를 재생성해야 하므로 효율이 떨어진다.
* **데이터 보존**: 캐시는 새로운 커밋이 발생할 때만 갱신된다. 고가용성을 위해 3개의 레플리카를 갖춘 StatefulSet 구성을 권장한다.

## 3. 관측 가능성 및 확장성
* **모니터링**: 프로메테우스를 활성화하여 배포 도구인 Argo CD 자체의 운영 지표를 수집하고 가용성을 관리한다.
* **표준화**: 컨테이너 오케스트레이션의 표준이 쿠버네티스인 것처럼, 메트릭 수집 및 관리는 프로메테우스 기반의 생태계를 따르는 것이 일반적이다.
