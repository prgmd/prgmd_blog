\# 1. AI Workflow

\## 1.1 개요 및 정의

\> 대형 언어 모델(LLM)이 작업 흐름의 핵심 구성 요소로 포함되어 데이터를 처리하는 일련의 과정.



더 정확하게 말하면 머신러닝 모델이 포함된 워크플로우. (꼭 LLM이 들어가지 않아도 되긴 하다)



근데 왜 LLM을 핵심이라 언급하냐면, 명확한 규칙 기반인 전통적인 워크플로우에서 발전해 자연어 명령과 맥락 이해를 통해 사람이 하던 판단과 분기를 AI가 대신하는 것이 사실상 현재 표준이기 때문.

\- 기존: 영수증 업로드 → 날짜/금액 텍스트 추출 → 엑셀 저장 (글자만 옮김)

\- LLM 결합: 영수증 업로드 → AI가 항목 분석 (술값인지 식대인지 판단) → 회사 규정에 맞는지 검토 → 부적절할 경우 반려 메일 초안 작성 및 알림



\### 1) 주요 특징

\* 반복 데이터 처리 업무가 많은 사무직 종사자들에게 높은 인기를 얻고 있음.

\* 기존의 단순 매크로와 달리, \*\*AI가 맥락을 이해하고 결과물을 초안 형태로 생성해준다는 점이 차별화된 특징\**.

\* 단순한 데이터 정리를 넘어, 실시간 콘텐츠 생성 및 멀티 채널 배포로 확장도 가능하다.

\* 마우스를 이용해 각 노드(Node)를 배치하고 연결하는 \*\*직관적인 그래픽 사용자 인터페이스(GUI)를 제공\**한다.

\* 전문적인 코딩 능력 대신 약간의 개발 지식과 논리적 흐름에 대한 이해만 있다면 복잡한 자동화 시스템 구축이 가능하다.



\#### 노코드(No-code) 지향

\> 복잡한 프로그래밍 언어 학습 (X) → 마우스 클릭과 연결(Drag & Drop)만으로 자동화 프로그램을 완성할 수 있는 환경 제공.



\#### 지능형 자동 배포 사례

!\[](https://velog.velcdn.com/images/paramad/post/6334ec30-e565-45bd-b5ff-85c83ba4f0b1/image.png)



1.  \*\*신규 기사 탐지:\*\* 특정 주제의 뉴스 기사가 발행되는 즉시 트리거가 작동한다.

2.  \*\*LLM 요약 및 추출:\*\* OpenAI(LLM)가 기사 내용을 요약하고 핵심 키워드(Text)를 추출한다.

\## 1.2 실습

\### 1) OpenAI API 적용 (gpt-5-nano 모델)

Python의 \`openai\` 라이브러리를 활용하여 최신 LLM 모델에 질의하고 응답을 받는 기본적인 구조를 확인한다.



\`\``python

from dotenv import load_dotenv

load_dotenv()



import os

from openai import OpenAI



\# OpenAI 클라이언트 초기화

client = OpenAI(api_key=os.getenv("OPENAI_API_KEY"))



model = "gpt-5-nano"

prompt = "KFC 버거 추천좀 해줘, 두줄 요약"



\# 모델 호출 및 결과 출력

response = client.responses.create(model=model, input=prompt)

print(response.output_text)

\`\``

\* \*\*실행 결과:\**

\> 매운맛 원한다면 핫크리스피 버거를 추천—바삭한 닭고기 패티와 매콤 소스의 조합이 포인트.

\> 고소함을 원하면 더블 크리스피 버거나 치즈버거를 골라 치즈의 풍미와 두툼한 패티를 즐겨봐.



\### 2) Upstage API 적용 (solar-pro3 모델)

OpenAI SDK와 호환되는 Upstage API를 사용하여 국산 LLM인 Solar 모델을 호출하는 방식. \`base_url\` 설정을 통해 타사 API도 동일한 문법으로 사용 가능하다. (OpenAI가 LLM 시장의 표준이 되면서, 많은 후발 주자(Upstage, Anthropic, Groq 등)들이 자사 API 구조를 OpenAI의 입출력 규격과 똑같이 맞추어 설계했기 때문)



\`\``python

import os

from openai import OpenAI



\# Upstage API 설정 (base_url 변경이 핵심)

client = OpenAI(

\    api_key=os.getenv("UPSTAGE_API_KEY"), 

\    base_url="https://api.upstage.ai/v1"

)



model = "solar-pro3"

prompt = "KFC 버거 추천좀 해줘, 두줄 요약"



\# Chat Completion 표준 방식으로 호출

response = client.chat.completions.create(

\    model=model, 

\    messages=\[{"role": "user", "content": prompt}]

)

print(response.choices\[0].message.content)

\`\``

\* \*\*실행 결과:\**

\> 1. \*\*추천 버거\*\*: 바삭한 닭가슴살이 속까지 촉촉한 \*\*오리지널 치킨 버거\*\*가 기본이지만, 매운 맛을 원한다면 \*\*하와이안 버팔로 버거\*\*, 고기와 치즈를 더하고 싶다면 \*\*더블 다운 버거\*\*를 추천합니다.  

\> 2. \*\*주문 팁\*\*: 가장 인기 있는 버거와 사이드 메뉴를 함께 주문하면 가성비가 높고, 배달 앱을 이용하면 할인 쿠폰을 쉽게 받을 수 있어요.



\#### ※ 주피터 API 키 연동 및 환경 변수 로드 오류 발생할 경우

\* 주피터는 실행 시점의 경로를 기준으로 파일을 탐색한다. \`.env\` 파일이 현재 실행 중인 \`.ipynb\` 파일과 다른 폴더에 있을 경우 \`load_dotenv()\`가 파일을 찾지 못해 \`None\`을 반환하거나 예전의 잘못된 키를 참조하게 된다.

\* 또한 \*\*주피터 커널은 한 번 로드된 환경 변수를 메모리에 계속 유지하려는 성질이 있다.\*\* 따라서 \`.env\` 파일을 수정하거나 위치를 옮긴 후에는 반드시 \*\*\`load_dotenv(override=True)\`\**를 사용하여 기존 메모리 값을 강제로 덮어씌워야 한다.

\## 2.1 개요 및 정의

\> LLM을 이용한 복잡한 워크플로우를 상태 기반의 그래프 구조로 설계하는 프레임워크. 



\### 그 전에... What is LangChain?

!\[](https://velog.velcdn.com/images/paramad/post/70162f1a-647a-40f3-a9ec-35d43c650239/image.png)



LangChain Inc.라는 오픈소스 기반 기업에서 만든 LLM, DB, 도구들을 연결하는 \*\*프레임워크(라이브러리)\*\*. LLM과 다른 도구를 단순 쇠사슬처럼 엮기 위해 만들어졌다. 하지만 실제 비즈니스는 반복(A 해보고 안 되면 다시 B 해보자 등) 및 상태 유지가 중요한데, 이를 구현한 상위 개념 오케스트레이션 도구가 LangGraph. 이를 추적하고 분석하는 도구가 LangSmith (사실상 상업용 관리 플랫폼인 셈)



\### 1) 핵심 요소

\* \*\*Agent (에이전트):\** AI Workflow 자체.

\* \*\*Node (노드):\** Workflow(Agent)를 구성하고 있는 개별적인 작업 단계를 의미한다. 각 노드는 특정 함수나 로직을 실행한다.

\* \*\*Edge (엣지):\** 노드와 노드를 잇는 연결선. 작업의 실행 흐름과 방향을 결정한다.

\* \*\*State (상태):\*\* \*\*노드들이 공유하며 값을 저장하고 전달할 수 있는 공용 공간. 그래프가 실행되는 동안 데이터가 유지되는 저장소 역할을 한다.\**



\### 2) 핵심 명령어

\* \*\*\`StateGraph(state_schema)\`\**: 도화지를 펴는 단계. 노드들이 공유할 데이터 구조(\`State\`)를 정의하며 그래프 객체를 생성.

\* \*\*\`.add_node("이름", 함수)\`\**: 작업자(노드) 배치. 특정 로직을 수행할 함수를 그래프에 등록.

\* \*\*\`.add_edge("출발", "도착")\`\**: 이동 경로(화살표) 그리기. 노드와 노드 사이의 실행 순서를 연결. (\`START\`와 \`END\` 포함)

\* \*\*\`.compile()\`\*\*: 설계도를 \*\*실행 가능한 프로그램\**으로 변환. 논리적 오류를 검증하고 \`invoke\` 기능을 가진 최종 객체를 반환합니다.

\* \*\*\`.invoke(input)\`\**: 전원 켜기(실행). 초기 데이터(입력값)를 넣고 워크플로우를 시작합니다.

\* \*\*\`Annotated\[list, operator.add]\`\**: 데이터 누적 설정. 새 데이터가 들어올 때 덮어쓰지 않고 리스트 끝에 합치도록 지시합니다.

\* \*\*\`pretty_print()\`\**: 로그 가독화. 복잡한 메시지 객체를 사람이 읽기 편한 텍스트 형태로 콘솔에 출력합니다.

\* \*\*\`add_conditional_edges\`\**: 조건 분기. 입력 변수가 어떤 타입인지 구분해 다르게 할당.



\## 2.2 기본 실습

\### 1) MessagesState 기반의 기본 그래프 구현

\`MessagesState\`를 활용하여 사용자 메시지를 입력받고 "hello world"를 응답하는 가장 기초적인 에이전트를 구축한다.



\`\``python

from langgraph.graph import StateGraph, MessagesState, START, END



\# 1. 노드 함수 정의: MessagesState 형식을 따름

def kfc(state: MessagesState):

\    return {"messages": \[{"role": "ai", "content": "hello world"}]}



\# 2. 그래프 생성 및 노드/엣지 구성

graph = StateGraph(MessagesState)

graph.add_node("KFC", kfc)      # 'KFC'라는 이름의 노드 등록

graph.add_edge(START, "KFC")    # 시작 지점(START)을 KFC 노드에 연결

graph.add_edge("KFC", END)      # KFC 노드 종료 후 끝(END)으로 연결



\# 3. 컴파일 및 실행

agent = graph.compile()

result = agent.invoke({"messages": \[{"role": "user", "content": "hi!"}]})



\# 4. 콘솔 로그 출력 (pretty_print 활용)

for m in result\["messages"]:

\    m.pretty_print()

\`\``



\* \*\*실행 결과:\**

\> \*\*Human Message:\*\* hi!  

\> \*\*Ai Message:\*\* hello world



\### 2) 커스텀 State(dict)를 이용한 다중 노드 연결

기본 메시지 형식이 아닌 일반 딕셔너리(\`dict\`) 형태의 State를 사용하여 여러 노드를 순차적으로 실행하고 데이터를 누적하는 방식.



\`\``python

from langgraph.graph import StateGraph, START, END



\# 1. 노드 함수 정의 (비즈니스 로직 처리)

def kfc(state):

\    print("KFC 실행")

\    return {"result": "kfc 실행"}



def bbq(state):

\    print("BBQ 실행")

\# 이전 노드(KFC)가 State에 저장한 값을 가져와서 가공함

\    return {"result": state\["result"] + " -> bbq 실행"}



\# 2. 그래프 생성 (상태 타입을 dict로 설정)

graph = StateGraph(dict)



\# 3. 노드 추가 및 워크플로우 설계

graph.add_node("KFC", kfc)

graph.add_node("BBQ", bbq)



\# 4. 엣지 연결 (START -> KFC -> BBQ -> END)

graph.add_edge(START, "KFC")

graph.add_edge("KFC", "BBQ")

graph.add_edge("BBQ", END)



\# 5. 빌드 및 실행

agent = graph.compile()

result = agent.invoke({}) # 초기 빈 상태로 실행



print("\n최종 결과:", result)

\`\``

\* \*\*실행 결과:\**

\> KFC 실행  

\> BBQ 실행  

\> \*\*최종 결과:\*\* {'최종 결과': 'kfc 실행 -> bbq 실행'}







\## 2.3 State Management (상태 관리)



랭그래프의 핵심은 노드 간의 상태(State) 공유. 워크플로우가 진행됨에 따라 출력값을 State에 누적해 저장하는 패턴이 가장 빈번하게 사용된다.



기본적으로 파이썬의 딕셔너리는 같은 키(Key)에 새 값을 넣으면 기존 값을 덮어씀(Overwrite). 하지만 대화 기록은 이전 내용을 유지하며 뒤에 붙여야 한다. 



\- \`Annotated + operator.add\`: 변수는 새 값이 들어오면 덮어쓰지 말고 기존 값에 더해달라고 랭그래프 엔진에 명령을 내림. 메시지뿐만 아니라 숫자(점수 누적), 리스트(검색 결과 축적) 등 어떠한 데이터 타입이라도 사용자 정의 합치기 규칙을 적용하고 싶을 때 사용한다.

\- \`MessagesState\`: 하지만 챗봇 만들 때 매번 타이핑하는 것은 매우 번거로움.그래서 랭그래프 개발진이 이 구조를 기본 클래스로 미리 정의해둔 것이 바로 'MessagesState'. 메시지 리스트만 관리하면 된다. 다만 오로지 메시지 키만 가질 수 있어 유연성은 다소 낮다.



\### 1) 문자열(String) 기반의 단순 누적

가장 직관적인 형태로, 이전 노드에서 전달받은 \`state\` 값에 새로운 문자열을 더해 다음 노드로 전달하는 방식이다.



\`\``python

from typing_extensions import TypedDict

from langgraph.graph import StateGraph, START, END



\# === State 정의: 공유할 데이터 구조 선언 ===

class State(TypedDict):

\    text: str



\# === Node 정의: 이전 상태에 텍스트를 누적하여 반환 ===

def step1(state: State):

\    return {"text": state\["text"] + "안녕? "}



def step2(state: State):

\    return {"text": state\["text"] + "나는 "}



def step3(state: State):

\    return {"text": state\["text"] + "KFC를 사랑해"}



\# === Graph 구성: 순차적 엣지 연결 (Step1 -> Step2 -> Step3) ===

graph = StateGraph(State)

graph.add_node("step1", step1)

graph.add_node("step2", step2)

graph.add_node("step3", step3)



graph.add_edge(START, "step1")

graph.add_edge("step1", "step2")

graph.add_edge("step2", "step3")

graph.add_edge("step3", END)



agent = graph.compile()

result = agent.invoke({"text": "ㅎㅎ "})

print(result\["text"]) # 출력: ㅎㅎ 안녕? 나는 KFC를 사랑해

\`\``



\### 2) Annotated와 operator.add를 이용한 메시지 누적

실제 챗봇 구현 시에는 단순 문자열보다 LLM이 이해하기 쉬운 \*\*Message 객체\*\*를 리스트 형태로 누적하는 방식이 선호된다.



\* \*\*Annotated\[list[AnyMessage], operator.add]:\*\* 랭그래프 라이브러리가 새로운 메시지를 받았을 때, 기존 리스트를 덮어쓰지 않고 \*\*리스트 끝에 추가(Append)\**하도록 지시하는 핵심 문법이다.

\* \*\*활용 목적:\** 전체 대화 이력을 보존하여 LLM이 맥락을 파악하게 하거나, 랭스미스(LangSmith)에서 디버깅할 때 전체 흐름을 확인하기 위함이다.



\`\``python

from typing_extensions import TypedDict, Annotated

import operator

from langchain.messages import AnyMessage, HumanMessage, AIMessage

from langgraph.graph import StateGraph, START, END



class State(TypedDict):

\# messages 리스트에 새로운 데이터가 들어오면 자동으로 합쳐짐(add)

\    messages: Annotated\[list[AnyMessage], operator.add]



def step1(state: State):

\    return {"messages": \[AIMessage(content="안녕? ")]}



\# ... (중략: step2, step3 동일 구조)



graph = StateGraph(State)

\# ... (중략: 노드 및 엣지 구성 동일)



agent = graph.compile()

result = agent.invoke({"messages": \[HumanMessage(content="시작")]})



for m in result\["messages"]:

\    m.pretty_print()

\`\``



\### 3) 최적화 도구: MessagesState

저장할 상태 데이터가 오직 메시지 리스트뿐이라면, 별도의 \`TypedDict\` 정의 없이 랭그래프에서 제공하는 \*\*\`MessagesState\`\*\*를 사용하여 코드를 더욱 간결하게 작성할 수 있다.



\* \*\*특징:\** 내부적으로 \`messages: Annotated\[list[AnyMessage], operator.add]\` 구조를 이미 포함하고 있다.

\* \*\*주의사항:\** 메시지 이외에 \`context\`, \`user_id\` 등 추가적인 상태 데이터가 필요한 경우에는 \`MessagesState\`를 사용할 수 없으며, 직접 \`TypedDict\`를 정의해야 한다.



\`\``python

from langchain.messages import HumanMessage, AIMessage

from langgraph.graph import StateGraph, START, END, MessagesState



def step1(state: MessagesState):

\    return {"messages": \[AIMessage(content="안녕? ")]}



\# ... (중략)



\# 그래프 생성 시 전용 상태 클래스인 MessagesState를 인자로 전달

graph = StateGraph(MessagesState)

\# ... (이하 동일)

\`\``

\# 3. LangSmith



\## 3.1 개요 및 정의

\> LLM 애플리케이션의 실행 결과를 모니터링하고 분석하기 위한 웹 기반 플랫폼. LangGraph나 OpenAI API 단독 호출 시 발생하는 중간 진행 상황을 추적(Tracing)하고 시각화한다.



\### 1) 특징

\* LangGraph 개발 시 LangSmith는 선택이 아닌 필수 도구.

  \* 사실상 웹 개발 시 브라우저에서 사용하는 \*\*'개발자 도구(F12)'\**와 같은 위상을 가짐.

\* 복잡하게 얽힌 LangGraph의 노드 실행 순서와 데이터를 예쁜 그래프 그림으로 한눈에 파악할 수 있다.

\* 에이전트가 의도대로 동작하지 않을 때, 어느 단계에서 에러가 발생했는지 혹은 프롬프트가 어떻게 전달되었는지 디버깅이 가능하다.



\### 2) LangSmith Studio

\#### 개요 및 정의

\> 랭그래프가 내부적으로 동작하는 모습을 실시간으로 시각화하여 보여주는 강력한 기능. 동작 테스트 및 에러 발생 지점 추적에 매우 효과적이며, 심지어 무료로 제공된다.



\#### 제약 사항

\* \*\*로컬 실행 필수:\*\* 별도의 서버(\`localhost:포트\` 사용)를 구동해야 하므로 실습용 코랩(Colab)이나 주피터랩 환경에서는 실행되지 않는다. 반드시 \*\*로컬 환경(VS Code, PyCharm 등)\*\*에서 실행해야 한다. (\*\*사용자 브라우저가 컨테이너 내부 포트에 접근하려면 별도의 포트 포워딩 설정이 필요함\**)

\* \*\*필수 구성 파일:\** 로컬 연동을 위해 아래 3가지 파일이 준비되어야 한다.

\    1. \`.env\`: 환경 변수 설정 파일

\    2. \`app.py\`: 메인 소스 코드

\    3. \`langgraph.json\`: 랭그래프 설정 파일



\## 3.2 실습

\### OpenAI API 호출 트레이싱 (Wrapper 활용)

LangGraph 프레임워크를 전체적으로 사용하지 않더라도, \`langsmith\`에서 제공하는 래퍼(Wrapper)를 통해 일반적인 OpenAI 호출을 기록할 수 있다.

\* \*\*트레이싱 스위치:\** \`wrap_openai\`를 사용하면 별도의 로깅 코드를 작성하지 않아도 호출 모델, 입력값, 출력값, 실행 시간 등이 LangSmith 대시보드에 실시간으로 기록된다.



\`\``python

from openai import OpenAI

from langsmith.wrappers import wrap_openai  # 트레이싱을 위한 래퍼 임포트



\# 1. OpenAI 클라이언트 생성 및 래핑

\# 기존 OpenAI() 객체를 wrap_openai로 감싸는 코드 한 줄만 추가하면 연동된다.

client = wrap_openai(OpenAI())



model = "gpt-5-nano"

prompt = "KFC 버거 추천좀 해줘, 한줄 요약"



\# 2. API 호출 (자동으로 LangSmith 서버에 기록됨)

response = client.responses.create(model=model, input=prompt)

print(response.output_text)

\`\``

\## 3.3 에이전트 핵심 구성 요소



\| 구성 요소 | 역할 (비유) | 상세 설명 |

\| :--- | :--- | :--- |

\| \*\*LLM (Model)\*\* | \*\*두뇌\*\* | 상황을 판단하고, 어떤 도구를 쓸지 결정하며, 최종 답변을 생성하는 핵심 엔진 (예: Solar-pro, GPT-4) |

\| \*\*Tools (도구)\*\* | \*\*손과 발\*\* | LLM이 직접 할 수 없는 외부 작업(인터넷 검색, 계산기, DB 조회)을 수행하는 함수들의 집합 |

\| \*\*Toolkit (도구 모음)\*\* | \*\*연장 통\*\* | 특정 목적(예: GitHub 관리, Gmail 연동)을 위해 관련된 여러 개의 Tool을 하나로 묶어놓은 세트 |

\| \*\*Memory (기억)\*\* | \*\*기억력\*\* | 과거의 대화 내용을 저장하여 맥락을 유지함 (예: \`ConversationBufferMemory\`) |

\| \*\*Planning (계획/미들웨어)\*\* | \*\*전략/논리\*\* | 에이전트가 사용자의 질문을 받고 답변을 내놓는 \*\*그 사이(Middle)\*\*의 실행 흐름에 개입하여 추가적인 로직을 수행하는 장치. 복잡한 문제를 단계별로 쪼개고 실행 순서를 정함 (예: \`TodoListMiddleware\`) |



\### Tool(도구)

랭스미스 스튜디오는 향후 학습할 \*\*'Tool'\*\* 기능을 사용할 때 그 가치가 극대화된다.



\* \*\*Tool의 개념:\** LLM에게 특정 함수(기능)를 손에 쥐여주는 것과 같다. (예: 계산기, 검색 등)

\* \*\*시각적 분석:\** - 프롬프트가 의도대로 세팅되었는지 확인 가능하다.

\- 불필요한 루프(반복)가 발생하고 있는지 시각적으로 파악할 수 있다.

\- 에이전트가 도구를 적절한 시점에 호출하는지 모니터링할 수 있다.



\`\`` python

from langchain_upstage import ChatUpstage

from langchain.agents import create_agent

from langchain.agents.middleware import TodoListMiddleware

from langchain_core.tools import tool

import time

import os



from dotenv import load_dotenv

load_dotenv()



@tool(parse_docstring=True)

def internet_search(query: str) -> str:

\    """인터넷 검색을 수행하는 함수 (Mock).



\    Args:

\    query: 검색할 키워드



\    Returns:

\    검색 결과 문자열

\    """



\    time.sleep(3)



\    return f"'{query}'에 대한 검색 결과는 이렇습니다 - '제주도 코코마을 사는 인호님은 KFC를 좋아해'"



\# Upstage API는 아래 주석을 풀고 쓰세요.

model = ChatUpstage(model="solar-pro", upstage_api_key=os.getenv("UPSTAGE_API_KEY"), temperature=0)



agent = create_agent(

\    model=model,

\    tools=\[internet_search],

\    system_prompt="당신은 인터넷 검색을 통해 정보를 찾는 AI 어시스턴트입니다.",

\    middleware=\[TodoListMiddleware()],

)



\#질문 : 제주도에 코코마을이 있는데. 그 마을에 인호님이 유명하시지. 그 분이 좋아하는 선물을 추천해봐. 검색해줘

\`\``



!\[](https://velog.velcdn.com/images/paramad/post/14eb2f54-0c45-42b5-acd1-7101929e3254/image.png)



\- 모델이 '검색이 필요해'라고 하면 미들웨어가 이를 낚아채서 \`tools\`로 보냄.

\- 모델이 '이제 답을 줄게'라고 하면 미들웨어가 \`\_\_end\_\_\`로 보냄.

\- 곡선 화살표는 AI가 정답을 찾을 때까지 반복해서 사고하고 도구를 사용한다는 것을 의미. (빙글빙글 돌며 데이터를 보강하는 셈이다)



\#### Toolkit



\* \*\*Tool (개별 도구):\** \`인터넷\_검색()\`, \`현재\_시간_확인()\` 처럼 딱 하나의 기능을 하는 함수.

\* \*\*Toolkit (도구 모음):\** "오피스 작업용 도구 모음"이라고 하면 그 안에 \`엑셀\_읽기\`, \`메일\_쓰기\`, \`일정_등록\` 등 여러 도구가 한꺼번에 들어있는 패키지. 랭체인에서는 \`GmailToolkit\`, \`SQLDatabaseToolkit\` 등을 기본 제공한다.
