## 1. Dockerfile 작성 시 유의 사항
도커 빌드는 사용자와의 대화식이 아닌 자동화된 프로세스이므로, 모든 명령은 중단 없이 실행될 수 있도록 작성해야 한다.

* **자동 승인 옵션**: 패키지 설치 시 `apt install -y`와 같이 `-y` 옵션을 사용하여 대화식 확인 절차를 건너뛰어야 한다.
* **패키지 업데이트**: 기반 이미지(OS) 설치 후에는 `apt update`를 실행하여 패키지 리스트를 최신화해야 설치 오류를 방지할 수 있다.
* **레이어 최적화**: Dockerfile의 명령어 하나당 하나의 이미지 레이어가 생성된다. 불필요한 레이어 생성을 줄이기 위해 여러 명령을 `&&`로 연결하는 것이 좋다.
* **경로 지정**: 현재 디렉토리가 아닌 위치의 Dockerfile을 빌드할 때는 `-f` 옵션으로 경로를 명시해야 한다.

## 2. 멀티 스테이지 빌드 (Multi-stage Build)
빌드 단계와 실행 단계를 분리하여 최종 이미지의 크기를 획기적으로 줄이는 방식이다.

### 1) 개념
* 하나의 Dockerfile 안에 여러 개의 `FROM` 구문을 사용한다.
* 첫 번째 단계(builder stage)에서 소스 코드를 컴파일하고 빌드 아티팩트를 생성한다.
* 두 번째 단계(runtime stage)에서는 빌드 결과물만 복사해오고, 빌드에 사용된 도구와 캐시는 버린다.

### 2) Go 애플리케이션 빌드 실습
* **1단계 (gobuilder-stage)**: `golang` 이미지를 사용하여 소스 코드를 복사하고 바이너리 파일을 빌드한다.
* **2단계 (runtime-stage)**: 아주 작은 크기의 `scratch` 이미지를 사용하여 1단계에서 생성된 실행 파일만 가져온다.
* **결과**: 빌드 도구가 포함되지 않아 보안성이 향상되고 이미지 용량이 매우 가벼워진다.

## 3. 프라이빗 레지스트리 (Private Registry) 구축
이미지를 외부에 공개하지 않고 내부 네트워크에서만 사용할 저장소를 직접 운영하는 방식이다.

### 1) 레지스트리 서버 실행
* 도커 허브에서 제공하는 공식 `registry:2` 이미지를 사용하여 컨테이너를 구동한다.
* **명령어**: `docker run -d --name registry -p 5000:5000 registry:2`
* **확인**: `curl` 명령을 통해 해당 IP의 5000번 포트로 API 요청을 보내 상태를 확인한다.

### 2) GUI 인터페이스 추가
* 텍스트 기반의 레지스트리를 웹 브라우저에서 관리하기 위해 관리용 웹 컨테이너를 추가로 실행한다.
* `--link` 옵션을 사용하여 레지스트리 컨테이너와 연결하고, 환경 변수(`REGISTRY_URL`)를 설정하여 연동한다.

### 3) 이미지 업로드 절차
1. **태그 지정**: 로컬 이미지에 프라이빗 레지스트리 주소를 포함한 태그를 붙인다.
   * `docker tag [이미지명] [레지스트리IP]:5000/[이미지명]`
2. **푸시(Push)**: 태그된 이름을 사용하여 사설 저장소로 업로드한다.
   * `docker push [레지스트리IP]:5000/[이미지명]`
