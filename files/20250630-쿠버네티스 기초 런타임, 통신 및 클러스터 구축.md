## 1. 컨테이너 런타임
컨테이너를 생성하고 실행하며 전체 수명 주기를 관리하는 환경이다.

* **Containerd**: 도커에서 개발한 오픈 소스 런타임으로, 이미지 다운로드, 압축 해제, 실행 및 감독 등 핵심 기능을 제공한다.
* **Docker**: Containerd를 기반으로 구축된 데몬으로, 컨테이너 관리 전반의 기능을 제공한다.
* **CRI-O**: 도커를 대체하기 위해 레드햇, 인텔 등이 협력하여 개발한 오픈 소스 런타임이다.

## 2. 클러스터 내부 통신 원리
여러 노드에 흩어진 포드(Pod)들이 서비스 IP를 통해 서로 통신한다.

* **넷필터와 iptables**: 리눅스 커널의 패킷 처리 엔진으로, 서비스 IP를 실제 포드 IP로 변환하는 프록시 역할을 수행한다.
* **동작 방식**: 워커 노드가 서비스 IP를 실제 서버 IP로 변환하여 라우터로 전달함으로써, 클라이언트가 개별 포드 위치를 몰라도 서비스에 접근할 수 있다.

## 3. 클러스터 외부 통신 방식
내부 자원을 외부에서 접근할 수 있도록 노출하는 방법이다.

* **NodePort**: 각 노드의 IP에 특정 포트를 할당하여 외부 요청을 내부 서비스로 전달한다.
* **Load Balancer**: 퍼블릭 클라우드의 로드 밸런서를 사용하여 외부 전용 IP를 할당받는다.
* **Ingress**: HTTP/HTTPS 요청을 처리하는 규칙 모음으로, URL 기반 라우팅과 SSL 인증서 처리를 정의한다.

## 4. 클러스터 구축 도구

### 1) 로컬 구축 도구
* **Minikube**: 단일/다중 노드 클러스터를 가상 환경에 쉽게 구축한다.
* **Kind**: 도커 컨테이너를 노드로 활용하여 다중 노드 구성을 테스트한다.
* **k3s**: 경량화된 쿠버네티스로 저사양 환경에 적합하다.

### 2) 다중 머신 구축 도구
* **kubeadm**: 가장 표준적인 구축 도구로 세부 설정이 다양하다.
* **kubespray**: Ansible 기반 자동화 도구로 온프레미스와 클라우드 모두 지원한다.
* **kops**: 클라우드 환경(AWS 등)에서 클러스터 관리에 최적화되어 있다.

## 5. 네임스페이스
물리적 클러스터를 가상으로 분리하여 팀별/환경별로 자원을 관리한다.

* **기본 네임스페이스**: `default`, `kube-system`, `kube-public`
* **보안 연계**: RBAC이나 네트워크 정책으로 네임스페이스 간 보안 경계를 강화할 수 있다.

## 6. kubectl과 리소스 관리

### 1) 인증 관리
* **Kubeconfig**: `~/.kube/config` 파일에 클러스터 주소, 사용자 인증 정보, 컨텍스트를 정의한다.

### 2) 리소스 생성 방식
* **명령어 기반 (Imperative)**: `kubectl run`, `kubectl create`로 즉시 생성한다.
* **선언적 관리 (Declarative)**: `kubectl apply`로 YAML 파일에 정의된 상태를 적용한다. CI/CD 환경에서 권장된다.

### 3) 삭제 및 고급 제어
* **일반 삭제**: `kubectl delete`는 비동기 처리되며, `--wait` 옵션으로 완료를 기다릴 수 있다.
* **강제 삭제**: `--force --grace-period 0` 옵션으로 즉시 제거한다.
* **롤아웃 재시작**: `kubectl rollout restart deployment [이름]`으로 포드를 순차적으로 재기동한다.
