## 1. 클라우드 보안의 개요
클라우드 도입 시 가장 큰 고려 사항은 보안이다. 클라우드 환경에서도 기존 IT 환경의 보안 위협은 여전히 존재하며, 가상화와 자원 공유로 인한 새로운 위험 요소들이 추가된다.

### 1) 주요 보안 위협
* **관리적 위협**: 클라우드 서비스 제공자(CSP)의 보안 기능이 기존 기업 내부 정책과 달라 정책 적용에 한계가 발생할 수 있다.
* **기술적 위협**: 인터넷 기반 인프라 구축으로 인해 정보 유출 및 해킹 공격 노출 범위가 확대된다.
* **가상화 위협**: 하이퍼바이저 탈취 시 해당 시스템을 사용하는 모든 사용자가 피해를 입을 수 있는 구조적 취약점이 존재한다.
* **사용자 실수**: 클라우드 설정 오류(스토리지 노출 등)나 계정 관리 미흡으로 인한 대규모 데이터 유출 사고가 빈번하게 발생한다.

## 2. 클라우드 보안 설계 원칙

### 1) 책임 공유 모델 (Shared Responsibility Model)
클라우드 보안은 서비스 제공자와 사용자가 책임을 나누어 갖는 구조다.
* **CSP의 책임**: 물리적 데이터 센터, 서버 하드웨어, 스토리지 및 네트워크 인프라의 보안을 담당한다.
* **사용자의 책임**: 데이터 암호화, 애플리케이션 보안, 운영체제 설정 및 사용자 인증 관리에 대한 책임을 진다.

### 2) 책임 추적성 필수 요건
안전한 클라우드 운영을 위해 '누가, 언제, 무엇을 했는지'를 추적할 수 있어야 한다.
* **식별(ID) 및 인증(Auth)**: 사용자가 누구인지 확인하고 신원을 검증한다. (MFA 등 다중 요소 인증 권장)
* **인가(Authorization)**: 인증된 사용자에게 최소 권한 원칙에 따라 필요한 작업 권한만 부여한다.
* **로깅 및 모니터링**: 모든 행위를 기록하고 이상 징후를 실시간으로 분석한다. (AWS CloudWatch 등 활용)
* **감사(Audit)**: 로그를 검토하여 보안 기준 준수 여부와 위험 요소를 정기적으로 점검한다.

## 3. 보안 모델의 변화

### 1) 성벽형(경계형) vs 공항형 모델
* **성벽형 모델**: 전통적인 보안 방식으로, 외부 침입을 막기 위해 방화벽으로 경계를 치는 방식이다.
* **공항형 모델**: 현대적 클라우드 보안 방식으로, 내부와 외부의 경계를 물리적 위치에 한정하지 않고 양방향에 대해 정밀한 출입 심사(인증/로깅/모니터링)를 수행하는 방식이다.

### 2) 제로 트러스트 (Zero Trust)
'아무도 믿지 않는다'는 원칙 아래, 네트워크 내부의 사용자라도 지속적으로 신뢰를 검증하는 모델이다. 마이크로 세그먼테이션과 소프트웨어 정의 경계 기술을 통해 보안을 강화한다.

### 3) 섀도우 IT (Shadow IT)
IT 부서의 승인 없이 직원들이 임의로 사용하는 클라우드 자원을 의미한다. 중요 정보의 외부 유출 경로가 될 수 있으므로 철저한 가시성 확보가 필요하다.

## 4. 클라우드 보안 서비스 및 기술

### 1) 주요 네트워크 보안 도구
* **VPC (Virtual Private Cloud)**: 논리적으로 격리된 가상 사설 네트워크를 구성하여 상호 간 호출을 차단한다.
* **서브넷(Subnet)**: VPC 내부를 공용(Public)과 사설(Private) 구역으로 나누어 민감한 자원을 외부에 노출되지 않도록 배치한다.
* **ACL 및 보안 그룹**: 
    - **ACL**: 서브넷 단위로 패킷 통과를 허가/거부하는 목록이다.
    - **보안 그룹**: 인스턴스(서버) 단위의 가상 방화벽으로 3, 4계층 필터링을 수행한다.
* **TLS 구간 암호화**: 데이터 전송 시 패킷을 암호화하여 도청과 변조를 방지한다.

### 2) AWS 주요 보안 서비스 예시
* **IAM**: 사용자 계정 및 권한을 중앙에서 관리한다.
* **KMS/CloudHSM**: 암호화 키를 안전하게 생성하고 관리한다.
* **GuardDuty/Macie**: 위협을 지속적으로 탐지하고 민감한 데이터를 머신러닝으로 분류 및 보호한다.
* **WAF/Shield**: 웹 애플리케이션 공격과 DDoS 공격으로부터 인프라를 보호한다.
* **AMI (골드 환경)**: 보안 설정이 완료된 사용자 정의 이미지를 생성하여 일관된 보안 수준을 유지한다.
