## 1. Git 초기화 및 설정
디렉토리를 Git 저장소로 관리하기 위한 초기 단계다.

### 1) 저장소 생성 (git init)
* 명령어를 실행하면 `.git` 숨김 디렉토리가 생성되며 버전 관리가 시작된다.
* `.git` 디렉토리를 삭제하면 연동이 해제되고, 복사하여 다른 곳에 두면 해당 시점의 저장소 상태를 그대로 옮길 수 있다.

### 2) 사용자 정보 설정 (git config)
커밋을 남기기 위해서는 사용자 이름과 이메일 설정이 필수적이다.
* **설정 범위**: 로컬 저장소별 설정뿐만 아니라 `--global` 옵션을 통해 시스템 전체에 적용할 수 있다.
* **우선 순위**: 로컬 설정이 글로벌 설정보다 우선하며, 최종적으로 시스템 설정이 적용된다.
* **확인 및 해제**: `git config --list`로 전체 설정을 확인하고, `--unset` 옵션으로 특정 항목을 삭제할 수 있다.

## 2. 기본 워크플로우: add와 commit
파일의 변경 사항을 추적하고 저장소에 기록하는 과정이다.

* **상태 확인 (git status)**: 현재 브랜치 정보, 커밋되지 않은 변경 사항, 추적되지 않는 파일(Untracked files) 등을 확인한다.
* **스테이징 (git add)**: 변경된 파일을 커밋 대기 상태로 만든다. `.`을 사용하면 현재 디렉토리의 모든 변경 사항을 추가한다.
* **기록 (git commit)**: 스테이징된 파일들을 메시지와 함께 저장소에 영구적으로 기록한다.

## 3. 원격 저장소(Remote Repository) 연동
GitHub 등 외부 저장소와 데이터를 주고받기 위한 설정이다.

### 1) 원격 저장소 관리
* **연결 확인**: `git remote -v`를 통해 다운로드(fetch)와 업로드(push) 경로를 확인한다.
* **상세 정보**: `git remote show [이름]` 명령어로 원격 저장소의 상세 상태와 브랜치 추적 정보를 볼 수 있다.

### 2) 업스트림(Upstream) 설정
* 브랜치 간의 상호 추적을 위해 `git push -u [원격명] [로컬브랜치명]` 명령을 사용한다.
* 한 번 설정하면 이후에는 `git push`나 `git pull`만으로도 지정된 원격 브랜치와 통신이 가능하다.

### 3) 데이터 동기화 (push와 pull)
* **push**: 로컬에서 커밋한 내용을 원격 저장소로 업로드한다. 로컬 커밋이 완료된 상태에서 실행해야 한다.
* **pull**: 원격 저장소의 최신 업데이트 내용을 로컬로 가져와 병합한다.

## 4. 기타 유용한 명령어
* **로그 확인**: `git log --oneline`을 통해 커밋 히스토리를 간결하게 한 줄씩 확인할 수 있다.
