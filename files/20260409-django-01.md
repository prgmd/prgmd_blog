# Django
## 1. 서론
![](https://velog.velcdn.com/images/paramad/post/20e1719a-32e7-455a-b7d4-278533faf4f5/image.png)

세상에는 많은 장고가 있다. 원피스의 장고, 영화 장고, 포켓몬의 쟝고, 침착맨의 DJ앙꼬... 하지만 오늘 배울 장고는 Python 오픈소스 웹 프레임워크 Django다.

2005년 7월 로렌스 저널 월드에서 일하던 에이드리안 홀로바티, 사이먼 윌리슨이 만들어 공개했다. 초기에는 신문사 웹사이트를 효율적으로 운영하려는 내부 도구에서 출발했다고. 반복되는 개발 작업을 줄이고자 **공통 기능, 설계 원칙**이 정리됐고, 이러한 결과물이 공개 프레임워크로 자리 잡았다고 한다.

이후 릴리스마다 기능을 확장하며 발전을 거뒀다. (DB 지원, 템플릿 엔진, 캐시 처리, 비동기 처리 등 현대 웹 개발에 필요한 요소들) 현재까지도 높은 점유율을 보이고 있다. Python 웹 프레임워크 중에서는 Flask 다음으로 2위급 인기를 유지 중. 상위 10위 안에 들어간다고 보고된다.

현재는 CMS, 전자상거래, SNS, 멀티테넌트 서비스 같이 일반 웹 앱에 널리 쓰인다. (대표 예시로는 Spotify, Instagram, Dropbox, NASA, The Washington Post 등) 특히 **REST API 백엔드 구축**에 많이 활용되는 편. 실무에서는 **SaaS**에 잘 맞는 편이다. ORM, 인증, 관리자 페이지, 보안 기능, 빠른 프로토타이핑에 상당히 강하고, 그 덕에 대시보드, CRUD 중심 관리 시스템, 내부 업무 도구, 데이터 중심 서비스, AI/ML 모델 구축에 능하다고. 

풀 스택 프레임워크긴 한데, Django의 Frontend 기능은 다른 전문적인 프레임워크에 비하면 매우 미흡한 편.

### 타 프레임워크와의 비교

경쟁사회 아니랄까봐 또 싸움을 붙이느냐 물어볼 수 있겠다만, 여기는 개발 사회다. 엄밀히 경우 따져야지. 웹 프레임워크는 화면이 이쁘고 테마가 마음에 드는지로 결정하는 문제보다, 이 프레임워크가 어떤 유형의 웹 앱을 만들 때 강한지, 어떤 툴킷을 가지고 있는지를 보고 선택해야 한다.

- Django: 풀스택 완성형 웹 앱에 강함. 
- Flask: 마이크로프레임워크. 필요한 것만 선택하는 것이 모토다. 프로토타이핑과 소형 서비스 제작에 적합하고, 매우 가볍고 유연해 초기 설정이 쉽다.
- FastAPI: 비동기 친화성, 고성능 API, 자동 문서화(Swagger, PyDantic)에 초점. 빠른 I/O 속도를 지원한다. 실시간 서비스나 고부하 API에 강하며, ML/마이크로서비스에 자주 사용된다. 

### 프론트엔드 프레임워크의 역할
```
[Client] - [Front-end] - [Server]
```

백엔드는 클라이언트의 요청을 처리하고 DB와 상호작용하는 단이다. **참고로 Django는 백엔드로 활용되는 대표적인 프레임워크**.

### 설치
```
pip install django
django-admin startproject project .
python manage.py runserver
```

## 2. 디자인 패턴 / 프로젝트와 앱
> 소프트웨어 설계에서 반복 발생하는 문제에 대해 사용하는 일반적으로 검증된 해결책. 재사용이 가능하다는 것이 특징.

### 2.1 디자인 패턴

#### MVC 디자인 패턴
> 하나의 애플리케이션을 Model, View, Controller로 구조화하는 대표적인 디자인 패턴. 각 로직을 독립적으로 운영하고 쉽게 유지 보수할 수 있다.

- Model: 데이터, 비즈니스 로직을 처리
- View: 사용자에게 보이는 화면을 담당
- Controller: 사용자 입력을 받아 Model과 View를 제어

#### MTV 디자인 패턴
> MVC 패턴과 동일. 단순히 명칭을 다르게 정리한 것.

- Model: 데이터, 비즈니스 로직을 처리
- ~~View~~ Template: 사용자에게 보이는 화면을 담당
- ~~Controller~~ View: 사용자 입력을 받아 Model과 Template를 제어 (비즈니스 로직을 처리하는 연산 장치)

### 2.2 프로젝트와 앱
> 장고는 MTV 디자인 패턴을 사용한다. 기존 MVC 패턴과 동일하나 단순 명칭을 달리한 패턴.

- Django Application: 독립적으로 작동하는 기능 단위 모듈 (각자 특정 기능 담당. 다른 앱들과 하나의 프로젝트를 구성한다)
- Django Project: Django Application의 집합 (DB 설정, URL 연결, 전체 앱 설정 등)

``` bash
# 앱 생성
python manage.py startapp articles
```

위 명령어를 수행하면, '`articles`' 폴더와 내부에 여러 파일이 생성되는 것을 볼 수 있다. (앱 이름은 복수형으로 지정하는 것을 권장)

※ 유의: 반드시 앱을 생성한 후 등록해야 한다. 등록을 먼저 할 경우 생성을 위한 명령어 실행 중 아직 존재하지 않은 앱을 찾으려다 실패한다.

### 앱 구조
'Battery Included(모든 게 준비된)' 철학 때문에, 앱 생성시 자동으로 기초 파일이 만들어진다. 이렇게 만들어두면 처음 보는 사람도 어디에 어떤 기능을 만들어야 할지 파악이 쉽기 때문. 각 파일이 뭔지만 간단하게 알아두자.

- `__init__.py`: 해당 폴더를 패키지로 인식하도록 설정하는 파일
- `settings.py`: 프로젝트의 모든 설정 관리
- `urls.py`: 요청이 들어오는 URL에 따라, 이에 해당하는 적절한 `views` 연결
- `asgi.py`: 비동기식 웹 서버와의 연결 관련 설정
- `wsgi.py`: 웹 서버와의 연결 관련 설정
- `manage.py`: Django 프로젝트와 다양하게 상호작용하는 커맨드라인 유틸리티
- `admin.py`: 관리자용 페이지 설정
- `models.py`: DB와 관련된 Model 정의. MTV 패턴의 M을 맡는다
- `views.py`: HTTP 요청을 처리하고 해당 요청에 대한 응답을 반환. MTV 패턴의 V를 맡는다
- `apps.py`: 앱의 정보가 작성된 곳
- `tests.py`: 프로젝트 테스트 코드 작성하는 곳

## 3. 요청과 응답 프로세스

일단 Django는 다음과 같은 프로세스로 사용자 요청을 처리한다.

```
- 사용자가 URL을 요청함
- urls.py가 URL을 확인
- views.py의 함수를 호출함
- 사용자 요청을 처리하고 결과를 HTML로 응답

```

그렇다면 앞서 제작한 `articles` 앱에 요청이 왔다고 가정해보자.

```
[사용자 요청] → http://127.0.0.1:8000/articles/ → [urls.py] →
적절한 views.py에 연결 → [views.py] → [models.py], [templates]...
```

이 때 `urls.py`은 request 객체를 views 모듈의 index view 함수에 전달하며 호출한다.

``` py
# urls.py
from django.contrib import admin
from django.urls import path
from articles import views # articles 패키지에서 views 모듈 가져옴

urlpatterns = [
	path('admin/', admin.site.urls),
    path('articles/', views.index), # url 경로는 반드시 /로 끝나야 한다
]
```

그러면 특정 경로에 있는 template와 request 객체를 결합해 응답 객체로 반환한다.

``` py
# views.py
from django.shortcuts import render

def index(request): # 요청 객체 받기 (필수)
	return render(request, 'articles/index.html')
```

모든 view 함수는 **첫번째 인자로 요청 객체를 필수적으로 받고, 매개변수 이름은 `request`가 아니어도 되지만 관례적으로 이렇게 적는 편**.

이후 `articles` 앱 폴더 안에 `templates` 폴더를 생성하고 (**반드시 폴더명은 templates여야 한다. 그래야 Django가 읽을 수 있다. 이는 개발자가 직접 생성해야 함**) 그 안에 `articles` 폴더 - 템플릿 파일을 생성해야 한다 (`index.html`을 만들어서 그 값을 반환하도록) Django는 templates 지점까지 기본 경로로 인식한다. 

#### 간략한 데이터 흐름
> URLs : path('articles'/, **view.index**),
> View : def **index** ... return render(request, **'articles/index.html'**)
> Template : articels/templates/**articles/index.html**

## render 함수
주어진 템플릿을 컨텍스트 데이터에 결합하고 렌더링된 텍스트와 함께 HttpResponse 응답 객체를 반환하는 함수.

```
render(request, template_name, context)
```

- request: 응답 생성시 사용되는 요청 객체
- template_name: 템플릿 이름 경로
- context: 템플릿에서 사용할 데이터로, 딕셔너리 타입으로 작성해야 한다. 생략 가능

## 그 외 Django 관련
### Trailing Comma (후행 쉼표)
리스트, 딕셔너리, 튜플 등 자료구조에서 마지막 요소 뒤 쉼표를 추가하는 것. 문법적으로는 아무런 영향을 주지 않는다. 일반적으로는 선택사항. (단일 요소 튜플 만들 때는 예외)

새로운 요소를 추가하거나 순서 변경시 편리하다고 사용. 혹은 시간이 지남에 따라 확장될 요소라면 적어둔다고 한다.

### LTS (Long-Term Support)
프레임워크, 라이브러리 등 소프트웨어에서 장기간 지원되는 안정적 버전을 부를 때 사용. 기업이나 대규모 프젝에서는 소프트웨어 업글에 많은 비용과 시간이 필요하기 때문에 장기간 지원되는 버전이 꼭 필요하다.
