## 1. 기본 통신 확인 (ping)
특정 목적지까지 네트워크가 정상적으로 동작하는지 확인하는 가장 대표적인 명령어다.

* **동작 원리**: ICMP(Internet Control Message Protocol) 프로토콜의 제어 메시지를 사용하여 상대 호스트의 접속 가능 여부와 통신 경로를 체크한다.
* **주요 옵션**:
    - `-c [개수]`: 보낼 패킷의 수를 지정한다. (리눅스는 기본적으로 무제한 전송)
    - `-i [초]`: 패킷 전송 시간 간격을 설정한다. (기본 1초)
    - `-s [사이즈]`: 패킷의 크기를 지정한다.
* **로컬 확인**: `ping 127.0.0.1`을 통해 자신의 네트워크 인터페이스 카드(NIC)가 정상인지 먼저 확인하는 용도로도 쓰인다.

## 2. 경로 추적 및 분석 (traceroute)
출발지부터 목적지까지 거치는 모든 경로(Hop)를 추적하여 어느 구간에서 지연이나 장애가 발생하는지 파악한다.

* **동작 방식**: 패킷의 TTL(Time to Live) 값을 하나씩 늘려가며 경로상의 라우터 정보를 수집한다.
* **포트 기반 확인**: 일반적인 `traceroute`는 UDP를 사용하지만, 방화벽 통과 여부를 확인하기 위해 TCP를 사용하는 `tcptraceroute`를 활용하기도 한다.

## 3. 네트워크 상태 정보 출력 (netstat)
현재 시스템의 네트워크 연결 상태, 라우팅 테이블, 인터페이스 통계 등을 보여준다.

* **자주 사용하는 옵션 조합**:
    - `netstat -an`: 모든 소켓 정보를 숫자로 출력한다.
    - `netstat -p`: 소켓과 관련된 프로세스 이름과 PID를 함께 보여준다.
    - `netstat -r`: 라우팅 테이블 정보를 출력한다.
* **포트 확인**: `netstat -an | grep LISTEN` 명령을 통해 현재 시스템에서 대기 중인 서비스 포트를 확인할 수 있다.

## 4. 기타 주요 진단 도구
* **arp**: 동일 네트워크 내에 있는 장비의 IP 주소와 대응하는 MAC 주소를 확인한다.
* **telnet [IP] [Port]**: 특정 서비스 포트가 실제로 열려 있는지(Listening 상태인지) 테스트할 때 유용하다. 연결에 성공하면 화면이 전환되거나 프롬프트가 바뀐다.
* **dig / nslookup**: DNS 설정이 올바른지 확인하고 도메인에 대한 IP 주소를 질의한다.

## 5. 네트워크 전송 실패 원인 분석
통신이 되지 않을 때는 크게 내부적 요인과 외부적 요인으로 나누어 점검한다.

* **내부 조치**: 자신의 IP 설정(`ifconfig -a`), 기본 게이트웨이 설정(`ip route`), DNS 설정(`dig`)을 차례로 확인한다.
* **외부 요인**: 
    - 경로상의 라우터 설정 오류
    - 네트워크 중간에 위치한 보안 장비(IPS, 방화벽 등)의 차단
    - 도착지 서버의 방화벽(iptables 등) 설정
    - 도착지 서버의 서비스 자체가 구동되지 않은 경우(Port Not Listening)
