## 1. Git Hub을 이용한 협업 기초
원격 저장소를 복제하고 팀원들과 데이터를 동기화하는 기본 과정이다.

### 1) 저장소 복제 (git clone)
* 원격 저장소의 전체 히스토리를 로컬 디렉토리로 내려받는다. 별도의 이름을 지정하지 않으면 저장소 이름과 동일한 디렉토리가 생성된다.

### 2) 동기화 (push와 pull)
* 작업 전에는 항상 `git pull`을 통해 원격 저장소의 최신 변경 사항을 로컬에 반영해야 한다.
* 로컬에서 커밋한 내용을 공유하려면 `git push`를 실행하며, 브랜치를 명시하여 특정 브랜치로 업로드할 수 있다.

## 2. 충돌(Conflict) 해결
서로 다른 작업자가 동일한 파일의 같은 부분을 수정했을 때 발생한다.

* **발생 원인**: `git pull` 과정에서 로컬의 변경 사항과 원격의 변경 사항이 겹쳐 Git이 자동으로 병합할 수 없을 때 발생한다.
* **해결 방법**: 충돌이 발생한 파일을 열어 Git이 표시한 구분자(`<<<<`, `====`, `>>>>`)를 확인하고, 최종적으로 남길 코드를 선택하여 수동으로 수정한다. 수정 완료 후 `git add`와 `git commit`을 거쳐 병합을 마무리한다.

## 3. 브랜치 머지 전략
브랜치를 병합할 때 프로젝트의 특성에 따라 다양한 방식을 선택할 수 있다.

* **Fast-Forward**: 타겟 브랜치에 추가적인 커밋이 없을 때, 단순히 브랜치 포인터를 최신 커밋으로 이동시키는 방식이다. 별도의 머지 커밋이 생성되지 않는다.
* **Recursive Merge**: 양쪽 브랜치에 모두 변경 사항이 있을 때 공통 조상을 찾아 병합하며, 새로운 'Merge Commit'을 생성한다. 병합 이력이 명확히 남는다는 장점이 있다.
* **Squash Merge**: 병합될 브랜치의 모든 커밋을 하나로 합쳐서 타겟 브랜치에 추가한다. 히스토리가 매우 깔끔해지지만, 개별 커밋의 상세 내역은 사라진다.

## 4. 리베이스 (Rebase)
브랜치의 기반 지점(Base)을 최신 상태로 재배치하는 기능이다.

* **목적**: 복잡하게 갈라진 브랜치 히스토리를 한 줄로 깔끔하게 정리하고 싶을 때 사용한다.
* **특징**: `merge`는 변경 사항을 합치는 커밋을 새로 만들지만, `rebase`는 커밋들을 대상 브랜치 뒤로 다시 배치하여 히스토리를 선형적으로 만든다.
* **주의**: 이미 원격 저장소에 공유된 커밋에 대해서는 리베이스를 지양해야 한다.

## 5. 브랜치 관리 팁
* **git checkout -b**: 브랜치 생성과 동시에 해당 브랜치로 이동한다.
* **git branch -d**: 작업이 완료된 브랜치를 삭제하여 저장소를 청결하게 유지한다.
* **로그 확인**: `--graph` 옵션을 사용하면 브랜치의 분기 및 병합 상태를 시각적으로 확인할 수 있다.
