## 1. Config & Storage API 개요
컨테이너에 설정 파일이나 패스워드와 같은 기밀 정보를 주입하고, 데이터를 보관할 영구 볼륨을 제공하기 위해 사용되는 리소스다.

* **Secret**: 비밀번호, 토큰 등 보안이 필요한 데이터 관리
* **ConfigMap**: 일반적인 설정값이나 스크립트 관리
* **영구 볼륨 클레임 (PVC)**: 파드에 영구 저장소를 할당하기 위한 요청

## 2. 쿠버네티스 환경 변수 설정
파드 템플릿의 `env` 또는 `envFrom` 필드를 사용하여 컨테이너 내부에 환경 변수를 전달할 수 있다.

### 1) 환경 변수 포함 정보
* **정적 설정**: 사용자가 직접 입력한 고정값 (예: MAX_CONNECTION)
* **파드/컨테이너 정보**: 파드의 이름, IP, 컨테이너 리소스 제한 정보 등
* **시크릿 데이터**: Secret 리소스에 저장된 기밀 정보
* **컨피그맵 데이터**: ConfigMap 리소스에 저장된 설정값

### 2) 타임존 설정
`TZ` 환경 변수를 활용하여 컨테이너의 시간대를 설정할 수 있으며, `kubectl exec` 명령어를 통해 적용 여부를 확인할 수 있다.

## 3. 시크릿 (Secret)
보안이 중요한 기밀 정보를 취급하기 위한 전용 리소스다.

* **저장 위치**: 마스터 노드의 분산 키-값 저장소인 `etcd`에 저장된다.
* **데이터 전송 및 보관**: 해당 시크릿을 사용하는 파드가 있는 노드에만 전송되며, 보안을 위해 메모리 기반 임시 파일 시스템(`tmpfs`)에 저장되어 디스크에 물리적으로 남지 않는다.
* **보안 취급**: `describe` 명령으로는 내용을 직접 볼 수 없으며, YAML 출력 시에도 `base64`로 인코딩되어 나타난다. 운영 환경에서는 별도의 암호화 솔루션과 연동하는 것이 권장된다.

## 4. 컨피그맵 (ConfigMap)
기밀 정보가 아닌 일반적인 설정 스크립트나 구성 파일을 관리할 때 사용한다.

* **데이터 마운트**: 컨피그맵에 저장된 데이터를 파일 형태로 파드에 마운트할 수 있으며, 이때 파일의 실행 권한(퍼미션)을 직접 지정할 수 있다.
* **자동 갱신**: 볼륨 마운트 방식으로 연결된 경우, 컨피그맵의 내용이 변경되면 쿠버네티스가 이를 감지하여 약 1분 이내에 컨테이너 내부의 파일 내용도 자동으로 업데이트한다.
