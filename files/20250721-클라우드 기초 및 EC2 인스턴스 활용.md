# I. 클라우드

## 1. 클라우드 컴퓨팅

> 인터넷을 통해 IT 리소스를 빌려 쓰는 방식. 

과거에는 서버실에 직접 기계를 사고 전선을 연결했다면, 요즘은 클릭 몇 번으로 전 세계 어디서든 고성능 컴퓨터와 저장 공간을 사용할 수 있게 됐다. 원격 접속과 클라우드를 엄연히 다르다! 두 용어를 헷갈리는 사람들이 존재.

### 1.1 핵심 특징 (NIST 정의 기준)

* On-demand Self-service: 서비스 제공자와 직접 소통할 필요 X. **그저 사용자가 원하면 즉시 리소스를 할당받는다.**
* 다양한 플랫폼(모바일, 노트북 등)에서 접속 가능
* **리소스 풀링 (Resource Pooling)**: 여러 사용자가 물리적인 자원을 공유.
* **탄력성**: 트래픽이 몰리면 순식간에 확장하고, 필요 없으면 즉시 축소하여 비용을 절감
* 전기료처럼 **사용한 만큼만 요금이 부과**되는 종량제 방식

### 1.2 클라우드 서비스 모델

| 모델       | 의미                           | 관리 범위                                                                                                                                        | 비유                          |
| -------- | ---------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------- |
| **IaaS** | **컴퓨터 하드웨어를 빌려주는 인프라형 서비스**. | 가상 서버, 네트워크, 스토리지 등 하드웨어 자원만 제공하며, 사용자는 OS(Windows, Linux 등)를 직접 설치하고, 그 위에 소프트웨어를 올린다. 서버 구축, 데이터베이스 설치, 대규모 컴퓨팅 작업 등 하드웨어 제어권이 필요할 때 사용한다. | 주방 기구와 가스레인지가 갖춰진 **공유 주방** |
| **PaaS** | **개발 환경을 빌려주는 플랫폼형 서비스**.    | OS, 실행 환경, DB 등 개발에 필요한 환경까지 제공. 관리나 업데이트는 업체가 다 알아서 해주고, 개발자는 오직 코드만 짜서 올리면 된다. 서버 설정보다는 개발 자체에 집중하고 싶을 때, 혹은 빠른 배포가 중요할 때 사용한다.            | 재료만 넣으면 요리가 되는 **밀키트 서비스**  |
| **SaaS** | **완성된 소프트웨어를 빌려주는 서비스.**     | 별도의 설치 없이 웹 브라우저나 앱으로 로그인만 하면 바로 기능을 사용할 수 있으며, 완성된 애플리케이션을 웹/앱으로 즉시 이용할 때 사용한다. 우리가 일상에서 쓰는 대부분의 서비스가 바로 SaaS.                              | 요리가 다 되어 나오는 **레스토랑**       |

#### 주요 예시

1. IaaS (Infrastructure as Service): 

* **AWS EC2**: 아마존에서 빌려주는 가상 서버입니다. 사양을 골라 원하는 대로 서버를 구축합니다.
* **Google Compute Engine (GCE)**: 구글의 인프라 위에서 가상 머신을 돌립니다.
* **Microsoft Azure VM**: 마이크로소프트의 가상 서버 서비스입니다.
* **네이버 클라우드 플랫폼 (NCP)**: 국내 기업들이 많이 사용하는 가상 서버 인프라입니다.

2. PaaS (Platform as a Service)

* Heroku: 코드를 올리면 바로 웹 서비스로 배포해주는 가장 유명한 PaaS 중 하나.
* AWS Elastic Beanstalk: 개발자가 코드를 업로드하면 AWS가 알아서 용량 조절, 로드 밸런싱을 처리한다.
* Google App Engine: 구글 인프라에서 돌아가는 애플리케이션 개발 플랫폼.
* Red Hat OpenShift: 컨테이너 기반의 애플리케이션 개발 및 운영 플랫폼.

3. SaaS (Software as a Service)

* 주요 예시 (B2C; Business-to-Consumer)

  * Google Drive / Google Docs: 웹에서 바로 문서 작성을 하고 저장.
  * Netflix / Spotify: 스트리밍 소프트웨어를 구독해서 이용.
  * Dropbox: 클라우드 기반의 파일 저장 서비스.
* 주요 예시 (B2B; Business-to-Business)

  * Slack: 협업용 메신저.
  * Salesforce: 세계 1위 고객 관계 관리(CRM) 소프트웨어.
  * Zoom: 화상 회의용 소프트웨어.
  * Notion: 올인원 협업 및 노트 도구.

### 1.3 클라우드 배포 모델

* **퍼블릭 클라우드(Public Cloud)**: AWS, Azure, GCP처럼 전문 업체가 관리하는 자원을 누구나 이용하는 방식.
* **프라이빗 클라우드(Private Cloud)**: 특정 기업 내부에서만 사용하기 위해 독립적으로 구축한 환경.
* **하이브리드 클라우드(Hybrid Cloud)**: 퍼블릭의 유연성과 프라이빗의 보안성을 결합하여 연동한 방식.
* **멀티 클라우드(Multi-Cloud)**: 장애 대비나 비용 최적화를 위해 두 개 이상의 퍼블릭 클라우드 업체를 동시에 사용하는 방식.

### 1.4 온프레미스와의 비교

| 구분        | 온프레미스 (Traditional IT)       | 클라우드 (Cloud)                  |
| --------- | ---------------------------- | ----------------------------- |
| **초기 비용** | 서버 구매 등 막대한 초기 자본 필요 (CAPEX) | 초기 비용 거의 없음, 사용한 만큼 지불 (OPEX) |
| **구축 속도** | 장비 발주부터 설치까지 수주~수개월 소요       | 단 몇 분 이내에 배포 완료               |
| **유지 관리** | 하드웨어 고장, 전기, 냉방 등 직접 관리      | 서비스 제공자가 하드웨어 및 물리 보안 책임      |
| **확장성**   | 서버실 공간 및 장비 한계로 확장이 어려움      | 사실상 무제한에 가까운 확장성 제공           |

# II. AWS

> 아마존에서 운영하고 전 세계적으로 가장 널리 사용되는 퍼블릭 클라우드 서비스로, 인프라 구축에 필요한 다양한 기능을 모듈식으로 제공한다. 

## 1. AWS의 등장 배경

2000년대 초반, 아마존은 급격히 성장하며 매년 블랙 프라이데이 같은 거대한 쇼핑 시즌을 견뎌낼 인프라가 필요했고, 이를 버티기 위해 평소보다 10배 넘는 트래픽을 견디기 위해 서버를 엄청나게 샀지만 정작 쇼핑 시즌이 지나면 그 비싼 서버의 90%가 노는 상태가 되는 것. 

이 남는 컴퓨팅 파워를 외부 개발자들에게 빌려주면 어떨까? 아이디어에서 시작한 것이 바로 AWS다. 2006년, S3(저장소)와 EC2(서버)를 출시하며 세상에 없던 '클라우드' 시장을 열었고, 서버가 없어도 아이디어만 있으면 서비스를 시작할 수 있다는 점 덕분에 Netflix, Airbnb, Instagram 등이 뛰어들었다.

처음에는 남의 컴퓨터에 우리 소중한 데이터를 어떻게 맡기나며 의심했지만, 정작 개별 기업이 직접 관리하는 서버실보다 보안 전문가 수만 명이 24시간 감시하는 AWS 데이터 센터가 훨씬 안전하다는 사실이 증명되면서 하나둘 AWS로 전환하기 시작. 이후 글로벌 데이터센터를 확장하기 시작하고, 점차 여러 확장된 서비스(서버리스의 Lambda, 머신러닝 모델은 SageMaker, 생성형 AI Bedrock 등)를 내면서 오늘날의 거대 기업이 됐다. 

## 2. 글로벌 인프라 구성

서비스를 '어디에' 배치할 것인가에 대한 물리적 기준.

| 구성 요소           | 정의 및 특징                            | 실무적 포인트                              |
| --------------- | ---------------------------------- | ------------------------------------ |
| **리전 (Region)** | 전 세계에 분산된 물리적 지점 (예: 서울, 도쿄, 버지니아) | 데이터 주권(법규)과 사용자 거리를 고려해 선택           |
| **가용 영역 (AZ)**  | 리전 내 격리된 데이터 센터 군 (최소 3개 이상)       | **고가용성(HA)**을 위해 최소 2개 이상의 AZ에 분산 배치 |
| **에지 로케이션**     | CloudFront(CDN)를 위한 캐시 거점          | 전 세계 사용자에게 정적 콘텐츠를 빠르게 전달            |

## 3. 주요 서비스

* **컴퓨팅**: EC2(가상 서버), EKS(쿠버네티스), ECS(컨테이너 레지스트리)
* **스토리지**: S3(오브젝트 스토리지), S3 Glacier(장기 보관), EBS(인스턴스용 디스크)
* **네트워크**: VPC(가상 네트워크), Route 53(DNS), Elastic IP(정적 IP)
* **데이터베이스**: RDS(관계형 DB)
* **개발자 도구**: Cloud9(웹 기반 IDE), CodeBuild, CodePipeline(DevOps)

## 3. EC2(Elastic Compute Cloud) 띄우기 기본 실습

### 3.1 인스턴스 생성 절차

1. **AMI 선택**: 사용할 운영체제 이미지(예: Ubuntu)를 선택.
2. **인스턴스 유형 선택**: 필요한 CPU 및 메모리 사양을 결정.
3. **키 페어(Key Pair) 생성**: SSH 원격 접속을 위한 인증키를 다운로드.
4. **네트워크 및 보안 그룹 설정**: 외부 접속을 위해 포트(22, 80 등)를 개.
5. **스토리지 설정**: 데이터 저장소인 EBS의 용량을 지정.

### 3.2 원격 접속 및 서버 설정

* **SSH 접속**: `ssh -i "키페어경로" ubuntu@PublicIP` 명령을 통해 접속.
* **웹 서버(Apache) 설치**:

  * 패키지 업데이트: `sudo apt update`
  * 설치: `sudo apt install -y apache2`
  * 보안 그룹에서 80번 포트 개방 후 웹 브라우저 접속 확인
* **데이터베이스(MySQL) 설치 및 설정**:

  * 설치: `sudo apt install mysql-server`
  * 루트 계정 비밀번호 변경 및 `bind-address=0.0.0.0` 설정을 통해 외부 접속 허용 처리
  * 변경 사항 적용을 위해 `FLUSH PRIVILEGES` 명령 수행 및 서비스 재시작

#### `sudo apt update`

패키지 설치 전, 일종의 최신 정보를 업데이트하는 작업이라 보면 된다. `apt`는 컴퓨터에 설치된 프로그램과 설치 가능한 모든 프로그램 목록(인덱스)을 로컬에 저장 중. 이 목록이 오래되면 구버전 위치에서 찾으려고 하기 때문에, `update`를 선행하는 것이 옳다.

또한 리눅스 소프트웨어는 단독으로 실행되지 않고 다른 라이브러리들에 의존하는 경우가 많은데, 버전이 다른 경우 **의존성 오류(Dependency Error)**가 발생. 만약 의존성 오류가 발생했을 경우 버전을 먼저 확인해보는 것을 권한다 (너무 낮거나 너무 높으면 발생)

## 4. 비용 관련

* **AWS Billing**: 요금 예측 및 예산 초과 시 알림이 뜨도록 설정 가능.
* **프리 티어(Free Tier)**: 가입 후 ~~12개월간~~ 소규모 인스턴스(EC2, RDS 등)와 5GB의 S3 스토리지를 무료로 이용할 수 있음. → 6개월로 변경됨! 꼭 유의할 것.
* **AWS CLI**: 로컬 터미널에서 명령어나 스크립트로 AWS 서비스를 제어할 수 있는 도구다.
