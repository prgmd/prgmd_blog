## 1. AWS 데이터베이스 서비스 분류
AWS는 애플리케이션의 요구사항과 데이터 형태에 최적화된 전용 데이터베이스 서비스를 제공한다.

### 1) 주요 데이터 저장소 유형
* **관계형 (RDBMS)**: Amazon Aurora, RDS, Redshift. 전통적인 비즈니스 앱, ERP, CRM, 전자 상거래 시스템에 주로 사용된다.
* **키-값 (Key-Value)**: Amazon DynamoDB. 높은 트래픽을 처리해야 하는 웹 애플리케이션이나 게임 시스템에 적합하다.
* **인메모리 (In-Memory)**: Amazon ElastiCache, MemoryDB for Redis. 초고속 성능이 필요한 캐싱, 세션 관리, 실시간 순위표 등에 활용된다.
* **문서 (Document)**: Amazon DocumentDB (MongoDB 호환). 콘텐츠 관리나 사용자 프로필처럼 유연한 스키마가 필요한 작업에 용이하다.
* **와이드 컬럼 (Wide Column)**: Amazon Keyspaces. 대용량 데이터 분석 및 장비/플릿 관리 등 열 단위 저장 구조가 효율적인 곳에 사용된다.
* **그래프 (Graph)**: Amazon Neptune. 데이터 항목 간의 복잡한 관계를 저장하고 탐색하는 부정 탐지나 추천 엔진에 특화되어 있다.
* **시계열 (Time Series)**: 시간 흐름에 따른 데이터 변화를 저장하고 분석하는 모니터링 시스템 등에 사용된다.

## 2. Amazon S3 (Simple Storage Service)
S3는 인터넷 어디서나 데이터를 저장하고 검색할 수 있도록 설계된 객체 스토리지 서비스다.

### 1) 주요 특징 및 성능
* **객체 기반 저장**: 데이터를 키(Key)와 값(Value)의 쌍으로 저장한다. 객체 이름에 경로를 포함하여 논리적인 디렉토리 구조를 만들 수 있다.
* **무제한 확장성**: 전체 저장 용량과 객체 수에 제한이 없으며, 단일 객체는 최대 5TB까지 지원한다.
* **높은 신뢰성**: 99.999999999%(11 9s)의 데이터 내구성과 99.99%의 가용성을 제공하여 안전한 데이터 보관을 보장한다.
* **접근성**: 고유한 URL을 통해 객체에 접근할 수 있으며, 세밀한 접근 제어 및 권한 관리가 가능하다.

### 2) 비용 과금 체계
* 실제 사용한 저장 용량(GB)을 기준으로 비용이 발생한다.
* 데이터 전송량(특히 아웃바운드 트래픽)과 수신된 HTTP 요청(GET, PUT 등) 횟수가 과금 항목에 포함된다.

## 3. S3 버킷(Bucket) 생성 및 권한 설정
데이터를 저장하는 최상위 컨테이너인 버킷을 관리하기 위해서는 보안과 접근 권한 설정이 중요하다.

### 1) IAM 사용자 연동
* 외부 애플리케이션에서 S3를 사용하려면 전용 IAM 사용자를 생성해야 한다.
* 해당 사용자에게 S3 관련 정책(예: AmazonS3FullAccess)을 연결한 후, **액세스 키(Access Key)**와 **비밀 액세스 키(Secret Access Key)**를 발급받아 연동 정보로 활용한다.

### 2) 버킷 관리 및 보안
* **이름 고유성**: 버킷 이름은 모든 AWS 계정과 리전을 통틀어 전 세계에서 유일해야 한다.
* **권한 설정**: ACL(액세스 제어 목록) 활성화 여부와 퍼블릭 액세스 차단 설정을 통해 데이터 노출 범위를 결정한다.
* **버킷 정책**: JSON 형식의 정책 문서를 작성하여 특정 IP 대역이나 사용자에게만 접근을 허용하는 등 상세한 보안 규칙을 정의할 수 있다.
