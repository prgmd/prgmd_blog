## 1. 스위치(Switch)와 루프 예방
스위치는 2계층 주소인 MAC 주소를 기반으로 동작하며, 네트워크의 안정성을 위해 루프(Loop)를 관리하는 것이 중요하다.

### 1) 루프와 브로드캐스트 스톰
* **문제점**: 네트워크가 고리 형태로 연결되면 패킷이 무한히 회전하는 루프 현상이 발생한다. 2계층 패킷은 수명(TTL)이 없어 전체 네트워크의 통신을 마비시키는 '브로드캐스트 스톰'을 일으킨다.
* **STP(Spanning Tree Protocol)**: 루프를 감지하고 특정 포트를 차단 상태로 유지하여 논리적인 트리 구조를 만드는 메커니즘이다. BPDU라는 정보를 교환하여 네트워크 구조를 파악한다.

### 2) 스위치 관리
* 스위치는 기본적으로 IP가 없어도 통신 중재가 가능하지만, 관리자가 원격에서 장비를 설정하거나 모니터링하기 위해 IP 주소를 부여하기도 한다.

## 2. 3계층 장비: 라우터(Router)
라우터는 목적지 IP 주소를 확인하여 최적의 경로로 패킷을 전달(포워딩)하는 역할을 수행한다.

* **경로 지정**: 라우팅 테이블을 참조하여 패킷을 보낸다. 직접 연결된 경로 외에도 관리자가 입력한 '정적 라우팅'이나 라우터끼리 정보를 교환하는 '동적 라우팅'을 통해 경로 정보를 얻는다.
* **브로드캐스트 컨트롤**: 스위치와 달리 목적지가 불명확한 패킷을 무분별하게 뿌리지(플러딩) 않고, 명확한 경로 정보가 있을 때만 통신을 허용하여 전체 네트워크 효율을 높인다.
* **Next Hop**: 패킷을 목적지까지 한 번에 보내는 것이 아니라 인접한 다음 라우터로 넘겨주는 방식으로 동작한다. 이를 'Hop by Hop' 라우팅이라 한다.

## 3. 로드 밸런서(Load Balancer)와 세션 관리
서버의 부하를 분산하기 위해 4계층 이상에서 동작하는 장비다.

* **시스템 확장**: 성능을 높이기 위해 장비 자체를 업그레이드하는 **Scale Up** 방식과, 저렴한 장비 여러 대를 배치하여 부하를 나누는 **Scale Out** 방식이 있다.
* **L4/L7 로드 밸런싱**: 포트 번호를 기준으로 나누면 L4, HTTP 헤더나 URI 등 애플리케이션 정보를 확인하여 정교하게 나누면 L7(ADC)이라고 부른다.
* **세션 테이블**: 통신의 방향성과 순서를 관리하는 테이블을 유지하며, 인바운드와 아웃바운드 경로가 일치하는 대칭 경로가 중요하다.

## 4. 네트워크 주요 기술: NAT와 DNS
주소 부족 문제 해결과 사용자 편의성을 위한 핵심 기술들이다.

### 1) NAT/PAT (주소 변환)
* **목적**: 사설 IP를 공인 IP로 변환하여 주소 고갈 문제를 해결하고 내부 보안을 강화한다.
* **구분**: 출발지 주소를 바꾸면 **SNAT**(사설→공인), 목적지 주소를 바꾸면 **DNAT**(로드 밸런서 등에서 사용)라고 한다.
* **포트 포워딩**: 외부에서 내부의 특정 서비스로 접속할 수 있도록 특정 포트 요청을 내부 IP로 연결해주는 설정이다.

### 2) DNS (Domain Name System)
* **계층 구조**: 루트 도메인을 정점으로 하는 역트리 구조다. .com, .kr 같은 최상위 도메인(TLD) 하위에 여러 단계의 도메인이 존재한다.
* **주요 레코드**:
    - **A**: 도메인 이름을 IPv4 주소로 매핑한다.
    - **CNAME**: 도메인 이름에 대한 별칭(Alias)을 부여한다.
    - **SOA**: 해당 도메인 영역에 대한 관리 권한 정보를 담고 있다.
* **캐싱**: 성능 향상을 위해 이전에 질의한 결과를 일정 시간(TTL) 동안 보관하여 사용한다.

## 5. 우분투 네트워크 설정
우분투 리눅스에서는 `/etc/network/interfaces` 파일이나 최신 버전의 경우 netplan 설정을 통해 네트워크를 관리하며, `systemd-resolved` 서비스가 DNS 해석을 담당한다.
