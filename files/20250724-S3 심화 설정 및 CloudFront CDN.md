# IV. 인스턴스 스토리지
## 1. EBS (Elastic Block Store)
> EC2 인스턴스가 실행되는 동안 연결하여 사용할 수 있는 네트워크 드라이브. (물리적 드라이브가 아닌 가상화된 네트워크 스토리지다!) 인스턴스에서 분리하여 다른 인스턴스로 신속하게 재연결이 가능하고, 인스턴스 종료 후에도 데이터를 영구적으로 유지할 수 있다.

### 1-1. 주요 특징 및 제약 사항

| 항목 | 상세 내용 |
| --- | --- |
| **가용 영역(AZ) 제한** | 생성된 가용 영역 내의 인스턴스에만 마운트 가능함. |
| **데이터 이동성** | 스냅샷(Snapshot)을 생성하여 다른 가용 영역으로 볼륨 복제 및 이동 가능함. |
| **다중 연결(Multi-Attach)** | io1/io2 등 특정 볼륨 유형은 동일 AZ 내 여러 인스턴스에 동시 연결 가능함. |
| **인스턴스당 할당** | 하나의 인스턴스에 여러 개의 EBS 볼륨을 연결하여 사용 가능함. |
| **성능 변경** | 인스턴스 가동 중에도 용량 및 IOPS 성능을 동적으로 확장할 수 있음. |

### 1-2. 성능 및 비용 구조

* **프로비저닝 방식**이기 때문에, 사용자가 필요한 GB 용량과 IOPS(초당 입출력 작업 수)를 미리 지정해야 함.
* 실제 데이터 저장량과 관계없이 예약(Provision)된 자원 전체에 대해 요금이 발생하는 구조.
  * 다만 무료 티어(?) 느낌으로 매달 범용 SSD(gp2/gp3) 또는 마그네틱 유형으로 총 30GB의 스토리지 이용 가능하다.

### 1-3. 세부 운영 설정

#### 종료 시 삭제 (Delete on Termination)
* 인스턴스 종료(Terminate) 시 연결된 EBS 볼륨의 자동 삭제 여부를 결정하는 속성.
* 기본적으로 루트 볼륨은 활성화, 추가 데이터 볼륨은 비활성화 상태로 설정됨.

#### 절전 모드 (Hibernate) 연동 ([저번 게시글](https://prgmd-blog.vercel.app/#post/20250723-learning-aws-03)의 SAA 레벨에서의 EC2 활용 파트에서 배웠다)
* 인스턴스 절전 모드 사용 시 RAM의 데이터를 EBS에 저장해야 하므로 **루트 볼륨은 반드시 EBS**여야 함.
* **휘발성인 인스턴스 스토어(Instance Store)는 루트 볼륨으로 사용 시 절전 모드 지원 불가함.**
* RAM 데이터를 저장할 수 있도록 EBS 볼륨 내 충분한 여유 공간과 암호화 설정이 필수임.

#### 확인 방법

* EC2 콘솔 내 [스토리지] 탭의 [블록 디바이스] 메뉴에서 연결 상태 확인 가능함.
* USB 스틱처럼 **독립적인 객체**로 관리되므로 연결 없이 볼륨만 생성해 두는 것도 가능함.

### 1-4. EBS 스냅샷 (EBS Snapshots)
> EBS 볼륨의 특정 시점 상태를 보존하는 백업 데이터. 

#### 특징
* 데이터 무결성을 보장하기 위해 스냅샷 생성 전 인스턴스에서 볼륨을 분리하는 것이 권장됨. (필수 사항은 아님)
* 스냅샷은 다른 가용 영역(AZ)이나 타 리전으로 복사가 가능함. 특정 가용 영역에 종속된 EBS 볼륨을 타 지역으로 옮기기 위한 핵심 수단.
* 스냅샷을 기반으로 다른 가용 영역에 새로운 EBS 볼륨을 복원 및 생성할 수 있음.
* Amazon Data Lifecycle Manager(DLM) 등을 통해 주기적인 스냅샷 생성이 가능하다. (백업 자동화 기능)
* **변경된 데이터 블록만 저장하여 저장 공간을 효율적으로 사용이 가능**하다.

#### 주요 기능 및 관리 도구

| 기능명 | 주요 특징 및 설명 | 비고 |
| --- | --- | --- |
| **EBS 스냅샷 아카이브** | 비용을 최대 75%까지 절감할 수 있는 저렴한 스토리지 계층임. | 복원에 24~72시간 소요되어 즉시 복원 불가함. |
| **EBS 스냅샷 휴지통** | 삭제된 스냅샷을 영구 삭제 전 보관하는 기능임. | 보관 기간은 1일에서 최대 1년까지 설정 가능함. |
| **빠른 스냅샷 복원(FSR)** | 스냅샷에서 볼륨 생성 시 첫 사용 지연 시간(Latency)을 제거함. | 대용량 볼륨의 즉각적인 성능 확보에 유리하나 비용이 높음. |

## 2. AMI (Amazon Machine Image)
> EC2 인스턴스의 운영체제(OS), 소프트웨어, 구성 설정 등을 포함한 시스템 이미지.

### 2-1. 특징
* 인스턴스 생성 시 필요한 모든 설정이 미리 패키징되어 있어 부팅 및 초기 구성 시간을 단축할 수 있다.
  * 이뜻인즉슨 사용자 커스텀 템플릿 생성도 가능하다는 뜻.
* 특정 리전에서 구축한 AMI를 다른 리전으로 복사하여 전역적인 서비스 배포에 활용 가능함.

### 2-2. AMI 생성 및 활용 프로세스

1. 특정 용도에 맞춰 EC2 인스턴스 내 소프트웨어 설치 및 환경 설정을 완료.
2. 이미지 생성 전 인스턴스를 중지(Stop)해 파일 시스템의 일관성을 유지. (무결성)
3. `이미지 생성(Create Image)` 명령을 실행. 이 과정에서 연결된 EBS 볼륨의 **스냅샷이 자동으로 생성**된다.
4. 생성된 이미지는 EC2 콘솔의 [이미지] -> [AMI] 메뉴에서 확인 가능.
5. 생성된 AMI를 선택하여 동일한 환경의 인스턴스를 즉시 복제 및 생성.

### 2-3. AMI 소스 분류 및 관리

| 분류 | 특징 | 관리 주체 |
| --- | --- | --- |
| **AWS 공식 AMI** | Amazon Linux 2023, Windows Server 등 표준 OS 제공 | AWS |
| **사용자 지정 AMI** | 사용자가 직접 인스턴스를 구성하고 이미지화한 형태 | 사용자 (자체 유지보수 필요) |
| **AWS 마켓플레이스** | 기업용 소프트웨어가 사전 설치된 유/무료 이미지 구매 가능 | 소프트웨어 판매 기업(Vendor) |
| **커뮤니티 AMI** | 다른 사용자가 생성하여 공유한 이미지 | 커뮤니티 개발자 |

### 2-4. 주요 활용 예시

* **애플리케이션 골든 이미지**: 필요한 모든 도구가 설치된 표준 이미지를 만들어 팀 전체에서 공유함.
  * 골든 이미지는 [가상화](https://prgmd-blog.vercel.app/#post/20250613-learning-docker-01)에서 등장한 개념. 
* **오토 스케일링**: 트래픽 증가 시 동일한 설정의 인스턴스를 자동으로 확장하기 위한 기반 템플릿으로 사용함.
* **재해 복구**: 특정 시점의 인스턴스 상태를 보존하여 장애 발생 시 빠른 복구를 수행함.

## 3. EC2 인스턴스 스토어 (EC2 Instance Store)

### 3-1. 개념 및 성능

* EC2 인스턴스가 실행되는 물리적 서버에 하드웨어적으로 직접 연결된 디스크임.
* 네트워크를 거치는 EBS와 달리 물리적으로 부착되어 있어 데이터 입출력(I/O) 속도가 매우 빠름.
* 초당 입출력 작업 수(IOPS)가 EBS 대비 압도적으로 높음 (예: i3 인스턴스의 경우 수백만 단위의 IOPS 제공).
* **비유**: EBS가 '네트워크로 연결된 외장 하드'라면, 인스턴스 스토어는 컴퓨터 본체에 직접 꽂힌 '내장 초고속 SSD'와 같음.

### 3-2. 휘발성 및 데이터 보호

* 인스턴스를 **중지(Stop)**하거나 **종료(Terminate)**하면 저장된 데이터가 영구적으로 삭제됨.
* 하드웨어 장애 발생 시에도 데이터 복구가 불가능한 '임시 스토리지' 성격을 가짐.
* 장기 보관이 필요한 데이터에는 부적합하며 버퍼, 캐시, 스크래치 데이터 등 임시 데이터 처리용으로 사용됨.
* 중요한 데이터는 반드시 EBS나 S3에 백업 또는 복제해 두어야 함.

### 3-3. EBS 볼륨 유형 상세 비교

EBS 볼륨은 성능과 가격에 따라 크게 SSD와 HDD 계열로 구분됨. 모든 칸을 채운 상세 비교는 다음과 같음.

| 볼륨 제품군 | 유형 | 주요 특징 | 주요 용도 | 부팅 여부 |
| --- | --- | --- | --- | --- |
| **범용 SSD** | **gp2/gp3** | 가격과 성능의 균형이 우수함. gp3는 성능과 용량 독립 설정 가능함. | 시스템 부팅, 개발/테스트 환경 | **가능** |
| **고성능 SSD** | **io1/io2** | 가장 높은 성능(PIOPS) 제공. 다중 연결(Multi-Attach) 지원함. | 대규모 DB, 미션 크리티컬 앱 | **가능** |
| **처리량 HDD** | **st1** | 저비용 대용량. 처리량(Throughput) 중심의 작업에 최적임. | 빅데이터, 로그 처리, DW | **불가능** |
| **콜드 HDD** | **sc1** | 가장 저렴한 비용. 액세스 빈도가 낮은 데이터에 적합함. | 백업, 아카이빙용 데이터 보관 | **불가능** |

* **비유**: gp는 '일반 사무용 노트북 SSD', io는 '기업용 고성능 서버 디스크', st/sc는 '영화 저장용 대용량 외장 하드'로 이해할 수 있음.

### 3-4. EBS 볼륨 다중 연결 (Multi-Attach)

* **io 제품군(io1, io2)**에서만 지원하는 특수 기능임.
* 동일한 가용 영역(AZ) 내에 있는 최대 16개의 인스턴스에 하나의 EBS 볼륨을 동시에 마운트할 수 있음.
* 모든 연결된 인스턴스는 해당 볼륨에 대해 읽기 및 쓰기 권한을 동시에 가짐.
* 동시 쓰기 작업을 관리하기 위해 반드시 '클러스터 인식 파일 시스템'(예: GFS2, OCFS2)을 사용해야 함.
* **비유**: 하나의 USB 메모리를 허브를 통해 여러 대의 컴퓨터에 동시에 꽂아 공유 드라이브처럼 쓰는 것과 같음.

### 3-5. EBS 볼륨 암호화

* EBS 볼륨 생성 시 암호화 옵션을 선택하여 데이터 보안을 강화할 수 있음.
* **범위**: 볼륨 내 저장 데이터(At-rest), 인스턴스와 볼륨 간 전송 데이터(In-transit), 해당 볼륨으로 만든 스냅샷 모두 암호화됨.
* **성능**: AWS KMS(Key Management Service)와 AES-256 표준을 사용하며, 지연 시간에 미치는 영향은 거의 없음.
* **운영**: 암호화 설정은 볼륨 및 스냅샷 생성 단계에서 자동으로 처리되므로 별도의 복잡한 절차가 필요 없음.

## 4. EFS (Elastic File System)

### 4-1. 정의 및 주요 특징

* 관리형 NFS(네트워크 파일 시스템)로, 여러 EC2 인스턴스에서 동시에 마운트하여 데이터를 공유할 수 있는 스토리지임.
* **다중 가용 영역(Multi-AZ)** 지원으로 높은 가용성과 내구성을 가지며 재해 복구에 유리함.
* 비용 절감을 위해 단일 가용 영역만 사용하는 **One Zone** 옵션 선택이 가능하며, 이는 백업 기능과 저빈도 액세스 계층을 지원함.
* 보안 그룹(Security Group)을 통해 접근 제어를 수행하며, **Linux 기반 AMI**에서만 호환됨(Windows 미지원).
* 저장 용량을 미리 예약할 필요 없이 사용량에 따라 자동으로 확장 및 축소되는 **종량제** 과금 방식임.

### 4-2. 성능 및 처리량 모드

| 구분 | 종류 | 세부 특징 및 용도 |
| --- | --- | --- |
| **성능 모드** | **범용 (General Purpose)** | 지연 시간에 민감한 웹 서버, CMS 등 일반적인 워크로드에 사용됨. |
| **성능 모드** | **최대 I/O (Max I/O)** | 높은 처리량과 병렬성이 필요한 빅데이터, 미디어 처리 작업에 적합함. |
| **처리량 모드** | **버스팅 (Bursting)** | 파일 시스템 크기에 비례하여 처리량이 결정되는 기본 방식임. |
| **처리량 모드** | **프로비저닝 (Provisioned)** | 스토리지 용량과 관계없이 필요한 처리량을 직접 설정하여 사용함. |

### 4-3. 스토리지 클래스 및 효율화

* **스탠다드(Standard)**: 자주 액세스하는 파일을 저장하는 기본 계층임.
* **EFS-IA (Infrequent Access)**: 자주 사용하지 않는 파일을 저장하며, 저장 비용은 저렴하나 데이터 검색 시 비용이 발생함.
* **아카이브(Archive)**: 1년에 몇 번만 접근하는 거의 사용하지 않는 데이터 보관용으로 최적화됨.
* **수명 주기 정책(Lifecycle Management)**: 설정한 기간(예: 60일) 동안 접근이 없는 파일을 하위 계층으로 자동 이동시켜 최대 90%의 비용 절감이 가능함.

### 4-4. EBS와 EFS 비교 분석

| 비교 항목 | EBS (Elastic Block Store) | EFS (Elastic File System) |
| --- | --- | --- |
| **접속 방식** | 특정 인스턴스에 직접 연결 (1:1 권장) | 네트워크를 통한 동시 다수 연결 (N:N) |
| **가용 영역** | 특정 가용 영역(AZ)에 국한됨 | 여러 가용 영역에 걸쳐 사용 가능함 |
| **확장성** | 용량 및 성능을 수동으로 변경해야 함 | 사용량에 따라 자동으로 용량 확장됨 |
| **지원 OS** | Linux, Windows 모두 지원함 | Linux 계열 OS만 지원함 |
| **비용 효율** | 범용 SSD 기준 EFS보다 저렴함 | 다소 비싸나 다중 연결 및 자동 확장이 용이함 |

### 4-5. 요약 및 주의 사항

* 데이터 공유가 빈번한 웹 서버 클러스터나 콘텐츠 관리 시스템(CMS)에 적합함.
* 암호화는 AWS KMS를 사용하여 미사용 데이터 및 전송 중 데이터를 보호할 수 있음.
* 표준 파일 시스템 API(POSIX)를 지원하여 기존 애플리케이션의 호환성을 유지함.

## 5. 총정리

### 1. AWS 주요 스토리지 서비스 비교 요약

| 구분 | EBS (Elastic Block Store) | 인스턴스 스토어 (Instance Store) | EFS (Elastic File System) |
| --- | --- | --- | --- |
| **정의** | 가상 네트워크 블록 스토리지임 | 물리적 서버 전용 로컬 디스크임 | 관리형 네트워크 파일 시스템임 |
| **연결 방식** | 네트워크 드라이브 (1:1 또는 소수 다중) | 물리적 서버 직접 부착 (1:1) | 네트워크 공유 (NFS, 수천 개 연결) |
| **가용 범위** | 특정 가용 영역(AZ)에 한정됨 | 특정 물리 하드웨어에 한정됨 | 리전 내 여러 가용 영역(Multi-AZ) |
| **데이터 영속성** | 인스턴스 종료 후에도 유지 가능함 | 인스턴스 중지/종료 시 삭제됨 | 인스턴스 종료와 관계없이 유지됨 |
| **성능 특징** | 프로비저닝된 성능(IOPS) 제공 가능함 | 초고성능, 매우 낮은 지연 시간임 | 대규모 병렬 처리 및 자동 확장됨 |
| **지원 OS** | Linux 및 Windows 모두 지원함 | Linux 및 Windows 모두 지원함 | Linux 기반 운영체제만 지원함 |
| **부팅 지원** | 루트 볼륨으로 사용 가능함 | 일부 인스턴스 유형에서 지원함 | 부팅 볼륨으로 사용 불가능함 |

### 2. EBS 볼륨 유형별 상세 비교

| 볼륨 제품군 | 유형 | 성능 특징 | 주요 워크로드 | 부팅 가능 여부 |
| --- | --- | --- | --- | --- |
| **범용 SSD** | **gp2 / gp3** | 성능과 가격의 균형이 우수함 | 웹 서버, 개발 환경, 부팅 볼륨 | **지원함** |
| **고성능 SSD** | **io1 / io2** | 초고성능, 다중 연결(Multi-Attach) | 대규모 데이터베이스 (NoSQL, SQL) | **지원함** |
| **처리량 HDD** | **st1** | 높은 처리량(Throughput) 중심임 | 빅데이터, 로그 처리, DW | **지원하지 않음** |
| **콜드 HDD** | **sc1** | 최저 비용 스토리지임 | 백업, 아카이브, 접근 빈도 낮은 데이터 | **지원하지 않음** |


### 3. EBS 및 EFS 추가 기능 요약

| 기능 구분 | 주요 내용 | 기대 효과 |
| --- | --- | --- |
| **EBS 스냅샷** | 특정 시점의 증분 백업을 수행함 | 데이터 복구 및 리전 간 이동 가능함 |
| **AMI** | OS 및 소프트웨어 설정을 포함한 이미지임 | 인스턴스 복제 및 오토 스케일링에 활용됨 |
| **EFS IA / Archive** | 자주 액세스하지 않는 데이터용 계층임 | 수명 주기 정책을 통한 비용 절감됨 |
| **EBS 암호화** | KMS를 사용한 AES-256 암호화 지원함 | 데이터 보안 및 규정 준수 강화됨 |
