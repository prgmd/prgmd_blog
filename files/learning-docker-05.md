## 1. 컨테이너 실행 구조와 수동 제어
도커 컨테이너는 읽기 전용 이미지 레이어 위에 읽고 쓰기가 가능한 컨테이너 레이어를 추가하여 생성된다.

### 1) 컨테이너 실행 과정
* **자동 실행**: `docker run` 명령은 이미지 다운로드(pull), 컨테이너 생성(create), 시작(start) 과정을 한 번에 수행한다.
* **수동 제어 단계**:
  1. `docker image pull`: 필요한 이미지 다운로드
  2. `docker create`: 이미지를 바탕으로 컨테이너 레이어 생성 (정지 상태)
  3. `docker start`: 생성된 컨테이너를 프로세스로 실행

### 2) 실행 중인 컨테이너 확인 및 조작
* **목록 확인**: `docker ps` 명령으로 실행 중인 컨테이너의 상태를 확인한다.
* **명령 수행**: `docker exec -it [컨테이너명] /bin/bash`를 통해 실행 중인 컨테이너 내부 셸에 접속하여 실시간 조작이 가능하다.

## 2. 도커 볼륨 (Docker Volumes)
컨테이너가 삭제되어도 데이터를 보존하기 위해 도커 엔진이 관리하는 별도의 저장 공간을 사용한다.

### 1) 특징
* 도커가 직접 관리하며 호스트의 특정 영역에 저장된다.
* 여러 컨테이너가 하나의 볼륨을 공유하여 데이터를 주고받을 수 있다.
* 컨테이너 제거 시에도 볼륨을 명시적으로 삭제하지 않으면 데이터는 유지된다.

### 2) 주요 명령어
* **볼륨 생성**: `docker volume create [볼륨명]`
* **볼륨 마운트**: `docker run -v [볼륨명]:[컨테이너내부경로] [이미지명]`
* **볼륨 삭제**: `docker volume rm [볼륨명]` (단, 연결된 컨테이너가 없어야 함)

## 3. 바인드 마운트 (Bind Mounts)
호스트 시스템의 특정 파일이나 디렉토리를 컨테이너 내부 경로와 직접 매핑하는 방식이다.

### 1) 특징
* 호스트의 절대 경로를 그대로 사용하며, 사용자가 직접 파일 시스템을 관리할 수 있다.
* 설정 파일이나 소스 코드를 호스트에서 수정하고 컨테이너에 즉시 반영할 때 유용하다.
* 지정한 호스트 디렉토리가 존재하지 않으면 자동으로 생성된다.

### 2) 실습 예시: 웹 서버 콘텐츠 교체
* 아파치 웹 서버(`httpd`)의 기본 문서 경로를 호스트의 특정 폴더와 바인드 마운트하여 외부에서 웹 페이지 내용을 실시간으로 변경할 수 있다.
