# I. Dockerfile
## 1. 코드형 인프라 (IaC: Infrastructure as Code)
수동 프로세스가 아닌 **코드를 통해 인프라를 구축, 관리, 프로비저닝하는 방식**. 편집과 배포가 쉽고, 매번 동일 환경을 보장하는 프로비저닝이 가능하다.

### 1.1 특징
- **멱등성**: 가장 중요한 핵심. 동일 코드를 100번 실행해도 항상 동일 상태를 유지해야 한다.
- **불변성**: 구성 사양을 **코드화하고 문서화하여 임시 변경을 방지**함.

### 1.2 **주요 도구**
#### Terraform
> 주로 **클라우드(AWS, Azure, GCP 등)의 자원을 생성하는 데 특화**된 도구. **선언적** 방식을 통해 **사용자가 원하는 상태를 설정하면 알아서 채워 만들어준다. **

- 대개 VPC, EC2, S3 같은 인프라 뼈대를 잡을 때 사용하는 편인데, 빈 땅에 아파트 단지를 설계하고, 건물(서버, 네트워크)을 세우는 소장님 포지션이라 보면 된다.
- 배포된 인프라 상태를 `.tfstate` 파일에 기록해 관리한다. 이 파일 덕분에 '현재 코드와의 차이'를 계산하는 것.
- 특정 제조사에 종속되지 않고 여러 클라우드 서비스를 '하나의 문법'으로 제어가 가능하다.

#### Ansible
> **이미 만들어진 서버에 접속해 소프트웨어를 설치하고 설정하는 데 특화**된 도구. **Agentless** 개념이 중요하다. 대상 서버에 별도 프로그램을 깔 필요가 없고, SSH(리눅스 접속 방식)만 열려 있으면 내 컴퓨터에서 원격 조종이 가능.

- YAML 형식을 사용해 무슨 작업을 할지 순서대로 적어둔 시나리오인 '**플레이북(Playbook)**'을 사용한다. 그 덕에 사람이 읽기 쉬운 편.
- **이미 패키지가 설치되어 있으면 다시 실행했을 때 중복 설치를 하지 않고 넘어간다!** 되게 중요한 요소. 이 덕분에 멱등성이 보장된다.

## 2. 도커파일 (Dockerfile)
도커도 IaC가 가능한 대표적인 프로그램이다. Dockerfile이란 **도커 이미지를 생성하기 위한 스크립트 파일**로, 적힌 명령문을 차례대로 수행하며 사용자 정의 이미지를 빌드한다.

### 2.1 주요 명령어
* **FROM**: 기반이 될 베이스 이미지 지정.
* **LABEL**: 이미지에 메타데이터(버전, 작성자 등)를 추가.
* **RUN**: 이미지 빌드 과정에서 실행할 명령어 기술. (패키지 설치 등)
* **COPY / ADD**: 호스트 파일을 이미지 내부로 복사. ADD는 URL 사용이나 압축 해제 기능이 추가되어 있음.
* **WORKDIR**: 명령어가 실행될 작업 디렉토리 설정.
* **EXPOSE**: 컨테이너가 개방할 포트 지정.
* **CMD**: 컨테이너가 시작될 때 실행할 기본 명령 설정. (하나만 유효)

``` Dockerfile
# 1. FROM: 기초 공사 (어떤 OS/환경에서 시작할 것인가?)
# 도커 허브에서 제공하는 가벼운 리눅스(alpine) 기반의 Node.js 18 버전을 베이스로 사용합니다.
FROM node:18-alpine

# 2. LABEL: 이름표 붙이기 (이 이미지의 주인은 누구인가?)
# 이미지의 버전이나 작성자 정보를 메타데이터로 남긴다.
LABEL maintainer="prgmd@example.com"
LABEL version="1.0"
LABEL description="My First Node.js Web Server"

# 3. WORKDIR: 작업실 정하기 (어디서 일할 것인가?)
# 이후 실행되는 모든 명령어(RUN, COPY 등)는 이 디렉토리를 기준으로 동작. (없으면 생성함)
WORKDIR /app

# 4. COPY: 재료 가져오기 (내 컴퓨터의 파일을 로봇 안으로!)
# 호스트(내 컴퓨터)에 있는 package.json 파일을 이미지 내부의 현재 경로(.)로 복사합니다.
COPY package.json .

# 5. RUN: 조립하기 (빌드 과정에서 실행할 작업)
# 이미지를 만드는 과정에서 필요한 패키지를 설치합니다. (캐싱 효율을 위해 소스 복사 전 실행)
RUN npm install

# 6. ADD: 특수 재료 가져오기 (URL이나 압축파일 등)
# 단순 복사는 COPY를 쓰지만, 원격 URL의 파일을 가져오거나 압축을 풀며 복사할 때 ADD를 씁니다.
ADD https://example.com/config.tar.gz ./config/

# 7. 소스 코드 복사
# 나머지 모든 소스 코드를 현재 작업 디렉토리(/app)로 복사합니다.
COPY . .

# 8. EXPOSE: 문 열어두기 (몇 번 포트로 대화할 것인가?)
# 컨테이너가 8080번 포트를 사용할 것임을 명시합니다. (실제 연결은 run 시 -p 옵션으로 함)
EXPOSE 8080

# 9. CMD: 시작 버튼 (컨테이너가 켜지자마자 할 일)
# 이미지가 컨테이너로 실행될 때 딱 한 번 실행되는 기본 명령어입니다.
CMD ["npm", "start"]
```

#### 경로 기호 간략 설명
- `/` 루트 디렉토리: 파일 시스템의 최상위 지점. 윈도우의 `C:\`와 같다. 
  - `WORKDIR /app`의 경우 컨테이너 최상위에 `app` 폴더를 만들고 거기로 이동하라는 뜻.
- `.` 현재 디렉토리: 지금 내가 있는 곳을 의미.
  - `COPY . .`는 뭔가요? → 현재 내 컴퓨터(호스트) 지금 폴더에 있는 모든 파일을 + 컨테이너 내부 작업 디렉토리(`WORKDIR`에서 설정)에 복사하라는 뜻.
- `~` 홈 디렉토리: 현재 접속 중인 **사용자의 개인 폴더.**
  - 보통 루트 사용자는 `/root`로 설정되어 있고 일반 사용자는 `/home/유저명`을 가리킨다.

## 2.2 Dockerfile의 특징
### 1) 레이어 캐싱
도커 이미지는 명령문 한 줄 당 하나의 레이어를 만드는데, 도커는 빌드시 '줄이 바뀌었나?' 체크해보고 안 바뀌었으면 만든 걸 재사용(캐시).
- 근데 만약 3번째 줄을 바꿔야 하는 상황이 오면 그 아래에 딸려오는 4번째 줄부터는 내용이 그대로여도 **전부 새로 빌드하는 습성이 있다!**
- 즉, **자주 안 바뀌는 `RUN apt-get install` 같은 명령문은 맨 위에, 매번 바뀌는 소스 코드인 `COPY . .` 같은 명령문은 가장 아래에 넣는게 핵심**이다.

### 2) 멀티 스테이지 빌드
프로그램 빌드시 필요한 도구와, 실행할 때 필요한 도구는 또 다름. (자바를 예로 들자면 빌드에는 JDK가 필요하지만 실행은 JRE만 있으면 되는 것처럼)
- 일단 빌드 도구를 전부 넣으면 이미지 용량은 GB 단위가 된다.
- 그래서 나온 해결책이 멀티 스테이지 빌드. 무거운 이미지를 가져와 코드를 빌드한 뒤 결과물(실행 파일)만 추출 → 그 다음 아주 작고 가벼운 다이어트 이미지를 새로 가져옴 → 여기에 결과물을 넣고 컨테이너를 가동.
  - 이렇게 하면 800MB 이미지를 50MB로 줄이는 등 엄청난 효과를 볼 수 있음.

### 3) `.dockerignore`
컴퓨터(호스트) 폴더에 있는 모든 파일을 컨테이너로 보낼 때(`COPY`) 필요 없는(혹은 보안상 섞이면 안되는) 파일을 제외하는 방식. 이건 `.gitignore`와 비슷하다.

### 4) 변수 설정
| 구분 | **ARG (Build Argument)** | **ENV (Environment Variable)** |
| :--- | :--- | :--- |
| **유통기한** | **빌드할 때만** 반짝 사용됨 | **실행 중(컨테이너 안)에도** 유지됨 |
| **비유** | 레시피를 적을 때 쓰는 **메모** | 완성된 요리에 뿌려진 **설탕** |
| **용도** | 버전 정보 지정, 빌드 옵션 | DB 비밀번호, API 키, 서버 포트 설정 |

### 5) 명령어 설정
> 보통 고정된 실행 파일을 `ENTRYPOINT`로 쓰고, 그 뒤 옵션값을 `CMD`에 둬 사용자가 바꿀 수 있도록 조합하는 편.

- `CMD`: "이걸 기본으로 실행해줘. 근데 사용자가 밖에서 다른 명령을 주면 그걸로 바꿔줄게."
- `ENTRYPOINT`: "나는 무조건 이거 실행해! 밖에서 명령을 줘도 내 뒤에 인자로만 붙여줄게."
