## 1. EC2 (Elastic Compute Cloud)

* AWS에서 제공하는 '서비스형 인프라스트럭처(IaaS)'.
* 가상 머신 렌탈, 데이터 저장(EBS), 부하 분산(ELB), 자동 확장(ASG) 등을 포함하는 거대한 개념.
  - 내 컴퓨터를 직접 사는 대신, 필요할 때마다 고사양 컴퓨터를 빌려 쓰고 빌린 시간만큼만 돈을 내는 '클라우드 PC방'과 같다.

### 1.1 EC2의 구성 옵션

* OS(리눅스, 윈도우, 맥 등), 컴퓨팅 성능(CPU), RAM, 용량, 네트워크 카드, 보안 그룹 등.
* 저장 방식 (EBS, EFS, 하드웨어에 저장)

#### 부트스트랩 스크립트
일종의 사용자 커스텀 데이터로, 인스턴스가 처음 부팅될 때 실행되는 명령어 집합. 인스턴스가 생성되자마자 "업데이트를 하고, 웹 서버 프로그램을 깔아라"라고 명령을 미리 적어두는 '자동 설치 매뉴얼'이다.

![](https://velog.velcdn.com/images/paramad/post/1c31e5b2-0b1a-40b2-9951-8884b200d3c1/image.png)


### 1.2 EC2 유저 데이터

* 부팅 작업을 자동화하며, 인스턴스 수명주기 중 **단 한 번** 실행됨.
* 루트 계정(sudo) 권한으로 실행되므로 모든 명령어를 관리자 권한으로 처리함.

### 1.3 EC2 인스턴스 생성 및 키 페어

* **키 페어(Key Pair)**: 인스턴스 로그인용 보안 파일. RSA 암호화 사용. **키 파일(`.pem` 등)은 한 번 다운로드하면 다시 받을 수 없다**. 잃어버리면 인스턴스에 접속할 수 없으므로 절대 분실 금지.
* **스토리지**: `Delete on termination` 체크 시 인스턴스 삭제와 동시에 저장 장치도 삭제됨.

### 1-4. IPv4와 과금 정책

* **공용 IP**: 외부에서 접근하는 주소. 인스턴스를 재시작하면 주소가 바뀜.
* **IPv4 과금**: 2024년 2월부터 사용 여부와 관계없이 모든 공용 IPv4에 요금 부과.
  - 과거에는 무료였으나, 이제는 켜두기만 해도 한 달에 약 3.6달러 정도가 청구되므로 **사용하지 않는 인스턴스는 반드시 종료해야 한다**.

## 2. EC2 인스턴스 유형
![](https://velog.velcdn.com/images/paramad/post/ecc0febb-3cf0-4b5b-b0f7-24d66247a197/image.png)

**네이밍 규칙**: `m5.2xlarge` (m: 타입/성격, 5: 세대, 2xlarge: 크기)

![](https://velog.velcdn.com/images/paramad/post/aca962cc-3cdd-4818-ad78-eea9054b5cf6/image.png)
(AI에 돌려보니 다음과 같은 사진을 만들어줬다. 귀엽다..)

### 2-1. 범용 (General Purpose)
- 성능, 메모리, 네트워킹의 균형이 좋음. 웹 서버나 코드 저장소에 적합.
- 어떤 작업이든 무난하게 수행하는 '균형 잡힌 캐릭터(올라운더)'.

### 2-2. 컴퓨팅 최적화 (Compute Optimized)
- 고성능 프로세서가 필요한 데이터 처리, 게임 서버, 머신 러닝에 적합. (C로 시작)
- 힘(CPU)이 좋은 전사 캐릭터. 계산 능력이 필요한 작업에 특화됨.

### 2-3. 메모리 최적화 (Memory Optimized)
- 대규모 데이터셋 처리를 위한 고성능 데이터베이스 등에 적합. (R로 시작)
- 기억력(RAM)이 매우 좋은 '지능형 캐릭터'. 많은 데이터를 머릿속에 띄워두고 작업할 때 유리함.

### 2-4. 스토리지 최적화 (Storage Optimized)
- 로컬 저장소의 데이터 읽기/쓰기 속도가 매우 중요한 작업에 적합. (I, D, H1 시작)
  - NoSQL 데이터베이스에 주로 사용. 특히 Redis (캐시, 데이터 웨어하우징, 분산 파일 시스템...)
- 가방(용량)이 크고 물건을 꺼내는 속도(I/O)가 매우 빠른 '보부상 캐릭터'.

## 3. 보안 그룹 (Security Groups)

![](https://velog.velcdn.com/images/paramad/post/03f707ab-925f-46d7-a157-cde08ac04c68/image.png)

> EC2 인스턴스 앞단에서 트래픽을 제어하는 가상 방화벽.

### 3-1. 주요 특징 및 관리

- 설정 기준: IP 주소(컴퓨터의 출발지)를 기준으로 트래픽 허용 규칙을 설정하고, 특정 IP 주소나 IP 대역을 '화이트리스트'에 등록하여 접근을 허용하는 방식이다.
- **다른 보안 그룹 자체를 참조하여 규칙을 설정할 수 있다!** "A 보안 그룹을 가진 인스턴스들만 B 보안 그룹의 특정 포트로 들어올 수 있다"는 식의 유연한 설정이 가능.
- 하나의 EC2 인스턴스에 **여러 개의 보안 그룹을 동시에 적용할 수 있음**.
- 보안 그룹은 **특정 리전(Region)과 VPC(가상 네트워크) 조합 내에서만 유효**함. 만약 다른 리전으로 인스턴스를 옮기거나 생성할 경우, 해당 리전에 맞는 새로운 보안 그룹을 다시 만들어야 함.
- 외부에서 서버로 들어오는 트래픽은 **인바운드(Inbound)**, 서버에서 외부로 나가는 트래픽은 **아웃바운드(Outbound)**라고 정의함.
- 보안 그룹은 **EC2 인스턴스 외부에서 작동하는 가상 방화벽**임.
  - 서버 내부까지 트래픽이 도달하기 전에 입구에서 차단하므로 보안 효율이 높다.
  - 주로 관리자용 SSH(22번 포트)는 본인의 IP에서만 접근 가능하도록 설정하고 나머지는 차단하는 편. (개발 동안에는 0.0.0.0으로 잠깐 풀어두기도)
- 어쨌든, 원격 접속을 위한 SSH 전용 보안 그룹을 별도로 생성하여 관리하는 것이 안전함.

### 3-2. 자주 쓰는 포트

| Port | Protocol | Description |
|------|----------|-------------|
| 22   | SSH      | 인스턴스 로그인 |
| 21   | FTP      | 파일 업로드 및 공유 |
| 22   | SFTP     | SSH 사용해 파일 업로드 |
| 80   | HTTP     | 웹사이트 접근 |
| 443  | HTTPS    | 보안 추가한 HTTP |
| 3389 | RDP(Remote Desktop Protocol)  | 윈도우 서버 원격 접속(윈도우 인스턴스 로그인) |

### 3-3. SSH

| OS / Method | SSH | PuTTY | 직접 접속 |
|-------------|-----|--------|----------------------|
| mac         | ✔️  |        | ✔️                   |
| linux       | ✔️  |        | ✔️                   |
| windows < 10|     | ✔️     | ✔️                   |
| windows ≥ 10| ✔️  | ✔️     | ✔️                   |

- SSH : 명령줄로 원격 머신을 제어할 수 있게 해주는 것
- PuTTY : 온라인에 있는 무료 툴. 윈도우 환경에서 사용
- 직접 접속(EC2 Instance Connect)은 Amazon Linux2에서만 작동

#### EC2 Instance Connect 주의

직접 들어가서 `aws configure`로 개인 정보 입력해두고 사용할 수는 있지만, 이 경우 계정 상 누구라도 접속해서 자격 증명 정보를 볼 수 있다는 사실을 기억할 것. 

대신 인스턴스에 IAM 역할을 지정하는 걸 권함. 이렇게 되면 `aws configure`를 하지 않아도 자동으로 인증을 해준다.

## 4. 인스턴스 구매 옵션

![](https://velog.velcdn.com/images/paramad/post/10010fc9-8ec6-4dcc-ab04-f0ac305f7fc5/image.png)

> 예산과 업무의 성격에 따라 가장 효율적인 구매 방식을 선택해야 한다. 온디맨드, 예약 인스턴스, 절약 플랜, 스팟 인스턴스, 전용 호스트, 용량 예약 등이 있다. 

### 4-1. 온디맨드 (On-Demand)
- 사용 기간 약정 없이 쓴 만큼만 지불. 비용이 가장 비쌈.
- 필요할 때마다 빌리는 '일반 렌터카'. 언제든 반납 가능하지만 일일 대여료는 비싸다.

### 4-2. 예약 인스턴스 (Reserved Instances) 및 절약 플랜 (Savings Plans)
> '오래 쓸 건데 할인 해줘'

- 1년 또는 3년 약정 시 큰 할인(최대 70% 이상) 제공.
- 오래 쓸 상황이 확실할 때 가장 저렴하다. ex) 오랫동안 DB를 실행할 경우
- 마켓 플레이스에서 구매가 가능하며 필요가 없어지면 팔 수도 있음.

#### 1) 전환형 예약 인스턴스 (Convertible Reserved)
- 인스턴스 타입을 변경할 수 있음.
- 대신 할인율은 좀 떨어짐.

#### 2) 절약 플랜 (Saving Plans)
> '미리 돈 줄테니 싸게 해줘'

- 기간은 1년 또는 3년 약정. 대신 미리 돈을 지불함.
- 사용량이 한도를 넘어설 경우 온디맨드 가격으로 청구
- 특정 인스턴스, 패밀리, 리전으로 고정됨

### 4-3. 스팟 인스턴스 (Spot Instances)
- AWS의 남는 자원을 경매 방식으로 저렴하게(최대 90% 할인) 이용. 단, AWS가 언제든 회수 가능.
- **주의**: 언제 꺼져도 상관없는 단순 계산 작업에는 최고지만, 중요한 웹사이트나 DB를 돌리기엔 위험하다. (2분의 유예 시간을 주고 꺼짐)

#### 스팟 블록
- 1~6시간을 정해두고, 그동안은 중단 없이 해당 블록을 사용할 수 있다고 정해둔 스팟.

#### 스팟 플릿
- 플릿은 인스턴스가 여러 개 모인 세트.
- 사용자가 정의한 가격 제한으로 목표 용량을 충족하기 위해 가장 적합한 런치 풀을 선택하고, 예산이나 원하는 용량에 도달시 인스턴스 시작을 중지.

#### 요청 방식
- 우리가 원하는 인스턴스 수, 최대 가격, 시작 사양을 정의해서 요청서를 보내면 알아서 맞는 인스턴스를 찾아줌.
- 만약 스팟 인스턴스를 삭제하고 싶다면 요청을 먼저 취소하고 그 다음에 인스턴스를 삭제할 것.

### 4-4. 전용 호스트 (Dedicated Hosts)
- 물리적 서버 자체를 통째로 빌림.
- 아파트 한 호수를 빌리는 게 아니라, '건물 한 채'를 통째로 빌려 쓰는 것과 같다. 보안 규정상 하드웨어를 공유하면 안 되는 기업이 주로 사용한다.

### 4-5. 용량 예약 (Capacity Reservations)
- 할인은 없지만, 특정 시점에 인스턴스를 확실히 생성할 수 있도록 '자리만 찜' 해두는 것.
- 실제 차는 안 빌려도 '주차 공간'은 미리 결제해두는 예약석 개념이다.
- 특정 AZ에 있어야 하는 단기적이고 중단 없는 워크로드에 좋음.

## 5. 정리

### EC2 기본 개념 및 설정 요약

| 구분 | 주요 특징 | 관리 및 주의사항 |
| --- | --- | --- |
| **User Data** | 인스턴스 최초 부팅 시 자동 실행되는 스크립트. | 부팅 자동화 및 초기 설정용(단 1회 실행). |
| **Key Pair** | 인스턴스 원격 접속을 위한 암호화 키(RSA). | 분실 시 재발급 불가, 보안 유지 필수. |
| **공용 IPv4** | 외부 인터넷 접속용 주소. | 인스턴스 재시작 시 변경됨, 24년 2월부터 유료화. |
| **스토리지** | EBS(Elastic Block Store) 등 가상 드라이브. | '종료 시 삭제' 옵션 여부에 따라 데이터 보존 결정. |

### EC2 인스턴스 유형(Family) 비교

| 유형 | 영문 기호 | 특화 능력 | 적합한 작업 |
| --- | --- | --- | --- |
| **범용** | **M** (General) | 성능, 메모리, 네트워크의 균형. | 웹 서버, 코드 저장소, 일반 애플리케이션. |
| **컴퓨팅 최적화** | **C** (Compute) | 고성능 CPU 및 연산 속도. | 배치 처리, 머신 러닝, 게임 서버. |
| **메모리 최적화** | **R** (Memory) | 대용량 RAM 및 빠른 데이터 조회. | 고성능 DB, 실시간 비정형 데이터 처리. |
| **스토리지 최적화** | **I, D, H** | 높은 I/O 속도 및 로컬 용량. | NoSQL DB, 데이터 웨어하우징. |

### 보안 그룹(Security Groups) 및 포트

| 포트 번호 | 프로토콜 | 용도 | 비고 |
| --- | --- | --- | --- |
| **22** | **SSH** | 리눅스(Linux) 서버 접속. | 보안을 위해 특정 IP만 허용 권장. |
| **80** | **HTTP** | 일반 웹사이트 접속. | 보안되지 않은 표준 웹 트래픽. |
| **443** | **HTTPS** | 보안 웹사이트 접속. | SSL/TLS 암호화가 적용된 트래픽. |
| **3389** | **RDP** | 윈도우(Windows) 서버 접속. | 원격 데스크톱 연결용. |

### 인스턴스 구매 옵션 비교

| 옵션명 | 할인율 | 유연성 | 추천 상황 |
| --- | --- | --- | --- |
| **온디맨드** | 없음(정가) | 가장 높음 | 단기 작업, 예측 불가능한 워크로드. |
| **예약/절약 플랜** | 최대 72% | 보통 (1~3년 약정) | 장기간 안정적으로 운영하는 서버/DB. |
| **스팟** | 최대 90% | 낮음 (중단 가능성) | 중단되어도 무관한 분석 및 배치 작업. |
| **전용 호스트** | 낮음 | 매우 낮음 | 하드웨어 점유 필요, 규제 준수, 라이선스 지참. |
| **용량 예약** | 없음 | 보통 | 특정 지역의 자원을 확실히 확보해야 할 때. |

# III. SAA 레벨에서의 EC2 활용

1. IP와 ENI의 특징을 이용해 트래픽 전환을 유연하게 만들고, 견고한 논리적 망을 구축
2. 워크로드 목적(성능? 가용성?)에 맞게 하드웨어 어떻게 물리적으로 배치할지 전략 세움
3. Hibernate(절전 모드)를 통해 메모리 상태를 보존할지 결정

## 1. IP 특징 및 운영 방식
### 1-1. EIP
> 인스턴스를 껐다 켜도 변하지 않는 고정 공인 IP. 장애 발생 시 새 인스턴스에 즉시 연결하여 다운타임을 최소화한다.

#### IP 주소 체계
* EIP는 IPv6를 활용하는데, IPv4와 달리 주소 공간이 매우 넓어 **IoT(사물인터넷)** 기기 연결에 주로 사용된다.
* **탄력적 IP(EIP) 제한**: AWS 계정당 기본 **5개**로 할당량이 제한됨.
* EIP 고정 방식보다 임의의 공용 IP에 **DNS 이름**을 할당하여 운영하는 것이 확장성 및 제어 측면에서 유리하다.
* 사용 여부와 관계없이 시간당 약 $0.005의 요금이 부과된다.

#### 공용 IP와 사설 IP 비교

| 구분 | 공용 IP (Public IP) | 사설 IP (Private IP) |
| --- | --- | --- |
| **통신 범위** | 인터넷 전역 통신 가능 | 특정 사설 네트워크 내부 통신 |
| **유일성** | 전 세계에서 유일함 | 네트워크 내부에서만 유일함 |
| **접근 방식** | 인터넷 게이트웨이(IGW) 필요 | 내부 라우팅을 통해 직접 연결 |
| **비용** | 할당 및 사용 방식에 따라 과금됨 | 무료로 자유롭게 할당 가능 |

### 1-2. 네트워크 통신 시나리오

![](https://velog.velcdn.com/images/paramad/post/a94da8f8-2880-49e2-88c2-a7475db67e3e/image.png)

* **서버 간 외부 통신**
  * 공용 IP를 사용하여 인터넷 전역에서 고유한 주소로 식별됨.
  * **인터넷 게이트웨이(IGW)**를 경유하여 외부 네트워크와 데이터를 주고받음.
* **회사 내부 통신**
  * 외부에 노출되지 않는 **사설 네트워크** 환경에서 통신함.
  * RFC 1918 규격에 따라 구체적으로 정의된 사설 IP 범위를 할당하여 사용함.

## 2. EC2 배치 그룹 (Placement Groups)

![](https://velog.velcdn.com/images/paramad/post/18499cef-a5cb-4c76-b9dc-84718a24b99f/image.png)

> EC2 인스턴스가 물리적인 하드웨어에 각각 어떻게 배치될지 AWS에 결정해주는 전략.

### 2-1. 정의 및 배치 전략 개요

* EC2 인스턴스의 물리적 하드웨어 배치 방식을 결정하는 논리적 설정임.
* 워크로드의 성격에 따라 성능 최적화 또는 가용성 극대화를 선택할 수 있음.

### 2-2. 배치 그룹 유형 비교

| 구분 | 클러스터 (Cluster) | 분산 (Spread) | 분할 (Partition) |
| --- | --- | --- | --- |
| **핵심 목표** | 낮은 지연 시간 및 고대역폭 | 하드웨어 장애로부터 완전 격리 | 대규모 분산 워크로드 관리 |
| **배치 범위** | 단일 가용 영역 (Single AZ) | 여러 가용 영역 가능 | 여러 가용 영역 가능 |
| **확장성 제한** | 인스턴스 유형별 상이함 | 가용 영역당 최대 7개 인스턴스 | 가용 영역당 최대 7개 파티션 |
| **네트워크 성능** | 매우 높음 (10Gbps 이상) | 일반 네트워크 성능 제공 | 일반 네트워크 성능 제공 |
| **주요 활용 사례** | 빅데이터 연산, 고성능 컴퓨팅 | 크리티컬 애플리케이션, 고가용성 | Kafka, Cassandra, Hadoop |

### 2-3. 세부 상세 특징

![](https://velog.velcdn.com/images/paramad/post/dbf16b69-a166-4e30-851a-2b3f3ad2336b/image.png)

#### 클러스터 배치 그룹 (Cluster)

* 모든 인스턴스를 단일 가용 영역 내의 동일한 네트워크 장비에 배치함.
* 인스턴스 간 물리적 거리를 최소화하여 지연 시간을 줄이고 초당 약 10Gbps의 대역폭 확보가 가능함.
* 대규모 연산 처리가 필요한 빅데이터 분석 환경에 적합함.
* 가용 영역 전체 장애 시 그룹 내 모든 인스턴스가 영향을 받을 수 있다는 단점이 있음.

#### 분산 배치 그룹 (Spread)
> 1랙 - 1EC2

* 각 인스턴스를 서로 다른 물리적 하드웨어 랙에 개별적으로 배치함.
* 하드웨어 하나가 고장 나더라도 다른 인스턴스의 안정성을 보장할 수 있음.
* 동일한 가용 영역 또는 여러 가용 영역에 걸쳐 구성 가능함.
* 인스턴스 개수가 제한적이므로 규모가 작은 핵심 애플리케이션 운영에 유리함.

#### 분할 배치 그룹 (Partition)
> 1랙 - 1파티션 (1파티션 = 수백 개 인스턴스)

* 배치 그룹을 여러 개의 논리적 파티션으로 나누고, 각 파티션을 서로 다른 랙에 배치함.
* 특정 파티션의 하드웨어 장애가 다른 파티션에 영향을 주지 않도록 격리됨.
* 한 파티션 내에 수백 개의 인스턴스를 포함할 수 있어 대규모 확장이 용이함.
* 인스턴스의 파티션 정보를 메타데이터를 통해 확인할 수 있어 데이터 복제 배치 등에 활용 가능함.

## 3. ENI (탄력적 네트워크 인터페이스)
![](https://velog.velcdn.com/images/paramad/post/38942dbf-05db-4bc8-90fd-d4a5154a0a66/image.png)

> 인스턴스에 부여되는 가상의 랜 카드(NIC; Network Interface Card)라고 보면 된다. IP를 포함해 여러 정보를 가지고 있음.

### 3-1. 개요 및 주요 특징
- VPC 내에서 가상 네트워크 인터페이스를 나타내는 논리적 네트워킹 구성 요소임.
- EC2 인스턴스 생성 시 기본적으로 하나의 네트워크 인터페이스가 자동으로 생성 및 할당됨.
- 식별 ID는 `eni-`로 시작함.
- AWS 관리 콘솔의 [네트워크 및 보안] 탭에서 생성, 연결, 분리 등의 관리 작업을 수행할 수 있음.

### 3-2. 주요 활용 시나리오 (장애 조치 및 네트워크 분리)
![](https://velog.velcdn.com/images/paramad/post/b6027619-fec7-4247-b65c-1c7498a4bffe/image.png)

- 1) 고가용성 및 장애 조치 (Failover)
동일한 서비스를 제공하는 두 개의 인스턴스가 있을 때 활용함.
  - 서비스 중인 인스턴스에 문제가 발생할 경우, 해당 ENI를 정상 작동 중인 다른 인스턴스로 즉시 이동함.
  - 이를 통해 사설 IPv4 주소를 유지하면서 트래픽을 신속하게 전환하여 서비스 연속성을 보장할 수 있음.
- 2) 네트워크 및 보안 분리
  - 관리용 네트워크와 서비스용 네트워크를 분리하기 위해 다중 ENI를 사용함.
  - 각 ENI에 서로 다른 보안 그룹을 적용하여 정교한 네트워크 제어가 가능함.

## 4. EC2 Hibernate(절전 모드)

![](https://velog.velcdn.com/images/paramad/post/d58e20be-80cd-41df-aca4-05f4705a7d56/image.png)

### 4-1. 개념 및 작동 원리

* 인스턴스 정지 시 RAM(메모리)의 내용을 루트 EBS 볼륨에 저장하는 기능임.
* 다시 시작할 때 EBS에 저장된 데이터를 RAM으로 복구하여 중지 전 상태에서 즉시 시작 가능함.
* 일반적인 부팅 과정(OS 커널 로드 등)을 생략하므로 서비스 재개 속도가 매우 빠름.
* 인 메모리(In-memory) 상태를 유지해야 하는 워크로드나 부팅 시간이 긴 애플리케이션에 유리함.

#### Hibernation(하이버네이션)
> 단순 서버를 끄는 것이 아니라, 현재 RAM(메모리)에 올라와 있는 모든 데이터를 EBS에 통째로 저장하고 전원을 끄는 작업. AWS의 가상화 기술인 Nitro 시스템(하이퍼바이저)이 인스턴스의 하드웨어 상태를 소프트웨어적으로 제어한다. RAM 데이터를 디스크로 옮기는 복잡한 과정을 하이퍼바이저가 안전하게 핸들링하는 것.

### 4-2. 주요 특징 및 제약 사항

| 항목 | 상세 내용 |
| --- | --- |
| **루트 볼륨 유형** | 반드시 **EBS 볼륨**이어야 함 (인스턴스 스토어 볼륨은 불가함). |
| **볼륨 암호화** | 데이터 보호를 위해 루트 EBS 볼륨의 **암호화가 필수적**임. |
| **지원 인스턴스** | 온디맨드, 예약 인스턴스(RI), 스팟 인스턴스에서 모두 사용 가능함. |
| **제약 대상** | **베어메탈(Bare Metal)** 인스턴스 유형은 지원하지 않음. |
| **운영 체제** | 리눅스(Amazon Linux, Ubuntu 등), 윈도우 등 주요 OS에서 지원함. |
| **유지 기간** | 하이버네이트 상태로 최대 **60일**까지 유지할 수 있음. |

#### 베어메탈
어떠한 소프트웨어도 설치되어 있지 않은 순수한 하드웨어 서버 그 자체. 가상화를 사용하지 않고 하드웨어 위에 직접 OS를 설치. 아파트로 치면 '단독 주택' 전체를 혼자 사용하는 것과 같다. 일반적인 클라우드 서버(EC2 등)는 하나의 물리 서버를 여러 명이 나누어 쓰기 위해 '가상화'라는 층을 들지만, 반면 베어메탈은 이 층이 없다. 왜 EC2 Hibernate는 베어메탈 유형을 지원하지 않는가? 바로 하이버네이션을 관리해줄 중간 관리자 역할 '하이퍼바이저'가 없기 때문.

### 4-3. 작동 메커니즘 상세
1. **하이버네이트 실행**: RAM 데이터를 루트 EBS 볼륨으로 덤프(Dump)함.
2. **인스턴스 정지**: RAM 데이터는 삭제되지만 EBS 볼륨 내에 상태 값이 보존됨.
3. **인스턴스 재개**: EBS 볼륨에서 데이터를 읽어 RAM으로 로드함.
4. **복구 완료**: 중단된 시점부터 프로세스가 다시 실행됨.


### 4-4. 설정 및 구성 방법
* **인스턴스 생성 시**: '세부 정보(Advanced details)' 섹션의 '중지 - 하이버네이트 동작(Stop - Hibernate behavior)'을 활성화함.
* **스토리지 설정**:
  * EBS 볼륨 암호화를 반드시 체크하고 KMS 키(`aws/ebs`)를 지정해야 함.
  * RAM 전체 용량을 덤프할 수 있도록 EBS 볼륨 용량을 인스턴스 메모리보다 크게 할당해야 함.
* **주의 사항**: 인스턴스 생성 이후에는 하이버네이트 설정을 변경할 수 없으므로 초기 생성 시 구성해야 함.
