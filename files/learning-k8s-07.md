## 1. 세션 고정 (Session Affinity)
특정 클라이언트로부터의 요청을 매번 동일한 파드로 전달하도록 설정하는 기능이다.

### 1) 특징 및 설정
* **동작 원리**: 서비스(ClusterIP, LoadBalancer 등)에 접근한 트래픽이 한 번 파드에 할당되면, 이후 동일한 클라이언트 IP에서 오는 요청은 일정 시간 동안 해당 파드로 계속 고정된다.
* **구현 방식**: 각 노드의 iptables를 통해 관리되며, 기본값은 `None`이다.
* **설정 파라미터**: 
  * `spec.sessionAffinity`: `ClientIP`로 설정하여 활성화한다.
  * `spec.sessionAffinityConfig.clientIP.timeoutSeconds`: 세션이 유지되는 최대 시간을 초 단위로 설정한다.

### 2) 활용 사례
* 사용자 로그인 세션 정보가 메모리에 저장되어 있어 다른 파드로 요청이 튀면 세션이 끊기는 애플리케이션에서 사용한다.

## 2. 인그레스 (Ingress)
클러스터 외부에서 내부 서비스로 접근하는 HTTP와 HTTPS 경로를 관리하는 API 리소스다. L7 수준의 로드밸런싱을 제공한다.

### 1) 주요 기능
* **URL 경로 기반 라우팅**: `/api`나 `/static` 등 경로에 따라 서로 다른 서비스로 트래픽을 분산한다.
* **호스트 이름 기반 라우팅**: 도메인 이름(예: example.com)에 따라 트래픽을 처리한다.
* **SSL/TLS 터미네이션**: 보안 연결을 인그레스 지점에서 종료하고 내부 서비스로는 일반 트래픽을 전달하는 역할을 수행한다.

### 2) 인그레스 컨트롤러 (Ingress Controller)
인그레스 리소스는 규칙을 정의한 문서일 뿐이며, 실제로 트래픽을 제어하려면 인그레스 컨트롤러가 실행 중이어야 한다.
* **클라우드 통합형**: AWS ALB 인그레스 컨트롤러처럼 클라우드 업체의 로드밸런서와 직접 연동되어 가상 IP를 할당받는다.
* **클러스터 내부 배치형**: Nginx 인그레스 컨트롤러와 같이 클러스터 내부에 전용 파드를 띄워 트래픽을 처리한다.

### 3) 트래픽 흐름의 차이
* **클라우드 로드밸런서 연동 시**: 외부 로드밸런서가 트래픽을 수신한 후 NodePort를 거쳐 대상 파드에 도달한다.
* **Nginx 인그레스 사용 시**: 외부 L4 로드밸런서가 Nginx 파드(인그레스 파드)로 트래픽을 보내면, Nginx가 L7 처리를 마친 후 대상 파드의 IP로 직접 트래픽을 전달한다.
