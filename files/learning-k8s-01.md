## 1. 컨테이너 런타임 (Container Runtime)
컨테이너 런타임은 컨테이너를 생성하고 실행하며 전체 수명 주기를 관리하는 환경을 의미한다. 쿠버네티스는 다양한 런타임을 지원하며 운영체제 수준의 가상화를 통해 효율적인 자원 관리를 수행한다.

* **Containerd**: 도커에서 개발한 오픈 소스 런타임으로, 이미지 다운로드, 압축 해제, 실행 및 감독 등 핵심 기능을 제공한다.
* **Docker**: Containerd를 기반으로 구축된 데몬으로, 컨테이너 관리 전반에 필요한 기능을 제공한다.
* **CRI-O**: 도커를 대체하기 위해 레드햇, 인텔 등 여러 기업이 협력하여 개발한 오픈 소스 런타임이다.

## 2. 클러스터 내부 통신 원리
쿠버네티스 클러스터 내에서는 여러 노드에 흩어져 있는 포드(Pod)들이 서비스 IP를 통해 서로 통신한다.

* **넷필터(netfilter)와 iptables**: 리눅스 커널의 패킷 처리 엔진이다. 서비스 IP로 요청이 들어오면 이를 실제 포드의 IP로 변환하는 프록시 역할을 수행한다.
* **동작 방식**: 워커 노드들이 서비스 IP를 실제 서버 IP로 변환하여 라우터나 게이트웨이로 패킷을 전달함으로써, 클라이언트가 개별 포드의 위치를 몰라도 서비스에 접근할 수 있게 한다.

## 3. 클러스터 외부와의 통신 방식
내부 자원을 외부 유저가 접근할 수 있도록 노출하는 세 가지 주요 방법이 있다.

* **NodePort**: 각 노드의 IP에 특정 포트(예: 30001)를 직접 할당하여 외부 요청을 내부 서비스로 전달한다.
* **Load Balancer**: AWS, GCP, Azure와 같은 퍼블릭 클라우드 환경에서 제공하는 로드 밸런서를 사용하여 클러스터 외부 전용 IP를 할당받는다.
* **Ingress**: 클러스터 외부에서 내부로 들어오는 HTTP/HTTPS 요청을 처리하는 규칙의 모음이다. URL 기반 라우팅, SSL 인증서 처리 등을 정의하며, 실제로 이를 구동하는 것은 인그레스 컨트롤러(Ingress-Controller)다.
