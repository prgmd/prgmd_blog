## 1. Django 애플리케이션 도커 배포 프로세스
애플리케이션을 컨테이너화하여 EC2 인스턴스에 자동 배포하는 환경을 구축한다.

### 1) 애플리케이션 준비 및 도커라이징
* **Django 프로젝트 설정**: 외부 접속을 위해 `ALLOWED_HOSTS`를 `['*']`로 수정하고, 의존성 라이브러리 목록을 `requirements.txt`에 기록한다.
* **Dockerfile 작성**: 파이썬 환경을 기반으로 소스 코드를 복사하고, 80번 포트를 개방하여 서버를 실행하는 이미지를 정의한다.

### 2) GitHub Actions를 이용한 CI/CD 구성
* **Docker Hub 푸시**: GitHub Actions를 통해 이미지를 빌드하고 도커 허브 레포지토리에 업로드한다. 이때 로그인 정보는 GitHub Secrets에 안전하게 저장하여 관리한다.
* **EC2 원격 배포**: GitHub Actions 가상 환경에서 EC2에 SSH로 접속하여 기존 컨테이너를 중단 및 삭제하고, 최신 이미지를 내려받아 새 컨테이너를 구동하는 스크립트를 실행한다.
* **보안 설정**: SSH 접속에 필요한 PEM 키는 Base64로 인코딩하여 GitHub Secrets에 등록하여 사용한다.

## 2. Amazon ECR (Elastic Container Registry)
AWS에서 제공하는 완전 관리형 도커 컨테이너 레지스트리 서비스다.

* **특징**: S3를 기반으로 이미지를 관리하여 높은 가용성을 보장하며, IAM 인증을 통해 이미지의 Push/Pull 권한을 세밀하게 제어할 수 있다.
* **구분**: 조직 내에서만 사용하는 프라이빗(Private) 레지스트리와 누구나 접근 가능한 퍼블릭(Public) 레지스트리를 모두 지원한다.

## 3. Amazon ECS (Elastic Container Service)
AWS 환경에 최적화된 관리형 컨테이너 오케스트레이션 서비스다.

### 1) 주요 구성 요소
* **클러스터 (Cluster)**: 컨테이너가 실행되는 논리적인 그룹이다.
* **태스크 정의 (Task Definition)**: 컨테이너 이미지, CPU/메모리 할당량, 포트 매핑 등을 정의하는 청사진이다. (쿠버네티스의 파드 설정이나 도커 컴포즈와 유사)
* **작업 (Task)**: 태스크 정의를 바탕으로 클러스터 내에서 실제로 실행되는 컨테이너 인스턴스다.
* **서비스 (Service)**: 지정된 수의 태스크가 항상 실행되도록 유지하고, 로드 밸런서 및 오토 스케일링과 연동하여 애플리케이션의 가용성을 관리한다.

### 2) 인프라 실행 모드
* **Fargate (서버리스)**: 사용자가 서버(EC2)를 직접 관리할 필요 없이 컨테이너를 바로 실행할 수 있는 방식이다. 인프라 관리에 대한 부담이 매우 적다.
* **EC2 인스턴스**: 사용자가 클러스터에 연결된 EC2 노드를 직접 관리하는 방식이다. 인프라에 대한 세밀한 제어가 필요한 경우 선택한다.

## 4. ECS 서비스 배포 실습 (Nginx 예시)
1. **이미지 확인**: 배포할 이미지가 레포지토리에 존재하는지 확인한다.
2. **클러스터 생성**: 서비스가 구동될 논리적 공간인 클러스터를 생성한다. (Fargate 방식 권장)
3. **태스크 생성**: 실행할 운영체제와 하드웨어 사양, 컨테이너 이미지 정보를 작성한다.
4. **서비스 연결**: 생성한 태스크를 클러스터에 배포하고 서비스를 활성화하여 외부 통신을 구성한다.
