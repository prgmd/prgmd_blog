## 1. 백엔드 애플리케이션 로컬 환경 테스트
실제 클라우드 배포에 앞서 로컬 도커 환경에서 애플리케이션과 데이터베이스의 연동을 확인한다.

* **로컬 DB 구성**: PostgreSQL 도커 이미지를 실행하고, `mywork` 사용자 및 `myworkdb` 데이터베이스를 생성한다.
* **샘플 데이터 생성**: 지역(Region), 명소(Location), 배치 처리(Batch Processing) 관련 테이블을 생성하고 기초 데이터를 입력하여 기능을 검증한다.

## 2. CloudFormation을 이용한 RDS 구축
AWS 인프라 자동화 도구인 CloudFormation을 사용하여 백엔드 애플리케이션이 사용할 관계형 데이터베이스 환경을 구축한다.

* **스택 생성 및 설정**: VPC 선택 시 EKS와 연동된 VPC를 지정하여 통신 효율을 높이고, 기존에 생성된 라우팅 테이블 정보를 활용한다.
* **데이터베이스 접속 및 계정 설정**:
    * 보안 강화를 위해 외부 노출이 차단된 RDS에 접속하고자 베스천 호스트(Bastion Host)와 세션 매니저를 이용한다.
    * AWS Secrets Manager를 통해 관리자 비밀번호를 확인한 뒤, PostgreSQL 클라이언트를 설치하여 애플리케이션 전용 계정과 데이터베이스를 생성한다.
    * 실무 환경과 동일하게 JPA 자동 생성 기능 대신 직접 테이블 스키마를 정의하여 구축한다.

## 3. EKS 클러스터 애플리케이션 배포 과정
백엔드 애플리케이션을 컨테이너화하여 관리형 쿠버네티스 서비스인 EKS에 배포한다.

* **네임스페이스 및 컨텍스트 설정**: `eks-work` 네임스페이스를 생성하고, `kubeconfig`의 컨텍스트를 해당 네임스페이스를 사용하도록 업데이트한다.
* **데이터베이스 접속 보안(Secret)**: 소스 코드 내 접속 정보를 직접 기입하는 대신, 환경 변수(`${DB_URL}`, `${DB_USERNAME}`, `${DB_PASSWORD}`)를 사용하도록 소스를 수정한다.
* **이미지 빌드 및 ECR 푸시**: Gradle을 이용해 JAR 파일을 빌드하고 도커 이미지를 제작한 뒤, Amazon ECR에 로그인하여 이미지를 배포한다.
* **애플리케이션 배포 수행**: 시크릿 템플릿과 디플로이먼트 매니페스트에 `envsubst`를 적용하여 실제 접속 정보를 주입하고 배포를 마무리한다.

## 4. 리소스 정리 및 모니터링
서비스 운영을 마친 후 불필요한 비용 발생을 막기 위해 리소스를 철저히 삭제하며, 운영 중 부하 상태를 관리한다.

* **모니터링**: Amazon CloudWatch를 통해 데이터 플레인의 부하 상태를 확인하고 오토 스케일링 그룹의 동작 상태를 관리한다.
* **리소스 삭제 순서**: 아래 순서에 따라 리소스를 삭제하여 의존성 문제 없이 정리를 완료한다.
    1. 쿠버네티스 서비스 및 디플로이먼트 삭제
    2. EKS 클러스터 삭제 (`eksctl delete cluster`)
    3. 데이터베이스 및 베스천 호스트 관련 CloudFormation 스택 삭제
    4. VPC 등 기본 네트워크 인프라 리소스 삭제
