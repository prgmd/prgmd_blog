## 1. 도커 컴포즈 (Docker Compose)
Dockerfile이 단일 애플리케이션 이미지를 만드는 도구라면, 도커 컴포즈는 여러 개의 컨테이너로 구성된 서비스 전체를 한 번에 관리하는 도구이다.

* **주요 특징**: 시스템 구축 명령어를 YAML 파일에 기재하여 전체 시스템을 일괄 실행하거나 폐기할 수 있다. 네트워크와 볼륨 정의를 포함할 수 있어 복합적인 애플리케이션 스택 관리에 유리하다.
* **주요 명령어**:
    * `up`: 정의된 이미지를 내려받고 컨테이너를 생성 및 실행한다.
    * `down`: 실행 중인 컨테이너와 네트워크를 정지하고 삭제한다. (볼륨과 이미지는 유지)
    * `stop`: 삭제 없이 컨테이너만 종료한다.
* **Dockerfile과의 차이**: Dockerfile은 이미지 생성에 집중하며 네트워크나 볼륨 생성이 불가하지만, 도커 컴포즈는 `docker run` 명령을 모아놓은 형태에 가까워 주변 환경까지 설정 가능하다.

## 2. Nginx를 활용한 로드 밸런싱 실습
하나의 Nginx 서버가 여러 개의 백엔드 애플리케이션(Flask)으로 트래픽을 분산하는 환경을 구축한다.

### 1) 백엔드 애플리케이션 준비 (Flask)
* **애플리케이션 작성**: 접속 시 "Web Application [N]" 메시지를 반환하는 간단한 Flask 코드를 작성한다.
* **환경 설정**: `requirements.txt`에 Flask와 필요한 의존성 패키지를 명시한다.
* **Dockerfile 작성**: Python 이미지를 기반으로 패키지를 설치하고 작성한 소스 코드를 복사하여 실행하도록 구성한다. 동일한 구성을 가진 3개의 앱 디렉토리를 준비한다.

### 2) Nginx 리버스 프록시 설정
* **nginx.conf 작성**: `upstream` 블록을 사용하여 부하를 분산할 대상 서버(Flask 컨테이너들의 IP 및 포트)를 지정한다.
* **설정 예시**:
    ```nginx
    upstream web-alb {
        server 172.17.0.1:5001;
        server 172.17.0.1:5002;
        server 172.17.0.1:5003;
    }
    server {
        listen 80;
        location / {
            proxy_pass http://web-alb;
        }
    }
    ```

### 3) 시스템 통합 실행
* 도커 컴포즈 YAML 파일에 Nginx 서비스와 3개의 Flask 서비스를 정의한다.
* 각 Flask 컨테이너는 호스트의 서로 다른 포트(5001~5003)에 매핑하고, Nginx는 80번 포트를 개방한다.
* `docker-compose up` 실행 후 외부에서 80번 포트로 접속 시, Nginx가 설정된 정책에 따라 각 웹 애플리케이션으로 요청을 전달하는 것을 확인한다.
