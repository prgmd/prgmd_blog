# 1. 데이터 타입 심화
## 1-1. 튜플
튜플은 단순 '수정 불가능한 리스트'가 아니라, 데이터의 구조를 잡는 강력한 도구로 활용 가능.

### 가변 언패킹
`a, *b, c = (1, 2, 3, 4, 5)`라고 하면 `a=1`, `c=5`가 들어가고 나머지 `[2, 3, 4]`는 리스트로 묶여 `b`에 담김.

### 조건부 대입
`result = ("낙제", "합격")[score >= 60]`와 같이 작성하면, 조건이 `False(0)`면 인덱스 0번을, `True(1)`면 인덱스 1번을 선택합니다. `if-else` 한 줄 쓰기(`ternary operator`)의 독특한 대안.

### 데이터 구조화(NamedTuple)
`Point = namedtuple('Point', ['x', 'y'])`로 정의하면, `p.x`, `p.y`처럼 이름을 찍어서 접근할 수 있음. 클래스를 만들기엔 너무 거창하고, 단순 튜플은 인덱스 번호가 헷갈릴 때 사용 가능한 선택지.

## 1-2. 집합과 딕셔너리
중복 제거와 빠른 검색(Hash Table)이 핵심.

### frozenset
데이터 변경이 불가능한 집합. 일반 `set`은 딕셔너리의 키(Key)로 쓸 수 없지만, `frozenset`은 불변이기 때문에 키로 사용이 가능하다.

### 안전한 조회(`get`)
`my_dict['key']`는 키가 없으면 에러(KeyError)를 내지만, `get('key', 0)`은 에러 대신 기본값(0)을 주어 프로그램 중단을 막음.

### 뷰 객체
`keys`, `values`, `items`는 단순 리스트가 아니라 딕셔너리의 상태를 실시간으로 반영하는 '뷰(View)'. 딕셔너리 내용이 바뀌면 이들의 결과도 함께 바뀐다.

## 1-3. 파이썬 도구
### `enumerate`
`for i, v in enumerate(list)`를 쓰면 "지금 몇 번째 데이터지?"를 알기 위해 별도의 카운터 변수를 만들 필요가 없음.

### Comprehension 
List, Dict, Set 모두 가능. `[x**2 for x in range(5) if x % 2 == 0]` 처럼 **[값 생성 / 반복 / 조건]**을 한 줄에 담아 가독성과 성능을 동시에 잡을 수 있다.

# 2. 유용한 라이브러리 모듈

## 2-1. collections 모듈

### deque
양방향 큐 자료구조. 앞뒤 어디서든 데이터를 넣고 빼는 속도가 매우 빠르다.

### Counter
데이터 안의 요소 개수를 자동으로 집계. `most_common(n)` 메서드를 쓰면 가장 빈도수가 높은 상위 $n$개를 바로 뽑아낼 수 있다.

### defaultdict/OrderedDict
존재하지 않는 키에 기본값을 주거나, 입력한 데이터 순서를 엄격하게 보장하는 특수 딕셔너리.

## 2-2. 시스템 및 경로 모듈

각각 파일 시스템(os), 인터프리터(sys), 파일 검색(glob)에 특성을 가지고 있다.

### `os` / `os.path`:
* `os.makedirs('path/to/dir', exist_ok=True)`: 계층 구조의 폴더를 한 번에 생성.
* `os.path.join('folder', 'file.txt')`: 운영체제(Windows/Linux)에 맞는 경로 구분자(`\` 또는 `/`)를 자동으로 삽입.
* `os.path.exists()`: 파일이나 폴더가 진짜 있는지 확인하는 안전장치.

### `sys`
* `sys.argv`: 터미널에서 프로그램을 실행할 때 넘겨준 인자값들을 리스트로 받음.
* `sys.path`: 파이썬이 모듈을 찾을 때 뒤져보는 경로 목록.
* `sys.exit()`: 특정 조건에서 프로그램을 즉시 강제 종료.

### `glob`
* `glob.glob('*.png')`: 현재 폴더의 모든 PNG 파일 목록을 리스트로 반환.
  * `recursive=True` 옵션과 `**` 패턴을 쓰면 하위 폴더까지 싹 뒤질 수 있다.

# 3. 예외 처리 (Exception Handling)
> 프로그램 실행 중에 발생하는 예상치 못한 에러를 관리하여 프로그램이 비정상적으로 죽지 않게 보호하는 기술.

## 3-1. 예외 처리의 기본 구조
프로그램이 갑자기 멈추는 '런타임 에러'를 방지하고, 우아하게(Gracefully) 오류를 알리는 방법.

* **`try`**: 에러가 발생할 가능성이 있는 코드를 격리.
* **`except`**: 특정 에러가 발생했을 때 실행될 '대피소'. `except ValueError:`처럼 구체적인 에러 이름을 명시하는 것이 좋다.
* **`else`**: **"에러가 하나도 없었을 때"**만 실행. `try` 블록에는 최소한의 코드만 넣고, 나머지 로직은 여기에 두어 가독성을 높이는 것이 꿀팁.
* **`finally`**: 에러 발생 여부와 상관없이 **"마지막에 무조건"** 실행되는 구문. 파일 닫기(`f.close()`)나 DB 연결 해제처럼 반드시 수행해야 할 정리 작업에 쓰인다.

### with 문 (context manager)
try-finally을 내부적으로 품고 있는 구문. 시작될 때 `__enter__` 메서드를 실행하고, with가 끝날 때 `__exit__` 메서드를 실행해 자원을 알아서 반납한다. 파이썬에서 파일을 열거나 데이터베이스를 연결할 때 발생하는 '뒷정리' 문제를 해결해주는 아주 똑똑한 도구다.

``` python
# with를 안 썼을 때 (위험)
f = open('test.txt', 'r')
data = f.read()
# 만약 여기서 에러가 나면 f.close()까지 못 가고 프로그램이 터짐
# 파일은 계속 열려 있는 상태(누수)가 됨
f.close()

# with를 썼을 때
with open('test.txt', 'r') as f:
    data = f.read()
    # 이 블록(들여쓰기)이 끝나는 순간 f.close()가 자동으로 호출됨!
    # 심지어 내부에서 에러가 나도 파이썬이 "어머, 닫아야지!" 하고 닫아줌
```

## 3-2. 개발자가 직접 제어하는 방식
파이썬이 잡지 못하는 비즈니스 로직상의 에러를 다룰 때는 다음과 같은 방식을 사용해야 한다.

* **`raise` (강제 발생)**: "내 규칙에 어긋나면 에러다!"라고 선언. (예: `if age < 0: raise ValueError("나이는 음수일 수 없습니다.")`)
* **`assert` (단언하기)**: `try-except`가 발생할 수 있는 에러를 수습하는 단계라면, `assert`는 절대 일어나선 안 되는 상황을 감시. "이 조건은 무조건 참이어야 함. 아니면 가망 없음... 지금부터는 코드 실행 의미 없으니 걍 프로그램 끄셈"이라는 뜻. 
  - 주로 개발 단계에서 디버깅 용도로 사용. 조건이 `True`면 넘어가고, `False`면 바로 프로그램 중단시킴.
  - 배포 시 최적화 옵션(`-O`)을 쓰면 무시될 수 있으니 주의해야 한다. (예: `assert score >= 0, "점수가 음수로 입력됨"`)

# 4. 객체 복사

## 4-1. 단순 대입 (Assignment)
수에 변수를 대입(`b = a`)하는 것은 복사가 아님. 하나의 불변 데이터에 **이름표를 하나 더 붙이는 것**. 이 경우 `b`를 수정하면 `a`도 똑같이 바뀐다. 둘은 같은 메모리 주소를 공유하기 때문.

### 데이터 타입에 따른 결과 차이
- 불변 객체일 경우 데이터 자체를 수정할 수 없음. b = 3처럼 값을 바꾸려 하면, 기존 데이터가 바뀌는 게 아니라 b라는 이름표만 떼서 새로운 데이터에 붙임. a와 b의 연결이 끊어지므로, a는 변하지 않음.
- 가변 객체일 경우 데이터 내부(내용물)를 수정할 수 있음. b.append(4)처럼 내용물 자체를 수정하면, 같은 데이터를 보고 있던 a도 그 변화를 그대로 보게 되고 a와 b가 똑같이 바뀜.

## 4-2. 얕은 복사 (Shallow Copy)
> 가장 바깥쪽의 리스트는 새로 만들지만, 그 안에 들어있는 **요소(주소값)**들은 그대로 가져옴.

* **방법:** `b = a[:]`, `b = a.copy()`, `b = list(a)`
* **문제점:** 1차원 리스트(예: `[1, 2, 3]`)는 괜찮지만, **중첩 리스트**(`[[1, 2], 3]`)에서는 내부의 리스트(`[1, 2]`) 주소가 원본과 공유된다. 속알맹이를 고치면 양쪽 다 바뀜.

## 4-3. 깊은 복사 (Deep Copy)
내부에 포함된 모든 객체까지 **재귀적으로** 전부 새로 복제.

* **방법:** `import copy` 후 `copy.deepcopy(obj)` 사용.
* **특징:** 원본과 복사본이 메모리상에서 완전히 남남이 된다. 어떤 깊이의 데이터를 수정해도 서로 영향을 주지 않는다.

## 비교 연산자 (`==`, `is`)
* **`==` (Equal):** "값이 같은가?"
* **`is` (Identical):** "완전히 같은 객체인가? (메모리 주소가 같은가?)"

얕은 복사를 하면 `a is b`는 `True`지만, 깊은 복사를 하면 `a == b`만 **True**로 나오고 `a is b`는 **False**가 나온다.

# 5. 파이썬 웹 프레임워크
## 5-1. Django (장고)
완벽주의자를 위한 웹 프레임워크. 서비스에 필요한 거의 모든 기능을 본사가 다 준비해둔 **풀옵션 아파트**와 같다. MTV 패턴(Model(데이터), Template(화면), View(로직))으로 역할을 엄격히 나눈다. 심지어 로그인, 권한 관리, 데이터베이스 관리(ORM), 관리자 페이지(Admin) 등 웹 서비스에 필요한 기능은 전부 제공. SQL 인젝션, CSS 공격 등 흔한 웹 보안 취약점도 프레임워크 수준에서 알아서 다 막아준다. 대규모 포털, 복잡한 사용자 권한이 필요한 커뮤니티, 빠른 시일 내에 완성된 기능을 뽑아내야 할 때 추천.

## 5-2. Flask (플라스크)
'Micro Framework'라는 슬로건답게 핵심 기능만 담은 **레고 블록**이라 보면 된다. 처음 설치하면 정말 딱 서버를 띄우는 기능만 있다. (DB 연결이나 로그인 기능은 개발자가 원하는 라이브러리를 직접 골라서 끼워 넣어야 함) 정해진 규칙이 거의 없어 코드를 아주 자유롭게 짤 수 있고, 공부용으로 구조 파악하기에 좋다. 아주 가볍기 때문에 마이크로서비스(MSA)나 아주 단순한 기능만 수행하는 서버를 만들 때 유리하다. 소규모 프로젝트, 프로토타입 제작, 프레임워크의 제약 없이 내 마음대로 구조를 설계하고 싶을 때 추천.

## 5-3. FastAPI
가장 최근에 등장한 **차세대 주자**. 파이썬의 최신 문법(Type Hint)을 적극 활용한 **스포츠카**다. 파이썬 프레임워크 중 가장 빠르며, (Go나 NodeJS와 비견될 정도) `async/await`를 이용한 **비동기 처리**가 비결. Pydantic을 기반으로 데이터가 들어올 때 타입이 맞는지 자동으로 체크한다. 또한 API 테스트 페이지인 Swagger를 지원해서, 별도 작업 없이 서버만 실행하면 자동 문서화가 가능하다. AI 모델 서빙, 데이터 엔지니어링 API, 비동기 처리가 중요한 실시간 서비스에 추천.

### 동기 vs. 비동기
- 동기 방식은 앞의 작업이 끝날 때까지 뒤의 작업이 무조건 대기하는 방식.
- 비동기 방식은 작업이 시작되면 결과를 기다리지 않고 다음 할 일을 먼저 하는 방식.
  - 컴퓨터가 일을 할 때 가장 시간이 오래 걸리는 작업은 연산(CPU)이 아니라 데이터를 주고받는 일(I/O)인데, FastAPI는 `await` 키워드를 만나면 '어 그래그래 난 결과 나올 때까지 딴 애부터 처리할게' 하고 넘어가 버린다.
  - 물론 비동기는 '기다리는 시간'을 효율적으로 쓰는 기술이지, '일하는 속도' 자체가 빨라지는 건 아니다. 데이터베이스 조회, API 호출이 많은 웹 서버 (대부분의 웹 서비스)의 경우 비동기가 매우 유리하지만, 복잡한 수학 계산이나 영상 인코딩처럼 CPU가 쉴 틈 없이 계속 일해야 하는 작업을 해야할 때는 비동기가 불리하다.
