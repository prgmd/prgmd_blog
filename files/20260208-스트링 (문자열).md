# 1. 문자열
## 1-1. 코드체계
- 메모리는 숫자만 저장 가능
- 영어는 대소문자를 합쳐 52자이므로, 6비트로 저장이 가능하다 (이진수 배정)
- 핵심 : 전 세계 모든 문자를 컴퓨터가 일관되게 표현하고 처리하는 것

### ASCII
- 네트워크가 발전하기 전 미국은 각 지역 별로 코드체계가 달랐는데, 서로 정보를 주고 받을 때 정보를 달리 해석한다는 문제가 발생했다
  - 그래서 표준안을 만들기로 함. 1967년 ASCII 표준이 제정
  - 7비트로 128문자를 표현하고, 33개의 출력 불가능한 제어 문자와 공백을 비롯한 95개의 출력 가능한 문자로 이뤄짐
    - 왜 7비트? 마지막 1비트는 오류를 감지하는 패리티 비트로 사용
- `'A'`는 10진수로 65, 이진수로 $1000001_2$.

### 확장 ASCII
- 표준 문자 외 악센트, 도형, 특수 문자 및 기호 등 부가 문자를 128개 추가
- 확장 아스키는 1byte 내 8비트를 모두 사용
- 단, 표준 아스키가 세계적으로 통용되는 데 비해 확장 아스키는 그러지 못한 편

## 1-2. 유니코드
- 컴퓨터가 발전하며 미국 뿐 아니라 각 나라에서도 컴퓨터 발전이 시작
- 각국에서도 자국 문자를 표현하기 위해 코드체계가 만들어졌다
- 국가 사이 정보를 주고받을 때 문제가 발생하기 시작
- 다국어 처리를 위한 표준 유니코드를 만들게 됨 (이모지도 여기 속한다)

### (1) 유니코드 Character Set
- 종류
  - USC-2 (Universal Character Set 2)
  - USC-4 (Universal Character Set 4)
- 특징
  - 유니코드를 저장하는 변수 크기를 정의한 것
  - 그러나 바이트 순서에 대해 표준화하지 못했다
  - 또한 파일을 읽을 때 UCS-2인지 4인지 인식하고 각 경우를 구분해 모두 다르게 구현해야 하는 문제 발생
    - 그래서 유니코드의 적당한 외부 인코딩이 필요하게 됨


### (2) 바이트 단위 저장 순서
> 여러 바이트로 이뤄진 데이터를 저장하는 방식을 'Endian'이라고 함

![](https://velog.velcdn.com/images/paramad/post/eca97a47-70b4-4b77-a5d5-529dfd0f8ea1/image.png)

- Big-endian : 상위 바이트(MSB; Most Significant Byte)를 가장 낮은 주소에 저장
- Little-endian : 하위 바이트(LSB; Least Significant Byte)를 가장 낮은 주소에 저장
- 예시 (`0x12345678`를 4바이트 데이터에 저장)
  - Big-endian : 12, 34, 56, 78로 저장
  - Little-endian : 78, 56, 34, 12로 저장

### (3) 유니코드 인코딩 (UTF; Unicode Transformation Format)
- UTF-8 (in web)
  - MIN : 8비트, MAX : 32비트 (1byte * 4)
  - 저장 예시
    - `0xxxxxxx` 1바이트
    - `110xxxxx 10xxxxxx` 2바이트
    - `1110xxxx 10xxxxxx 10xxxxxx` 3바이트
    - `11110xxx 10xxxxxx 10xxxxxx 10xxxxxx` 4바이트
  - Python 인코딩
    - 2.x 버전은 기본 인코딩 방식이 ASCII라 첫 줄에 `#-*- coiding: utf-8 -*-`를 써줘야 함
    - 3.x 버전은 utf-8이 디폴트라 표시 생략해도 됨
    - **만약 다른 인코딩 방식으로 처리하고 싶다면 첫 줄에 인코딩 방식을 써주면 된다**
- UTF-16 (in windows, java)
  - MIN : 16비트, MAX : 32비트 (2byte * 2)
- UTF-32 (in unix) : 인덱스 접근이 빠르지만 메모리 낭비가 심함 (4바이트 고정 길이기 때문)
  - MIN : 32비트, MAX : 32비트 (4byte * 1)

#### 인코딩 예
PyCharm이나 VSCode에서 하단을 보면 인코딩 방식을 볼 수 있다
- Line Seperator (인코딩과는 상관이 없지만 줄 바꿈을 표시하는 문자가 다름)
  - CRLF : Classic macOS (`\r\n`)
    - 윈도우는 CR(13)과 LF(10) 두 글자를 사용한다
    - CR : 종이를 치는 장치를 맨 왼쪽으로 밀어넣는 것
    - LF : 종이를 한 줄 올리는 동작
    - 윈도우는 이 두 동작을 모두 계승함
  - LF : Unix, 현대의 macOS (`\r`)
    - Unix와 macOS는 LF(10) 한 글자를 사용한다
    - 리눅스(서버)에서 짠 코드를 윈도우에서 열면 줄 바꿈이 안 되어 한 줄로 보이거나, 반대로 윈도우에서 짠 코드를 리눅스에서 실행하면 끝에 `^M` 같은 이상한 문자가 붙는 이유가 바로 이것 때문
- File Encoding
  - ISO-8859-1, US-ASCII, UTF-16...

인코딩 방식을 바꿔가며 저장된 파일을 읽어보면 실시간으로(?) 값이 깨지는 걸 볼 수 있다

## 2. 문자열
- 문자가 순서대로 나열된 데이터

### 2-1. 분류
- Length-Controlled 문자열
  - 문자열 길이 정보를 함께 저장해서 그 길이만큼 읽는 방식
  - Java, Python, 네트워크 패킷에 사용됨
- Delimited 문자열
  - 문자열 끝을 나타내는 특정 구분자(delimiter)가 있음
    - 그 구분자가 나올 때까지 문자열로 인식함
    - ex) `Hello\0`
  - C언어는 `null`, `\0`을 사용함

#### 파이썬 str 클래스 구조
길이 외에 다른 정보도 저장한다
• `PyObject_HEAD`: 모든 Python 객체가 상속하는 공통 구조
• `length`: 문자열의 길이
• `hash`: 문자열의 해시값. 딕셔너리 키로 쓸 때 사용된다
• `interned`: 같은 문자열을 관리하는 플래그
• `kind`: 문자열 인코딩 크기
• `data`: 문자열이 저장된 실제 메모리 주소를 가리키는 포인터


### 2-2. 각 언어에서의 문자열
#### (1) C언어에서 문자열
* 항상 마지막에 끝을 표시하는 널문자(`'\0'`) 필요
  - `char ary[] = "abc";`
  - `char ary[] = {'a', 'b', 'c', '\0'};`
* 문자열 처리에 필요한 연산을 함수 형태로 제공함
  * `strlen()`, `strcpy()`, `strcmp()`, …

#### (2) Java에서의 문자열
* 문자열 데이터를 저장, 처리해주는 클래스를 제공함
  * `String` 클래스.
    * `String str = "abc";`
    - `String str = new String("abc");`
* 문자열 처리에 필요한 연산을 연산자, 메소드 형태로 제공함
  * `+`, `length()`, `replace()`, `split()`, `substring()`, …

#### (3) Python3에서의 문자열
* 텍스트 데이터의 취급 방법이 통일되어 있음
  * 바이트 문자열과 Unicode 구분이 없음 (Python2에서 업그레이드 되면서 괜찮아짐)
  * 유니코드(Unicode) 기반이라 어떤 언어나 기호도 동일한 방식으로 처리 
* 문자열 기호
  * `'` (홑따옴표), `"` (쌍따옴표), `'''` (홑따옴표 3개), `"""` (쌍따옴표 3개)
* 연산
  * `+` 연결(Concatenation)
    * 문자열 + 문자열 : 이어 붙여주는 역할
    * 예) `'ab' + 'c'`
  * `*` 반복
    * 문자열 * 수 : 수만큼 문자열이 반복
    * `'ab' * 3`
* 문자열은 데이터의 순서가 구분되는 시퀀스 자료형으로 분류
  * 즉, 시퀀스 자료형에서 사용할 수 있는 인덱싱, 슬라이싱 연산들을 사용할 수 있다
* 문자열 클래스에서 제공되는 메소드.
  * `replace()`, `split()`, `isalpha()`, `find()`
* 문자열은 튜플과 같이 요소값을 변경 할 수 없음 (immutable)


```python
# 인덱싱 사용
s = 'abc'
print(s[1])

# 요소값 변경 불가
s = 'abc'
s[1] = 'a'   // TypeError: 'str' object does not support item assignment
```

## **2-3. 비교**

* 비교 연산자 `<` 사용
  * 문자열에 대한 `<` 연산은 유니코드 값에 대한 비교
    - `'Apple' < 'apple'`도 `True`, `'Zebra' < 'apple'`도 `True`다

### (1) 두 문자열의 사전상 순서를 비교하는 `my_strcmp()` 함수

```python
def my_strcmp(s1, s2):
    if s1 < s2:
        return -1      # s1이 s2보다 사전 순서상 앞서는 경우
    elif s1 > s2:
        return 1       # s1이 s2보다 사전 순서상 나중인 경우
    else:
        return 0       # s1과 s2 문자열의 내용이 같은 경우

```

## 3. 패턴 매칭
### 3-1. 고지식한 알고리즘 (Brute Force)

* **단순한 방법**
  * 본문 문자열을 처음부터 끝까지 차례대로 순회하면서 패턴 내의 문자들을 일일이 비교하는 방식입니다.

#### 구현 원리

* **본문의 비교위치 i, 패턴에서의 비교위치 j**
  * 문자가 일치하면 **i, j를 모두 증가**시킵니다.
  * 비교에 실패하면 **i는 이전 시작 위치의 다음으로** 이동하고, **j는 맨 앞(0)으로 초기화**합니다.

#### 구현 코드

```python
def brute_force(p, t): # p: 찾을 패턴, t: 본문 문자열
    # 패턴이 있으면 시작 인덱스, 없으면 -1 리턴
    i = 0 # t의 인덱스
    j = 0 # p의 인덱스
    M = len(p)
    N = len(t)
    
    while j < M and i < N:
        if t[i] != p[j]:    # 다른 글자인 경우
            i = i - j
            j = -1
        i = i + 1
        j = j + 1
        
    if j == M: 
        return i - M        # 검색 성공
    else: 
        return -1           # 검색 실패

```

#### 시간 복잡도

* 최악의 경우 텍스트의 모든 위치에서 패턴을 비교해야 하므로 **$O(MN)$**이 됨
  * **예시:** 길이가 10,000인 문자열($N$)에서 길이 80인 패턴($M$)을 찾는 경우
* 최악의 경우 약  $10,000 \times 80 = 800,000$  번의 비교가 필요

### 3-2. KMP 알고리즘
> 불일치가 발생했을 때, 이미 비교한 정보를 활용해 거꾸로 되돌아가지 않고 앞으로만 나아가는 효율적 방식

  * **핵심 아이디어**: 패턴의 접두사와 접미사가 일치하는 특성(LPS)을 이용해 비교가 불필요한 부분을 건너뜁니다.
  * **LPS(Longest Prefix which is also Suffix) 배열**:
    * 패턴의 각 위치에서 매칭 실패 시 돌아갈 위치를 미리 계산한 전처리 배열입니다.
    * 구현에 따라 `next` 또는 `pi` 배열로도 불립니다.
 * **시간 복잡도**: 전처리 $O(M)$, 본문 검색 $O(N)$으로 총 **$O(M+N)$**이 소요됩니다.

### 3-3. 보이어-무어 (Boyer-Moore) 알고리즘
>패턴의 오른쪽 끝부터 왼쪽 방향으로 비교하며, 상용 소프트웨어에서 가장 많이 채택되는 매우 빠른 알고리즘입니다.

* **동작 특징**:
  * 패턴의 오른쪽 끝 문자가 본문과 다르고 그 문자가 패턴 내에 아예 없다면, 패턴 길이만큼 한 번에 점프합니다.
* **불일치 문자 휴리스틱 (Bad-Character Heuristic)**:
  * 오른쪽 끝 문자가 불일치하지만 패턴 내부에 그 문자가 존재한다면, 가장 오른쪽에 있는 해당 문자의 위치에 맞춰 점프합니다.

## 4. 문자열 매칭

각 알고리즘은 성능과 구현 복잡도에 따라 사용처가 다르다.

| 알고리즘 | 수행 시간 (패턴 $m$, 전체 $n$) | 특징 |
| --- | --- | --- |
| **고지식한 패턴 검색** | $O(mn)$ | 본문 문자열을 처음부터 끝까지 순회하며 일일이 비교합니다. |
| **카프-라빈** | $\Theta(n)$ | 해싱을 이용한 매칭 방식입니다. |
| **KMP** | $\Theta(n)$ | 불일치 발생 시 이미 비교한 정보를 활용하여 전방으로만 이동합니다. |
| **보이어-무어** | 일반적으로 $\Theta(n)$ 미만 | **상용 소프트웨어(grep, VS Code 등)에서 주로 채택**하며 가장 빠른 성능을 보입니다. |

* **고지식한 패턴 검색 (Brute Force)**: 수행 시간 $O(mn)$으로, 모든 경우를 다 비교하는 단순한 방식입니다.
* **카프-라빈 (Karp-Rabin)**: 해싱을 이용하며 수행 시간 $\Theta(n)$을 가집니다.
* **KMP 알고리즘**: 패턴의 접두사와 접미사가 일치하는 최대 길이인 **LPS(Longest Prefix which is also Suffix) 배열**을 전처리하여 비교를 건너뜁니다.
  - 매칭 실패 시 돌아갈 위치(LPS 배열)를 전처리하여 수행 시간 $\Theta(n)$을 달성합니다.
* **보이어-무어 (Boyer-Moore)**:
  * **오른쪽 끝에서 왼쪽 방향**으로 비교하며, 불일치 시 패턴 내 문자의 존재 여부에 따라 점프합니다.
    - **Skip 배열**과 **불일치 문자 휴리스틱**을 사용합니다.
  * 텍스트의 문자를 모두 읽지 않아도 되므로 일반적인 경우 $\Theta(n)$보다 빠릅니다.
  * **grep, VS Code, JVM** 등 상용 소프트웨어에서 널리 사용됩니다.


### 4-1. 암호 체계
#### (1) 시저 암호 (Caesar Cipher)

* **정의**: 평문에서 사용되는 알파벳을 일정한 문자 수만큼 **평행이동**시켜 암호화하는 방식입니다.
* **예시 (키 값 = 1)**:
	* 평문: `S A V E`  암호문: `T B W F`
* **암호 해독 (전사 공격)**: 모든 가능한 키 값(보통 1~25)을 차례로 대입하여 의미 있는 문장이 나오는지 시도하여 해독할 수 있습니다.
  * 모든 키 값을 대입해 보는 **전사 공격(Brute-force attack)**에 취약합니다.

#### (2) **단일 치환 암호 (Substitution Cipher)**

>  알파벳 하나를 다른 고정된 알파벳으로 바꾸는 방식

* **복호화의 어려움**: 가능한 키의 조합이  (약 4000억의 100조 배 이상)로 매우 많아 전사 공격이 사실상 불가능하다.
* **빈도 분석 공격**: 텍스트에서 가장 자주 등장하는 글자(예: 영어의 E, T, A)를 추정하여 해독할 수 있다.
  * *역사적 사실*: **앨런 튜링**은 '봄브(Bombe)'를 개발해 에니그마 암호를 해독했으며, 이는 최초의 디지털 컴퓨터 **콜로서스** 탄생의 계기가 되었다.


### 4-2. 문자열 압축 (String Compression)**

데이터 효율성을 높이기 위한 두 가지 대표적인 알고리즘.

1. **Run-length Encoding**: 같은 값이 몇 번 반복되는지 나타내는 방식입니다 (예: `AAAAA`  `A5`). BMP 파일 등의 압축에 사용됩니다.
2. **허프만 코딩 (Huffman Coding)**:
    * 자주 나오는 문자에는 짧은 이진 코드를, 드문 문자에는 긴 코드를 부여합니다.
    * 전체 데이터의 평균 비트 수를 최소화하는 가장 효율적이고 일반적인 압축 방법입니다.
