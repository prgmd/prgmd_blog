# Chapter 7. Tokenizer
## 1. 토크나이저(Tokenizer)
### 1-1. 토크나이저의 개념
> 인간의 언어(문장)를 인공지능 모델이 처리할 수 있는 수치 리스트(Index List)로 변환하는 도구. 문장을 토큰 단위로 자른 다음 수로 변환한다. (토큰 단위는 툴마다 다르다)

`'안녕하세요'` → `['안녕', '하세요']` → `[8192, 91352]`

머신러닝의 기본 수식인 $y = wx + b$에서 문장은 입력값 x에 해당하지만, 모델은 텍스트를 직접 계산할 수 없으므로 반드시 수치화 과정이 선행되어야 함.

### 1-2. 동작 원리
1. 분석하고자 하는 **원문 텍스트 입력**
2. 문장을 더 이상 쪼개기 어려운 의미 단위로 **토큰화(Tokenization)**.
3. **미리 학습된 사전(Vocabulary)**을 참조하여 각 토큰을 **고유한 정수(ID)로 매핑(인덱싱)**.

#### 왜 이렇게 하나요?
문장 전체에 고유 번호를 부여하는 방식은 불가능. 세상의 모든 문장을 사전에 등록할 거 아닌 이상... 심지어 조합도 무한대. 그래서 문장을 토큰 단위로 자르는 것.

#### Vocabulary는 어떻게 만들어졌나요?
대규모 텍스트 데이터를 이용하여, 많이 등장하는 글자나 바이트를 알아내고, 자주 함께 등장하는 조합을 찾아냄. 그리고 이러한 조합을 토큰으로 등록시키고 인덱스 번호를 부여한 것. (이러한 사전을 만드는 작업을 Tokenizer Training이라고 한다)

### 1-3. Tokenizer Training
토크나이저 트레이닝에는 대표적으로 2개가 있음.

#### ① Word Piece 알고리즘
- **핵심 단위**: 글자(Character) 단위 분할
- **선정 기준**: 빈도 기반으로 **점수 측정 후 점수가 좋은 조합을 찾아냄**
- **대표 모델**: BERT 등 (이전 세대 표준)
  - BERT는 트랜스포머 구조를 응용해 매우 우수한 언어 모델을 만들어낼 수 있다는 걸 세상에 알린 유명한 모델. 등장과 함꼐 NLP(자연어처리) 벤치마크 점수의 신기록을 압도적으로 갈아 치웠다. (물론 지금은 잘 안 쓰인다)
  - BERT 자체가 유명해져, Word Piece 방식으로 만든 사전을 'BERT Tokenizer'라고 부른다.
  - 특징으로는 `##`가 자주 등장한다는 점. `##하다` 식으로 표현해서 **앞에 다른 글자가 붙는다는 걸 표현**한다는 특징을 가진다.
- **다국어 대응**: 언어별 별도 학습 필요 (한글 지원 약함)
- **특징**: 한글 토큰화 결과가 가독성이 좋음

※ NLP(자연어처리) : 컴퓨터가 인간의 말을 이해하고 분석하는 AI 분야.

#### ② Byte-Level BPE 알고리즘
- **핵심 단위**: 바이트(Byte) 단위 분할
- **선정 기준**: 단순 **빈도(Frequency)가 높은 조합을 찾아냄**
- **대표 모델**: GPT, Claude, Gemini, Qwen (현대 표준)
  - 유명한 모델이 많기 때문에 Byte-Level BPE 알고리즘을 사용해 만든 토크나이저는 그냥 'Byte-Level BPE Tokenizer'라고 부른다.
- **다국어 대응**: 모든 언어에 범용적 대응 가능 (UTF-8 기준)
- **특징**: 내부적으로 Latin-1 문자를 사용하여 가독성 낮음
  - Character-Level BPE가 따로 있다.

※ Sentence Piece 역시 유명한 토크나이저 프레임워크이자 라이브러리. 여러 토크나이저 알고리즘을 지원하고, 작업에 필요한 기능들을 통합해뒀다. Byte-Level BPE가 대세가 되기 전, 한국어, 일본어, 중국어의 토크나이저로 많이 사용된 프레임워크.


### 1-4. 임베딩 모델 적용
토크나이저의 등장으로 문장을 모델 입력으로 넣을 수 있게 되었지만, 같은 의미의 단어를 조금만 바꿔도 추론 성능이 떨어진다는 단점이 존재했음. 예를 들어 `나 이 영화 좋아요`는 긍정으로 구분하는데 `저 이 Movie 좋아요`는 부정으로 구분하는 식.

- 임베딩 모델을 적용하면 벡터값을 도출할 수 있음 (`나는 맥도날드가 좋아요` → `[424, 4312, 598, 66]` → `[0.2, 0.4, 0.1, 0.53, 0.652, 0.215]`)
- 이 벡터와 라벨(긍정)을 모델에 넣어 학습을 시킴
- 이후 이러한 문자열이 입력되었다고 가정 (`Im은 McDonald를 Like해요` → `[693, 1204, 329, 1926, 543, 1232]`)
- 학습한 임베딩 모델을 거치면 비슷한 벡터값이 만들어지는 것을 볼 수 있음 (`[693, 1204, 329, 1926, 543, 1232]` → `[0.2, 0.3, 0.1, 0.54, 0.615, 0.215]`)

### 1-5. 풀링(Pooling)
> 문장을 토큰화하면 토큰 개수(N)만큼의 벡터가 생성되는데, 문장 전체의 의미를 추출하기 위해서는 이 N개의 벡터를 하나의 대표 벡터로 합쳐야 함. 이를 풀링이라 함.

가장 널리 쓰이는 방식은 모든 토큰 벡터의 평균값을 구하는 Mean Pooling.

#### 풀링 과정
- `사과는 맛있다`를 토큰화 → `[사과', '는', '맛있다']` → `[75, 899, 499]`
- 각 토큰을 임베딩 모델을 통해 벡터화 → `[[0.5, 0.1, 0], [0.1, 0, 0.4], [0, 0.6, 0.1]
- 평균으로 풀링 → `[0.2, 0.35, 0.16]`

### 1-6. 임베딩 모델과 본 모델
참고로 임베딩 모델과 본 모델은 따로 학습하는 편이다. 보편적으로 범용적인 버전의 임베딩 모델을 먼저 학습시킨 다음, 임베딩 모델의 파라미터가 변경되지 않도록 고정한 뒤 추가 레이어(본 모델)를 설치한다. 이후 본 모델을 학습시키는 방식.


## 2. 허깅페이스
> AI 모델의 'GitHub'과 같은 오픈 소스 생태계. transformers 라이브러리를 통해 전 세계 전문가들이 공유한 모델과 토크나이저를 단 몇 줄의 코드로 불러올 수 있다.

### 2-1. AutoTokenizer의 활용
``` python
from transformers import AutoTokenizer

# 1. 모델 로드 (Hugging Face Repository ID 사용)
model_id = "klue/bert-base"
tokenizer = AutoTokenizer.from_pretrained(model_id)

# 2. 토큰화 프로세스 상세
text = "저는 맥도날드에 다녀왔어요."

# tokenize(): 문자열을 토큰 단위 리스트로 분리
tokens = tokenizer.tokenize(text) 

# convert_tokens_to_ids(): 토큰 문자열을 사전 기반 인덱스(숫자)로 변환
ids = tokenizer.convert_tokens_to_ids(tokens)

# decode(): 숫자 리스트를 다시 인간이 읽을 수 있는 문장으로 복원
decoded_text = tokenizer.decode(ids)
```


## 3. 벡터 유사도 측정
### 3-1. 코사인 유사도(Cosine Similarity)
> 고차원 공간에서는 벡터의 '거리'보다 **'방향성'**이 유사도를 판단하는 더 정확한 기준이 됨. 두 벡터 사이의 각도를 이용해 계산하며, 수학적 특성상 NLP 모델에서 유사도 값은 0.5 ~ 0.9 사이의 범위를 가진다.

일반적인 기준에서는 이해가 잘 안 갈지 모르겠지만, 허깅페이스에서 사용 가능한 `intfloat/e5-small-v2` 모델은 384차원. 

$\text{Cosine Similarity}(A, B) = \frac{A \cdot B}{\|A\| \|B\|}$
- A와 B는 비교하고자 하는 두 벡터고, $A \cdot B$는 내적(각 성분끼리 곱한 후 모두 더한 값), $\|A\|, \|B\|$는 각 벡터의 크기다.
- 이 때, 만약 A와 B의 크기가 각각 1이라면 코사인 유사도 계산이 엄청 쉬워진다. 즉, **행렬의 크기를 1로 만들고, 방향만 남기면 계산이 쉬워진다는 뜻**


### 3-2. L2 정규화(L2 Normalization)
> 벡터의 크기(길이)를 1로 만드는 과정. 모든 벡터의 크기가 1이 되면, **'내적(Dot Product) = 코사인 유사도'**가 되어 계산이 매우 단순하고 빨라진다.

- LLM (거대모델)의 경우 벡터의 크기 자체가 정보의 중요도나 확신을 의미하므로 정규화를 하면 안 된다.
- 하지만 이미지나 텍스트 검색의 경우 순수하게 '주제(방향)'의 유사성만 찾는 것이 중요하기 때문에 L2 정규화를 적극 활용한다. RAG에도 사용함.

### 3-3. Qwen3 & Sentence Transformers

Alibaba의 Qwen3-Embedding 모델은 소형이면서도 한국어와 다국어 처리 능력이 뛰어난 최신 임베딩 모델. 풀링과 정규화 과정을 자동화하여 편리하게 실습할 수 있다.

``` python
import torch
from sentence_transformers import SentenceTransformer

# 모델 로드 (Pooling 및 Normalization 자동 적용)
model = SentenceTransformer("Qwen/Qwen3-Embedding-0.6B")

# 비교 대상 데이터
queries = ["스토리가 정말 흥미진진해요!", "기대했는데 실망했어요."]
documents = ["Positive", "Negative"]

# 임베딩 생성 (Qwen3는 prompt_name='query' 설정 시 성능 향상)
query_emb = model.encode(queries, prompt_name="query")
doc_emb = model.encode(documents)

# 코사인 유사도 계산
similarity = model.similarity(query_emb, doc_emb)

# 가장 유사한 인덱스 추출 (Prediction)
max_indices = torch.argmax(similarity, dim=1).tolist()

for i, q in enumerate(queries):
    print(f"입력: {q} ---- 결과: {documents[max_indices[i]]}")
```
