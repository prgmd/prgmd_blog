## 1. 도커 컴포즈 (Docker Compose)

> Dockerfile이 **단일 애플리케이션 이미지를 만드는 도구**라면, 도커 컴포즈는 여러 개의 컨테이너로 구성된 **서비스 전체를 한 번에 관리하는 도구**.

* 시스템 구축 명령어들을 YAML 파일로 기재해 전체 시스템을 일괄 실행할 수 있다.
  * 예를 들어 `docker run` 등의 주변 환경 설정이 모두 가능.
* 네트워크와 볼륨 정의도 포함 가능. 복합 애플리케이션 스택 관리에 유리하다.
  * Dockerfile은 네트워크나 볼륨 생성이 불가능.

### 1.2 주요 명령어

* `up`: 정의된 이미지를 내려받고 컨테이너를 생성 + 실행. `-d` 옵션 붙이면 백그라운드 실행 모드.
* `down`: 실행 중인 컨테이너와 네트워크를 정지하고 삭제. (볼륨, 이미지는 유지함)
* `stop`: 삭제 없이 컨테이너만 종료함.
* `ps`: 컨테이너 상태 확인
* `logs -f`: 로그 확인 (문제 발생시 체크할 것)

### 1.3 구성 요소
#### 전역 설정

* `version`: Compose 파일 규격의 버전 (예: '3.8'). 버전에 따라 지원하는 옵션이 다르므로 명시가 필요함.
* `services`: 이 파일에서 관리할 컨테이너들의 집합을 정의하는 최상위 노드.
* `networks`: 컨테이너들끼리 통신하기 위한 가상 네트워크 정의. (미지정 시 기본 네트워크 생성)
* `volumes`: 데이터를 영구 저장하기 위한 공유 저장소 정의.

#### 서비스 정의 - 컨테이너 단위

* **빌드 및 이미지**
  * `image`: 도커 허브나 프라이빗 레지스트리에서 가져올 이미지 이름을 지정.
  * `build`: 로컬의 Dockerfile을 사용하여 직접 빌드할 때 경로를 지정. (build: .)
* **네트워크 및 포트**
  * `ports`: `[호스트 포트]:[컨테이너 포트]` 형태로 외부 접속 허용. (예: `8080:80`)
  * `expose`: 호스트에는 노출하지 않고, 컨테이너들끼리만 통신할 포트 지정.
* **볼륨 및 마운트**
  * `volumes`: `[호스트 경로]:[컨테이너 경로]` 형태로 연결하여 컨테이너 삭제되어도 데이터 유지.
  * `configs` / `secrets`: 설정 파일이나 비밀번호 같은 민감 정보를 안전하게 관리할 때 사용합니다.
* **실행 제어 (Execution Control)**
  * `container_name`: 컨테이너 고유 이름 강제 지정.
  * `restart`: 컨테이너 종료 시 재시작 정책. (`always`, `on-failure`, `no` 등)
  * `depends_on`: 서비스 간 실행 순서 정의. 의존성을 관리한다고 보면 된다. (예: DB가 뜬 후 App 실행)
    * 하지만 DB의 경우 반드시 `healthcheck`을 해줘야 한다. **왜냐면 DB가 띄워진다 해도 실제로 쿼리를 받을 준비가 되려면 시간이 좀 필요하기 때문**
  * `command`: 이미지의 기본 실행 명령어를 덮어씀.

#### 환경 설정 (Environment)

* `environment`: 직접 환경 변수를 키-값 형태로 주입합니다.
* `env_file`: 별도의 `.env` 파일에 변수를 모아두고 읽어올 때 사용합니다.

### 1.4 예시

```yaml
version: '3.8'

services:
  # 서비스 이름 (사용자 정의)
  app:
    # 사용할 이미지
    image: nginx:latest
    
    # 컨테이너 이름 설정 (생략 시 자동 생성)
    container_name: my-web-server
    
    # 포트 포워딩 [호스트 포트]:[컨테이너 포트]
    ports:
      - "8080:80"
    
    # 볼륨 마운트 [호스트 경로]:[컨테이너 경로]
    volumes:
      - ./html:/usr/share/nginx/html
    
    # 환경 변수 설정
    environment:
      - NODE_ENV=production
    
    # 컨테이너 종료 시 재시작 정책
    restart: always
```

### 1.5 환경 변수 설정 방법

#### 직접 입력 (Hard-coding)

>`environment` 속성에 `KEY: VALUE` 형태로 직접 기재. 편하긴 한데, 당연히 보안은 취약... 공개되어도 무방한 일반 설정에만 사용하자 (타임존 설정 같이... `TZ=Asia/Seoul`) 그래도 Dockerfile 직접 삽입하는 방식보다는 컨테이너 실행 시점에 결정되므로 수정 자체는 편한 편.

#### Shell 환경 변수 (Dynamic Reference)

호스트 OS 터미널에서 `export`로 변수를 선언하고, YAML 파일에서는 `${변수명}`으로 호출. 다른 방식보다 우선순위가 높아 `.env` 파일 값을 덮어쓸 때 유용하다. 설정 파일 자체에 값이 남지 않아 흔적도 깔끔.

#### 환경 변수 파일 (.env)

프로젝트 루트에 `.env` 파일 생성하고 변수 따로 관리. 이게 실무 표준 방식이다. 배포 환경에 따라 파일만 교체하면 되므로 유연한 편. 대신 `.gitignore` 등으로 Git 같은 외부망에 노출되지 않도록 늘 항상 신경을 잘 써야 한다.

#### Dockerfile 삽입 (Fixed Default)

이미지 빌드 단에서 `ENV` 명령어를 사용해 변수를 이미지 내부에 박아 넣음. 이미지 자체가 값을 들고 있어 별도 설정 없이도 실행이 가능하다! 대체로 이미지 기본갑 설정시에 사용하는 편 (소프트웨어 버전이나 설치 경로, 타임존 등) 하지만 당연히 보안도 낮고, 가장 큰 문제는 **값을 수정하려면 이미지를 다시 빌드해야 함**...

* 그래서 대체로 Dockerfile에 `ENV`로 직접 `localhost` 기본값을 설정해두고 추후 `environment`로 오버라이드하는 기법을 자주 사용한다.
