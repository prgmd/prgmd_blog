# JavaScript

## 1. JavaScript의 역사

### 1.1 브라우저 전쟁
#### 웹의 탄생
Tim Berners-Lee가 하이퍼텍스트 시스템을 고안해 개발. URL과 HTTP 등이 이 때 처음 구현되었으며, 정적인 텍스트 페이지만을 지원했다.

![](https://velog.velcdn.com/images/paramad/post/eaaa38dc-e73f-463f-a9be-58e1d22f5127/image.png)

#### 탄생
1993년 대중화가 본격적으로 이뤄졌고, 최초 상용 웹 브라우저인 Netscape Navigator가 출시되었다. 90% 이상 시장 점유율을 가졌고, 웹의 동적 기능을 만들기 위해 프로젝트를 시작해 1995년 JavaScript를 탄생시킴. Netscape 소속 개발자 Brendan Eich는 회사 요구사항인 웹의 동적 기능 개발을 넘어 스크립트 언어인 Mocha를 개발. 이후 LiveScript로 이름을 바꿨다가, 당시 가장 인기였던 Java에 명성에 기대고자 JavaScript로 이름 변경. 이후 Netscape Navigator 2.0에 탑재되어 동적 기능 추가에 쓰였다.

#### 파편화
1996년 Microsoft가 IE 3.0에 유사한 JScript를 도입. 이때부터 여러 회사가 독자적으로 JavaScript 규격을 변경하며 자체 브라우저에 탑재하기 시작했다.

#### 1차 브라우저 전쟁
심지어 Microsoft는 빌 게이츠를 필두로 공격적인 마케팅과 자금력을 내세우고, IE를 자사 Windows OS에 내장에 무료로 배포했기에, Netscape는 빠르게 몰락하기 시작. 결국 2002년에 이르러 시장 점유율은 IE가 96% 달성. 훗날 Brendan Eich와 Netscape의 핵심 개발진은 Mozilla 재단을 설립해 2003년 Firefox 브라우저를 출시했다.

웹 표준이 부재했기에 각 기업에서 자체 표준을 확립하려는 상황이 발생했고, 이 때문에 웹 개발자들은 큰 혼란을 겪었다.

#### ECMAScript

![](https://velog.velcdn.com/images/paramad/post/1a3293c5-d8a6-4620-8d6f-e6751e43f0fa/image.png)

1997년 JavaScript의 파편화를 막기 위해 Netscape 사는 ECMA 재단에 웹 표준 제작 요청. 이후 ECMA에서 ECMAScript 표준 언어를 정의해 발표. **스크립트 언어가 준수해야 하는 규칙과 세부사항을 정의했다.** 이후 JavaScript는 이를 기반으로 발전하기 시작했다.

#### 2차 브라우저 전쟁

![](https://velog.velcdn.com/images/paramad/post/d1078900-66f3-4c36-8f35-b34923a57bca/image.png)

하지만 당시 가장 높은 점유율을 가진 IE가 웹 표준을 지키지 않으면서, 이에 대해 Firefox가 대항하기 시작했다. 2008년까지 30%까지 점유율을 끌어올리는 데 성공. 이후 2008년 Google의 Chrome이 출시되면서 3년 만에 Firefox를 넘어서고, 그로부터 반년 뒤 IE의 점유율까지 넘어섬.

Chrome이 시장 우위를 점하게 된 데는 빠른 성능과 다양한 플랫폼 지원, Google과의 생태계 통합 등이 있지만, 가장 결정적인 이유는 적극적인 웹 표준 준수. 사용자들은 브라우저 간 일관된 웹 페이지를 볼 수 있었고, 다양한 플랫폼 및 기기에 호환되는 환경을 지원했다. 강력한 개발자 도구를 제공해 웹 개발자들에게 큰 도움을 준 것도 유효.

Chrome은 단순 표준만 잘 지킨 것이 아니라 자체 개발한 V8 JavaScript 엔진으로 압도적인 성능을 보임. 이후 다른 브라우저 제조사들도 웹 표준 준수의 중요성을 인식하며 Chrome의 방식을 따라가기 시작했다.

### 1.2 ECMAScript
JavaScript는 ECMAScript의 명세를 기반으로 웹 브라우저나 Node.js 환경에서 실행된다. 즉, ECMAScript와 JavaScript의 관계는 **표준 - 표준을 따르는 구체적인 프로그래밍 언어**라 볼 수 있다. 

2009년 ES5에서 안정성과 생산성이 크게 올랐고, 2015년 ES6에서 객체지향 프로그래밍 언어를 적극 도입. 역사상 가장 중요한 버전으로 평가받는다. JavaScript 공부 역시 ES6 이후 문법을 기준으로 공부한다고.

[권장 스타일 가이드](https://standardjs.com/rules-kokr)

### 1.3 JavaScirpt의 미래
2009년 Node.js의 출시로 브라우저 외부에서도 실행이 가능해지면서 단순 '웹 페이지 동작 구현'을 넘어 서버 사이드 개발에도 사용되기 시작했다. 다양한 프레임워크와 라이브러리들이 붙으면서 이제는 웹 개발 분야에서 필수적인 언어로 자리 잡게 됐다.

## 2. JavaScript 개요
### 2.1 변수 작성 규칙
- 반드시 문자, 그 외 특별한 용도는 달러 `$`, 밑줄 `_`로 시작할 것
- 의미가 드러나는 이름을 사용할 것
- 대소문자를 구분할 것
- 예약어 사용 불가 (`for`, `if`, `function` 등)
- 카멜 케이스는 변수, 객체, 함수에 사용할 것
- 파스칼 케이스는 클래스, 생성자에 사용할 것
- 대문자 스네이크 케이스는 상수에 사용할 것

### 2.2 변수 선언 키워드
블록 스코프를 갖는 지역 변수 선언 방식에는 2가지가 있다.

- `let`: 재할당이 필요한 변수
  - 예제
    - `let number = 10`: 선언 및 초기값 할당
    - `number = 20`: 재할당이 가능함
    - ~~`let number = 20`~~: 재선언은 불가능
- `const`: 재할당이 불가능한 상수. 
  - 예제
    - `const number = 10`: 선언 및 초기값 할당
    - ~~`number = 10`:~~ 재할당 불가능
  - 특징
    - **대체로 const 사용을 권함**
    - 코드의 의도가 명확해짐 (변수 재할당 안 할 겁니다)
    - 버그 예방 (팀 작업에서 의도치 않은 변수 값 변경 방지)
    - `let`을 사용한다는 뜻은 즉 **변수가 의도적으로 변경될 수 있음**을 뜻하는 것.

#### 블록 스코프
`if`, `for` 함수 등의 중괄호 내부를 가리킨다. 블록 스코프 변수는 블록 바깥에서 접근이 불가능함.

#### `var`
~~`var`~~: 호이스팅 문제로 더이상 사용을 권장하지 않음
- 호이스팅: 코드가 실행되기 전 변수 및 함수 선언문이 스코프의 최상단으로 끌어올려지는 듯한 현상.
- 변수 선언시 다만 어떠한 키워드도 사용하지 않으면 자동으로 var로 선언된다.
- 재할당, 재선언이 가능하며 함수 스코프를 가진다.
  - 함수 스코프: 함수의 중괄호 내부를 가리키며, 함수 스코프를 가지는 변수는 함수 바깥에서 접근이 불가능함.
  
자바스크립트는 코드를 한 번 쭉 읽어보면서 변수 선언문과 함수 선언문만 골라내 메모리에 등록한다. 이 과정에서 변수 선언 → 초기화(메모리 공간 확보) → 할당(실제 값 넣음) 단계로 생성되는 것. `var`로 선언한 변수는 선언과 초기화를 동시에 진행해 버리고 즉시 `undefined` 값을 채워 넣는다. 그래서 변수 선언 문장 이전에 접근해도 에러가 나지 않고, `undefined`를 반환한다.

> 일시적 사각지대(TDZ; Temporal Dead Zone): 스코프의 시작 지점부터 변수의 초기화가 이뤄지는 지점(실제 코드 선언부)까지의 구간

함수 선언문 `function a() {}`는 `var`보다 더 강력하게 호이스팅 됨. 선언 전에도 함수를 문제 없이 호출할 수 있다.

## 3. DOM
> 웹 페이지를 구조화된 객체로 제공해 프로그래밍 언어가 **페이지 구조에 접근할 수 있는 방법을 제공**. 문서 구조, 스타일, 내용을 변경할 수 있도록 한다.

HTML 문서는 여러 상자가 중첩된 구조. 각 상자는 **객체**이며, 이 객체와 상호작용해 어떤 HTML 태그를 나타내고 어떤 콘텐츠가 포함되어 있는지 알아낼 수 있다. 이를 **객체 모델(Document Object Model), DOM이라고 부른다.** 페이지 요소들을 객체 형태로 제공하고, 관련된 메서드를 함께 제공한다. 

핵심은 **DOM API**. 이를 통해 **다른 프로그래밍 언어가 웹 페이지에 접근하고 조작할 수 있다.** DOM 조작은 웹 페이지에 실시간으로 반영되어 **사용자와 상호작용하는 동적 페이지를 만든다.** 사용자 클릭 및 키보드 입력 같은 이벤트를 감지하고 이에 반응하는 것.

개발자 도구에서 Elements, Properties로 들어가면 선택한 해당 요소의 DOM 속성을 확인할 수 있다.

### 3.2 DOM 트리
HTML 태그들의 관계를 나무 모양으로 만든 계층 구조. 각 노드는 자식 노드를 가질 수 있고, 객체 간 상속 구조도 존재한다. 

![](https://velog.velcdn.com/images/paramad/post/e7fc6d86-7399-4ccd-bce3-19be9b02ee53/image.png)

#### 노드
DOM의 기본 구성 단위로써, DOM 트리의 각 부분은 노드라는 객체로 표현된다. DOM 메서드를 사용해 선택한 여러 노드의 목록은 NodeList라고 부름. (배열과 유사한 성질을 가진다. 인덱스로 각 항목 접근이 가능하고, 배열 메서드 사용도 가능하다)

#### Element
노드의 하위 유형. HTML 태그들(`<p>`, `<div>`, `<span>`, `<body>` 등)이 Element 노드를 생성한다. 노드의 속성과 메서드를 모두 갖고 있다. 모든 Element는 노드지만, 모든 노드가 Element인 건 아니다.

#### Parsing
브라우저가 문자열을 해석하 DOM Tree로 만드는 과정 (구문 분석, 해석) 

#### 세미콜론
자바스크립트는 문장 마지막에 세미콜론을 선택적으로 사용 가능. 없어도 ASI(자동 세미콜론 삽입 규칙)에 의해 삽입된다. 제작자 Brendan 또한 선택적이어야 한다고 생각했다고. 중요한 것은 팀의 스타일 가이드를 따르는 것. 즉 **일관성**.

### 3.3 유의점
웹 페이지를 동작하게 만든다는 뜻은 곧 웹 페이지를 조작하는 것. DOM 조작 순서는 다음과 같다.

1. 조작하려는 요소 선택
2. 선택된 요소를 조작

### 3.4 선택 메서드
- `document.querySelector(selector)`: 제공한 선택자(selector; 찾고 싶은 html 요소를 지정하는 검색 조건)와 일치하는 첫 번째 요소를 하나 선택한다. 없다면 null 반환
- `document.querySelectorAll(selector)`: 제공한 선택자와 일치하는 여러 요소 선택해 NodeList를 반환함.
- 선택자 예시: `.content`, `#id`...

### 3.5 DOM 조작
#### 클래스 속성 조작 `classList`
스타일링 및 상태 제어를 위한 클래스 목록을 동적으로 추가, 제거. `classList`를 통해 요소의 클래스 목록을 DOMTokenList(유사 배열) 형태로 반환한다.

- `element.classList.add()`: 지정한 클래스 값 추가
- `element.classList.remove()`: 지정한 클래스 값 제거
- `element.classList.toggle()`: 클래스가 존재하면 제거하고 `false` 반환. 존재하지 않으면 클래스 추가하고 `true` 반환

![](https://velog.velcdn.com/images/paramad/post/bcf74a64-e48f-492f-823e-bfb06b273f41/image.png)

![](https://velog.velcdn.com/images/paramad/post/623f359f-70c4-4670-9264-7c2d193731da/image.png)


#### 일반 속성 조작
`id`, `href` 등 요소의 모든 HTML 속성 값을 직접 설정, 조회.

- `Element.getAttribute()`: 해당 요소에 지정된 값 반환 (조회)
- `Element.setAttribute()`: 지정된 요소의 속성값 설정. 속성 이미 있으면 기존 값 갱신.
- `Element.removeAttribute()`: 요소에서 지정된 이름 가진 속성 제거

#### DOM 요소 조작
- `document.createElement(tagName)`: 작성한 tagName의 HTML 요소를 생성해 반환. 
  - 메모리에만 요소를 만들기 때문에 실제로는 `appendChild`로 문서에 삽입해야 화면에 보인다.
- `Node.appendChild()`: 한 노드를 특정 부모 노드의 자식 NodeList 중 마지막 자식으로 삽입. 추가된 Node 객체를 반환한다.
- `Node.removeChild()`: DOM에서 자식 노드 제거. 제거된 노드 반환.
  - 제거된 노드는 메모리에 남아있기 때문에 변수에 담아두고 활용해보자.
