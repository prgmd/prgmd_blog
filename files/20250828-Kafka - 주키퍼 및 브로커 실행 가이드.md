## 1. 카프카(Kafka) 실행 인프라 구성
카프카 시스템을 구동하기 위해서는 코디네이터 역할을 하는 주키퍼(Zookeeper)와 실제 메시지를 처리하는 카프카 브로커(Kafka Broker)가 순차적으로 실행되어야 한다.

### 1) 주키퍼(Zookeeper) 실행
주키퍼는 카프카 클러스터의 메타데이터 관리 및 노드 상태를 모니터링하는 역할을 수행한다.
* **실행 명령어**: `zookeeper-server-start.sh -daemon /opt/kafka/config/zookeeper.properties`
* **설정**: 기본적으로 제공되는 `zookeeper.properties` 설정 파일을 참조하며, `-daemon` 옵션을 통해 백그라운드에서 실행한다.

### 2) 카프카 브로커(Kafka Broker) 실행
메시지 생산자(Producer)와 소비자(Consumer) 사이에서 데이터를 중계하는 핵심 서버이다.
* **실행 명령어**: `kafka-server-start.sh -daemon /opt/kafka/config/server.properties`
* **전제 조건**: 주키퍼가 정상적으로 구동된 상태에서 실행해야 브로커가 클러스터에 정상적으로 참여할 수 있다.

## 2. 서비스 구동 상태 확인
자바 기반 프로세스의 실행 상태를 확인하는 `jps` 명령어를 활용하여 시스템이 정상적으로 동작하는지 검증한다.

### 1) 주키퍼 상태 확인
* **명령어**: `jps -vm`
* **확인 사항**: 실행 중인 프로세스 목록에서 주키퍼 관련 클래스가 포착되는지 확인하며, 사용된 가상 머신 옵션과 매개변수를 함께 검토한다.

### 2) 카프카 브로커 상태 확인
* **명령어**: `jps -m`
* **확인 사항**: 메인 메서드로 전달된 인자를 포함하여 카프카 프로세스가 활성화되어 있는지 점검한다.
