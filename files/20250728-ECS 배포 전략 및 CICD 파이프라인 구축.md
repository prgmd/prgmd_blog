## 1. ECS 배포 전략 및 오토 스케일링
서비스의 안정성을 높이고 부하에 유연하게 대응하기 위한 운영 전략이다.

### 1) Blue/Green 배포 전략
* **개요**: 현재 실행 중인 환경(Blue)과 새 버전이 배포된 환경(Green)을 동시에 운영하며 트래픽을 전환하는 방식이다.
* **장점**: 무중단 배포가 가능하며, 문제 발생 시 빠른 롤백이 가능하다. 실시간 테스트를 통해 새 버전의 안정성을 검증한 후 전체 트래픽을 전환할 수 있다.
* **적용**: ECS 태스크 정의에서 이미지 정보 등을 수정하여 새 리비전을 생성함으로써 적용할 수 있다.

### 2) 오토 스케일링 (Auto Scaling)
* **기능**: 설정한 조건에 따라 태스크의 수를 자동으로 늘리거나(Scale-out) 줄이는(Scale-in) 기능이다.
* **지표**: 주로 CPU 및 메모리 사용률, 또는 수신되는 요청 횟수를 기준으로 트리거를 설정한다.

## 2. Django 애플리케이션을 이용한 ECR & ECS CI/CD
GitHub Actions를 활용하여 이미지는 ECR에 저장하고, 컨테이너는 ECS에서 실행하는 자동화 파이프라인을 구축한다.

### 1) 프로젝트 준비 및 도커라이징
* **Django 설정**: `ALLOWED_HOSTS`를 모든 호스트(`*`)로 허용하도록 수정하고 `requirements.txt`를 생성한다.
* **도커 설정**: `Dockerfile`을 작성하고, 로컬 환경 검증을 위해 `docker-compose.yml`을 적용하여 빌드 및 실행을 테스트한다.

### 2) AWS 권한 및 자격 증명 설정
* **ECR 정책 생성**: 이미지 푸시를 위한 `ecr:PutImage`, `ecr:InitiateLayerUpload` 등의 권한이 포함된 정책을 IAM에서 생성한다.
* **OIDC 연동**: GitHub Actions에서 AWS에 안전하게 접근할 수 있도록 자격 증명 공급자를 설정하고 전용 IAM 역할을 할당한다.

### 3) GitHub Actions 파이프라인 단계
1. **Checkout & Setup**: 소스 코드를 가져오고 파이썬 환경을 구성한다.
2. **AWS Credentials**: OIDC 역할을 사용하여 AWS 자격 증명을 구성한다.
3. **ECR Login & Push**: Amazon ECR에 로그인한 후, 커밋 해시를 태그로 사용하여 이미지를 빌드하고 푸시한다.
4. **ECS 배포**: `task-definition.json` 파일에 새 이미지 ID를 주입하고, 이를 기반으로 ECS 서비스를 업데이트하여 배포를 완료한다.

## 3. 도메인 연결 및 보안(HTTPS) 적용
태스크의 유동적인 IP 대신 고정된 도메인을 통해 접근하고 보안을 강화하는 단계다.

### 1) 로드 밸런서 및 Route53 연결
* **이유**: 태스크가 재생성될 때마다 IP가 변경되므로 로드 밸런서를 통해 단일 엔드포인트를 제공해야 한다.
* **설정**: Route53에서 A 레코드를 생성할 때 별칭(Alias) 기능을 사용하여 생성된 로드 밸런서를 도메인에 연결한다.

### 2) HTTPS 보안 인증서 적용
* **인증서 발급**: AWS Certificate Manager(ACM)를 통해 도메인에 대한 인증서를 신청하고 Route53 레코드를 통해 검증한다.
* **리스너 설정**: 로드 밸런서에서 HTTPS(443) 리스너를 추가하고 발급받은 인증서를 연결하여 암호화 통신을 활성화한다.
