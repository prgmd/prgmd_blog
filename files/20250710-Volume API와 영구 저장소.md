## 1. Volume API 개요
쿠버네티스에서 데이터를 영구적으로 보관하기 위해 사용되는 스토리지 리소스는 크게 세 가지로 구분된다.

### 1) 볼륨 (Volume)
* 호스트 경로, NFS, iSCSI 등 이미 준비된 외부 저장소를 매니페스트에 직접 지정하여 사용한다.
* 쿠버네티스 내부에서 볼륨 자체를 신규로 생성하거나 삭제하는 생명 주기 관리는 불가능하며, 기존 자원을 연결하는 역할만 수행한다.

### 2) 영구 볼륨 (PersistentVolume, PV)
* 외부 스토리지 시스템과 연계하여 볼륨의 생성 및 삭제를 쿠버네티스 리소스로 관리할 수 있게 한다.
* 클러스터 관리자가 실제 물리적 스토리지 자원을 추상화하여 리소스로 등록해둔 상태를 의미한다.

### 3) 영구 볼륨 클레임 (PersistentVolumeClaim, PVC)
* 사용자가 필요한 용량과 접근 권한을 명시하여 PV에 할당을 요청하는 리소스다.
* 동적 프로비저닝을 사용하면 PVC가 생성되는 시점에 PV가 자동으로 생성되기도 한다.

## 2. Container Storage Interface (CSI)
컨테이너 오케스트레이션 엔진(쿠버네티스 등)과 다양한 외부 스토리지 시스템을 표준화된 방식으로 연결하기 위한 인터페이스다. 이를 통해 특정 벤더에 종속되지 않고 스토리지를 확장할 수 있다.

## 3. 영구 볼륨(PV) 설정 및 플러그인
PV를 생성할 때는 스토리지의 성격에 따라 다양한 항목을 정의한다.

### 1) 주요 설정 항목
* **Capacity**: 스토리지의 전체 용량 (예: 10Gi)
* **Access Modes**: 읽기/쓰기 권한 설정 (ReadWriteOnce 등)
* **Reclaim Policy**: PVC가 삭제되었을 때 볼륨을 유지(Retain)할지 삭제(Delete)할지 결정하는 정책
* **Storage Class**: 스토리지의 종류나 성능에 따른 클래스 구분

### 2) 지원 플러그인 종류
클라우드 환경(AWS EBS, GCE PD, Azure Disk)뿐만 아니라 온프레미스 환경(NFS, iSCSI, Ceph, GlusterFS) 등 다양한 스토리지 플러그인을 지원한다.

## 4. 실습 예시: GCE 볼륨 기반 PV 생성
구글 클라우드 환경의 디스크를 사용하는 PV를 생성할 때는 `gcePersistentDisk` 설정을 사용하며, 실제 클라우드상에 해당 자원이 존재해야 정상적으로 연동된다. `storageClassName`을 `manual`로 지정하여 수동으로 관리할 수 있다.
