# I. IAM

![](https://velog.velcdn.com/images/paramad/post/c65b11aa-678c-4eb5-9543-c9ad66ff71d1/image.png)

## 1. IAM 개요 및 구조

### 1-1. 기본 개념

> **AWS 리소스에 대한 액세스를 안전하게 제어하는 서비스**. 사용자 생성 및 그룹 배치를 관리한다. '누가(인증)' '어떤 권한을 가지고(인가)' AWS를 사용할지 결정하는 가상의 신분증 관리소와 같다.

#### 루트 계정
계정 생성 시 기본 생성되는 관리자 계정. 모든 문을 열 수 있는 '마스터 키'와 같으므로, 보안을 위해 일상적인 작업에는 사용하지 않으며, 개별 IAM 사용자를 만들어 사용할 것을 권장한다. 이 계정이 탈취되면 계정 내 모든 자원이 위험해진다...

### 1-2. 그룹 및 정책 원칙

* **사용자 및 그룹**: 사용자는 다수 그룹에 속할 수 있으며, 그룹은 사용자만 포함 가능. (그룹 내 그룹은 배치 불가)
  * '개발팀', '인사팀'과 같이 직무별로 그룹을 만들어 두면 신입 사원이 올 때마다 일일이 권한을 설정할 필요 없이 그룹에 넣기만 하면 된다.
* **최소 권한의 원칙**: 모든 사용자에게 모든 권한을 허용하지 않고, 작업에 필요한 최소한의 권한만 부여함.
  * 집을 수리하러 온 사람에게 현관문 열쇠만 주면 되지, 안방 금고 열쇠까지 줄 필요는 없다는 논리다.
* **인라인 정책**: 특정 사용자에게만 예외적으로 권한을 부여할 때 사용하나, 가급적 그룹 정책 활용을 권장함.
  * 개별 사용자마다 권한을 따로 주면 나중에 누가 어떤 권한을 가졌는지 파악하기 매우 힘들어지기 때문이다.
* **1인 1계정 원칙**: 사고 발생 시 누가 해당 작업을 수행했는지 추적(로깅)하기 1인 1계정 원칙을 고수.

## 2. IAM 정책과 JSON 구조

### 2-1. 정책 정의

* 사용자나 그룹의 권한은 **JSON 문서** 형태로 지정한다.

#### JSON
이름(Key)과 값(Value)으로 이루어진 데이터 형식. AWS IAM에서는 컴퓨터가 권한 유무를 빠르게 읽기 위해 사용한다. `[Visual 편집기]`를 통해 시각적으로 수정하거나 직접 JSON 코드를 편집할 수 있다.

### 2-2. JSON 구성 요소

* **Version**: 정책 언어의 버전 (예: "2012-10-17").
* **Statement**: 정책의 본체. 하나 이상의 문장으로 구성됨.
* **Sid**: 문장 식별자(선택 사항).
  * 해당 문장이 무엇을 위한 것인지 메모를 남기는 ID 값이다.
* **Effect**: 허용(Allow) 또는 거부(Deny) 여부.
  * AWS는 명시적인 거부가 허용보다 우선하며, 아무런 언급이 없으면 기본적으로 거부된다.
* **Principal**: 정책이 적용될 대상(특정 사용자의 경우).
* **Action**: 허용 또는 거부되는 서비스 작업 목록 (예: `s3:GetObject`).
  * 'S3에서 파일을 읽어오기'와 같은 구체적인 동작을 지정한다.
* **Resource**: 작업이 적용될 리소스 범위 (예: 특정 S3 버킷 ARN).
  * 권한을 행사할 구체적인 '대상'이 어디인지 명시한다.
* **Condition**: 정책이 효력을 발생하는 조건(선택 사항).
  * '특정 IP 주소에서 접속할 때만 허용'하거나 '특정 시간에만 허용'하는 정교한 제어가 가능하다.

#### 'my-study-bucket'이라는 이름의 바구니(버킷)에 대해서만 작업을 허용하는 설정

```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Sid": "AllowS3ManagementForSpecificBucket",
      "Effect": "Allow",
      "Action": [
        "s3:PutObject",
        "s3:GetObject",
        "s3:ListBucket"
      ],
      "Resource": [
        "arn:aws:s3:::my-study-bucket",
        "arn:aws:s3:::my-study-bucket/*"
      ],
      "Condition": {
        "IpAddress": {
          "aws:SourceIp": "203.0.113.0/24"
        }
      }
    }
  ]
}
```

## 3. 계정 보안 및 로그인 관리
### 3-1. 정보 보호 정책
* **비밀번호 정책**: 최소 길이, 특수 문자 포함 여부, 만료 기간, 재사용 방지 등 설정 가능.
* **다중 인증(MFA)**: 비밀번호와 보안 장치를 결합한 인증 방식. 은행의 보안카드나 OTP와 같은 개념으로, 보안의 가장 핵심적인 방어선 기능을 한다.
* **가상 MFA**: Google Authenticator, Authy 등 앱 기반. 한 장치에서 여러 토큰 지원(최대 8개).
* **물리적 MFA(U2F)**: YubiKey, Gemalto 하드웨어 키 등 물리 장치 활용.

### 3-2. 로그인 편의성
* **로그인 URL 및 별칭**: 긴 계정 ID 대신 고유한 **계정 별칭(Alias)**을 생성하여 간소화된 URL로 접속 가능.
  * 숫자 12자리로 된 계정 ID를 외우기 힘들기 때문에 회사 이름이나 본인의 닉네임으로 별칭을 만들어 사용한다.

## 4. AWS 접속 방법 및 도구
### 4-1. 접근 방식 비교
* **AWS 콘솔**: 웹 브라우저를 통한 그래픽 기반 관리. ID, 비밀번호, MFA 사용. 마우스로 버튼을 클릭하며 조작하는 방식이다.
* **AWS CLI**: 터미널(명령줄 인터페이스)에서 명령어로 조작. 액세스 키 사용. 검은 화면(터미널)에 글자를 직접 입력하여 AWS를 제어하는 방식이다.
* **AWS SDK**: 애플리케이션 코드 내에서 API를 호출하여 조작. 라이브러리 형태로 포함. 개발자가 만든 프로그램(Java, Python 등)이 스스로 AWS 리소스를 생성하거나 삭제하도록 할 때 사용한다.

### 4-2. 액세스 키(Access Key)

* **구성**: 액세스 키 ID와 비밀 액세스 키(Secret Access Key) 한 쌍으로 구성됨.

  * CLI는 `aws configure` 명령어로 설정하며, SDK는 환경 변수나 IAM 역할을 통해 권한을 획득함.
* **주의**: 당연한 거긴 한데, 액세스 키는 절대 깃허브(GitHub) 같은 공개된 곳에 올리면 안 된다. 노출될 경우 막대한 비용 폭탄이 발생할 수 있다.

### 4-3. AWS CloudShell

![](https://velog.velcdn.com/images/paramad/post/69dd49b1-37ac-405f-868b-8116b2a2f8a4/image.png)

* 브라우저 기반의 CLI 환경. 내 컴퓨터에 별도로 프로그램을 설치하지 않아도 웹 브라우저 안에서 바로 CLI 명령어를 연습할 수 있는 무료 도구다.
  * **특징**: 영구 저장소 제공, 커스터마이징 가능, 파일 업로드/다운로드 지원.
  * 다만 한국 리전은 지원하지 않으므로 도쿄 등 타 리전을 선택하여 사용해야 함.

## 5. IAM Role

![](https://velog.velcdn.com/images/paramad/post/475cab11-2080-4263-806a-55acd8ea84f5/image.png)

### 5-1. IAM Role 개요
* 사람이 아닌 **AWS 서비스**(EC2, Lambda 등)에 권한을 부여하기 위해 사용되는 개체. 이것이 어떻게 보면 IAM의 핵심이기도 하다!
* 서비스가 다른 AWS 서비스를 조작해야 할 때 해당 역할을 부여하면 된다.
  * 예를 들자면, EC2 서버가 S3 버킷에 파일을 업로드해야 할 때, EC2에게 S3 접근 권한이 담긴 IAM 역할을 입혀주는 식.
  * 사용자가 '신분증'이라면, 역할(Role)은 잠시 빌려 쓰는 '작업복'이나 '자격'에 비유할 수 있다.

### 5-2. 보안 감사 도구
* **IAM Credentials Report**: 계정 내 모든 사용자의 자격 증명 상태(비밀번호, 키 사용 현황 등)를 담은 CSV 보고서.
* **IAM Access Advisor**: 서비스별 마지막 액세스 시간을 확인하여 불필요한 권한을 식별하고 삭제하는 데 활용함.
  * '지난 90일 동안 한 번도 쓰지 않은 권한'을 찾아내어 삭제함으로써 보안을 강화한다.

## 6. 총정리

* **글로벌 서비스**: IAM은 특정 리전에 국한되지 않는 **전역(Global)** 서비스임.
  * 리전을 변경해도 IAM에서 생성한 사용자와 그룹 정보는 동일하게 유지된다.
* **정책 문장의 구성**: 시드(Sid), 효과(Effect), 원칙(Principal), 조치(Action), 리소스(Resource), 조건(Condition)으로 이루어짐. (버전은 정책 전체의 속성임)

### IAM 핵심 구성 요소 및 개념

| 구분               | 정의 및 특징                           | 비유          |
| ---------------- | --------------------------------- | ----------- |
| **루트 계정**        | 계정 생성 시 기본 생성되는 관리자 계정. 모든 권한 보유. | **마스터 키**   |
| **IAM 사용자**      | 실제 개별 사용자와 1:1 매칭되는 개체. 공유 금지.    | **개인 신분증**  |
| **IAM 그룹**       | 사용자들의 집합. 직무별(개발, 인사 등) 권한 관리 용이. | **부서별 출입증** |
| **IAM 역할(Role)** | 사람이 아닌 서비스(EC2 등)에 임시 권한 부여 시 사용. | **작업복/자격증** |

### AWS 접근 방식 및 인증 도구

| 방식             | 주요 특징                         | 인증 수단            |
| -------------- | ----------------------------- | ---------------- |
| **AWS 콘솔**     | 웹 브라우저를 통한 그래픽(GUI) 기반 조작 방식. | ID, 비밀번호, MFA    |
| **AWS CLI**    | 터미널에서 명령어를 직접 입력하여 조작하는 방식.   | 액세스 키(ID/Secret) |
| **AWS SDK**    | 애플리케이션 코드 내에서 API를 호출하는 방식.   | 액세스 키(ID/Secret) |
| **CloudShell** | 브라우저 내에서 바로 사용 가능한 무료 터미널 환경. | 콘솔 로그인 세션 공유     |

### IAM 정책(JSON) 구성 항목

| 항목명           | 설명                                    | 필수 여부 |
| ------------- | ------------------------------------- | ----- |
| **Version**   | 정책 언어의 버전 정의 (예: 2012-10-17).         | 필수    |
| **Effect**    | 해당 권한을 '허용(Allow)'할지 '거부(Deny)'할지 결정. | 필수    |
| **Action**    | 수행하려는 구체적인 작업 (예: s3:GetObject).      | 필수    |
| **Resource**  | 권한이 적용될 대상의 주소 (ARN 형식).              | 필수    |
| **Condition** | 특정 IP, 시간대 등 권한이 발동되는 세부 조건.          | 선택    |
| **Sid**       | 해당 문장이 무엇인지 설명하는 고유 식별자.              | 선택    |

### 계정 보안 및 감사 도구

| 도구명                    | 주요 기능                         | 활용 목적        |
| ---------------------- | ----------------------------- | ------------ |
| **MFA**                | 비밀번호 외에 추가 보안 장치(앱, 하드웨어) 인증. | 보안 강화(필수 권장) |
| **비밀번호 정책**            | 길이, 문자 제한, 만료 기간 등 설정.        | 계정 탈취 예방     |
| **Credentials Report** | 계정 내 사용자별 자격 증명 상태 보고서(CSV).  | 사용자 보안 현황 감사 |
| **Access Advisor**     | 서비스별 마지막 액세스 시간 확인 가능.        | 불필요한 권한 삭제   |
